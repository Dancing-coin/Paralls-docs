<a id="design-intent"></a>

## 一、设计目的

### 1.1 要做到什么

| 目标 | 含义 |
|---|---|
| **角色按设定行事** | 同一个世界事件，不同角色因设定不同而做出不同判断 |
| **智力表现可调** | 角色的"聪明程度"由两个独立参数控制，可从设定推导 |
| **感知受限** | 角色只知道自己该知道的，不知道的不会表现出来 |
| **单一推进者** | 同一角色同一时刻只有一个决策源 |
| **可解释** | 任一行为可追溯到感知、记忆、设定、决策链 |

### 1.2 不追求什么

- **不追求"最聪明的 AI"**。追求的是"符合这个角色设定的判断"。
- **不追求完全确定性**。LLM 的非确定性是特性（角色会做出意料之外的判断），但必须在可解释范围内。
- **不让智能体绕过世界规则**。它能决定"想做什么"，不能决定"发生了什么"。

### 1.3 与实现状态的关系

本文件是**设计规格**。仓库中 Laya 与角色智能体的实现尚未达到本规格（详见 [§十二 实现状态](#implementation-status)）。

**实现的缺口不改变设计目的**，只意味着需要补齐。本文件写的是目标，不是现状。

<a id="two-agents"></a>

## 二、两种智能体

| | 角色智能体 | 司命智能体 |
|---|---|---|
| 粒度 | 单个角色 | 全局 |
| 决定 | 这个角色想做什么 | 谁需要被精细模拟、何时 |
| 权限 | 产出意图，不写世界 | 分配计算资源，不写世界 |
| 数量 | 每激活角色一个 | 全局唯一 |
| 频率 | 感知驱动 | 周期性 + 事件驱动 |

**关键区分**：角色智能体决定**角色行为**，司命决定**模拟精度分配**。

司命可以驱动群体模拟，群体模拟再驱动角色——但只有**激活为角色智能体**的角色才由角色智能体本身驱动。

```
司命
 └─ 决定激活谁
     ├─ 未激活 → 群体模拟（B0/B1）驱动
     └─ 已激活 → 角色智能体（C3）驱动
```

<a id="cognitive-pipeline"></a>

## 三、角色智能体的四级管线

```
L1 感知    世界事实 → 角色私有世界快照
L2 理解    快照 + 记忆 + 设定 → 解释与信念
L3 规划    解释 + 目标 + 候选 → 意图
L4 执行    意图 → 语义动作提案
```

### 3.1 L1 感知

**输入**：感知事件（`CharacterPerceivedEvent`）、自身身体事件、司命注入的感知包。

**输出**：`CharacterPrivateWorldSnapshot`——角色"以为的世界"。

| 通道 | 内容 | 约束 |
|---|---|---|
| `visual` | 所见 | 需要朝向与视线 |
| `auditory` | 所闻 | 需要声源可达 |
| `olfactory` | 所嗅 | 距离衰减强 |
| `thermal` | 所感温度 | |
| `tactile` | 接触 | 需物理接触 |
| `spatial` | 空间可达性 | |

**关键约束**：

| 约束 | 说明 |
|---|---|
| 只能拿到自己能感知的 | 不是全世界事件流 |
| 感知有质量差异 | `clarity` 与 `certainty` 必须真实变化，不能恒为常数 |
| 不允许全知 | 未感知的事实在快照中不存在，不是"值为空" |

### 3.2 L2 理解

**输入**：L1 快照 + 记忆召回 + 角色设定 + 当前目标。

**输出**：`CharacterInterpretation`——角色对处境的解释、信念更新、情绪评估。

L2 是**唯一调用慢思考模型的层**（详见 §四）。

### 3.3 L3 规划

**输入**：L2 解释 + 候选意图集 + 设定 + 约束。

**输出**：`CharacterIntentDecision`——选定意图。

L3 是**快思考的主要战场**（详见 §四）。

### 3.4 L4 执行

**输入**：选定意图。

**输出**：`CharacterSemanticIntentProposal`——**语义**动作提案。

| L4 产出 | 不产出 |
|---|---|
| 语义 action id | 骨骼动画 |
| 意图参数（目标、方式） | 物理位置 |
| 表现提示（动作节奏、姿态倾向） | 世界事实 |
| 出处与置信 | |

**L4 不写世界。** 它产出的是"我想这样做"的提案，由 UE 执行器与领域 Owner 决定能否实现。

<a id="intelligence-levers"></a>

## 四、智力表现的两个调节轴

这是本文件的核心。**角色的"智力表现"由两个独立参数控制。**

```
            智力表现
               │
      ┌────────┴────────┐
      │                 │
快思考依赖度        慢思考推理强度
（用不用 Laya）    （想得多深）
```

### 4.1 为什么是两个而不是一个

一个参数无法表达"聪明但反应慢"与"不聪明但反应快"：

| 组合 | 表现 |
|---|---|
| 高依赖 + 低强度 | 反应极快，判断粗糙（莽夫） |
| 高依赖 + 高强度 | 反应快，但快思考本身被限制（矛盾，实际按依赖度走） |
| 低依赖 + 高强度 | 反应慢，判断精细（谋士） |
| 低依赖 + 低强度 | 反应慢，判断也粗糙（糊涂但谨慎） |

**四种组合对应四种可辨识的角色类型。** 单一参数只能表达一条轴。

### 4.2 轴一：快思考依赖度 `fast_think_reliance`

```text
fast_think_reliance: dec 0..100
```

**语义**：该角色多大程度上信任"第一反应"。

高值 → 更多情形由快思考（Laya）直接决定，不问慢思考。
低值 → 更多情形升级到慢思考，即使情况看起来简单。

**路由规则**：

```text
事件复杂度  complexity ∈ [0, 100]        （见 §4.4）
依赖度      reliance   ∈ [0, 100]
升级门槛    threshold  ∈ [0, 100]

threshold = 33 + (100 - reliance) × 0.34

若 complexity < threshold  →  快思考（Laya）
否则                       →  慢思考（模型）
```

| reliance | threshold | 含义 |
|---|---|---|
| 100 | 33 | 只有极复杂情形才慢思考 |
| 50 | 50 | 平衡 |
| 0 | 67 | 稍复杂就慢思考 |

**关键设计点**：

1. 依赖度**不改变快思考能看到什么**，只改变"多大程度上够用"。
2. 即使依赖度最高，`complexity ≥ 33` 仍会升级——**没有任何角色可以对一切只靠快思考**。
3. 反之，依赖度最低，`complexity < 67` 仍走快思考——**没有任何角色对所有事都深思**。

第 2、3 条是刻意的：它们保证两个极端仍然合理，避免"纯快"（等于无脑）与"纯慢"（等于永远卡顿）。

### 4.3 轴二：慢思考推理强度 `thinking_effort`

```text
thinking_effort:
  preferred:  low | medium | high | deep
  maximum:    low | medium | high | deep
  supported:  bool
```

**语义**：慢思考时，允许模型想多深。

| 级别 | 含义 |
|---|---|
| `low` | 快速判断，少量推理 |
| `medium` | 常规推理 |
| `high` | 深度推理，考虑多条线索 |
| `deep` | 最大推理预算 |

**解析规则**：

```text
requested = preferred
if 事件 tier == fast      → minimum = low
if 事件 tier == balanced  → minimum = medium
if 事件 tier == deep      → minimum = high

actual = clamp(
    max(requested, minimum),
    lower = minimum,
    upper = maximum
)

if not supported → actual = unsupported，且必须显式记录，不得伪装为 low
```

**关键约束**：

| 约束 | 说明 |
|---|---|
| `maximum` 是硬天花板 | 事件再难也不超过角色设定上限 |
| `minimum` 由事件决定 | 足够难的事件不能被"懒得想"跳过 |
| `unsupported` 必须暴露 | provider 不支持时必须标记，不能用 `low` 冒充 |
| **effort 必须真的传给 provider** | 只记录不传递等于没有这个参数 |

最后一条是本规格与现有实现差距最大的地方（见 §十二）。

### 4.4 事件复杂度 `complexity`

复杂度衡量"这个情形有多难判断"，与角色无关。

```text
complexity = 100 × (
    0.20 × ambiguity          证据的模糊程度
  + 0.20 × risk               判断错误的后果严重度
  + 0.15 × goal_conflict      当前目标之间的冲突程度
  + 0.15 × actor_count        涉及的主体数量
  + 0.15 × domain_crossing    跨越的领域数
  + 0.15 × causal_distance    与已知信息的因果距离
)
```

各分量 ∈ [0, 1]，由 L2 的解释结果给出，不由模型自由发挥。

**为什么是这六项**：它们覆盖了"不确定"的六个来源——看不清、错不起、想不清、人太多、跨太广、离太远。

### 4.5 两个轴的组合语义

```text
最终行为 = 路由(reliance, complexity) × 强度(effort, complexity)
```

| 情形 | 路由 | 强度 | 结果 |
|---|---|---|---|
| 简单事件 + 高依赖 | Laya | — | 极快，按第一反应 |
| 简单事件 + 低依赖 | Laya | — | 仍然快，但角色"本来想多想想" |
| 复杂事件 + 高依赖 | 慢思考 | 受 maximum 限 | 想但受限于天花板 |
| 复杂事件 + 低依赖 | 慢思考 | 可到 deep | 最有质量的判断 |

**注意第三行**：高依赖 + 复杂事件时，仍会慢思考，但强度受 `maximum` 限制。这是"莽夫遇到难题"的正确表现——他会想，但想不深。

### 4.6 与硬上限的关系

`thinking_effort` 是"允许想多深"，`hard_limits` 是"最多能处理多少"：

```text
hard_limits:
  max_context_items:            int    记忆召回条数上限
  max_active_hypotheses:        int    同时考虑的假设数
  max_reasoning_hops:           int    推理链长度上限
  max_candidate_intents:        int    候选意图数
  max_concurrent_goals:         int    并行目标数
  planning_horizon:             enum   short | medium | long
  confidence_ceiling_without_evidence: dec 0..1
```

**两者的区别**：

- `effort = deep` 但 `max_reasoning_hops = 2` → 模型被允许深想，但输入只给了两条推理空间
- `effort = low` 但 `max_reasoning_hops = 8` → 输入充足，但角色不愿意想

**组合产生真实差异**：一个"想得深但记性差"的角色（高 effort + 低 context），与"记得多但懒得想"的角色（低 effort + 高 context），行为完全不同。

### 4.7 从角色设定推导

```yaml
cognitive_capability_layer:
  # 轴一：快思考依赖度
  fast_think_reliance: "70"        # 0..100

  # 轴二：慢思考强度
  compute_defaults:
    preferred_effort: "medium"
    maximum_effort: "high"

  # 边界
  hard_limits:
    max_context_items: 8
    max_active_hypotheses: 3
    max_reasoning_hops: 2
    max_candidate_intents: 3
    max_concurrent_goals: 2
    planning_horizon: "short"
    confidence_ceiling_without_evidence: "0.68"

  # 表达约束
  expression_constraints:
    vocabulary_band: "plain"       # plain | literary | archaic
    explanation_depth: "terse"     # terse | normal | verbose
    uncertainty_style: "admit"     # admit | deflect | assert
```

### 4.8 推导示例

| 角色类型 | reliance | preferred / maximum | 表现 |
|---|---|---|---|
| 老卒 | 85 | low / medium | 反应快，判断凭经验，遇难题也能想但想不深 |
| 谋士 | 20 | high / deep | 极少凭直觉，凡事深思 |
| 莽夫 | 95 | low / low | 几乎全靠第一反应，难题也硬上 |
| 县丞 | 45 | medium / high | 常规事凭经验，重要事细想 |

**这四个不是预设类型**，是参数组合的示例。真实角色由档案给出数值。

### 4.9 校验

| 检查 | 拒绝码 |
|---|---|
| `fast_think_reliance ∉ [0,100]` | `profile_reliance_out_of_range` |
| `preferred > maximum` | `profile_effort_inverted` |
| 缺 `cognitive_capability_layer` | `profile_cognition_layer_missing` |
| `supported: false` 却配置了 `maximum > low` | `profile_effort_unsupported` |

**缺认知层必须拒绝，不能补默认值。** 补默认值会让"忘记配置"变成"用一套固定智力"，正是现有实现的问题。

<a id="memory"></a>

## 五、记忆系统

### 5.1 六个池

```text
working          当前工作记忆（短期，容量小）
event            事件记忆（发生了什么）
observation      观察记忆（看到了什么）
knowledge        知识记忆（确信什么，带置信档）
social           社会记忆（与谁的关系如何）
higher_order     高阶记忆（我关于"别人怎么想"的推断）
```

前五项是经典"五池"，`working` 是当前的活跃集。

### 5.2 写入路径

```
感知事件
  → 同时写 event + observation
  → 若带事实主张，upsert knowledge
  → 若涉及他人，写 social / higher_order
```

**写入必须带来源。** 无来源的记忆无法在 L3 中作为依据。

### 5.3 置信档

```text
noticed
suspected
tentatively_believed
believed
high_confidence_believed
disputed
refuted
```

置信档由感知质量与来源共同决定，不由模型自评。

### 5.4 召回

```text
召回上限 = min(hard_limits.max_context_items, 策略上限)
```

**召回必须受 `hard_limits` 约束**——这是"想得深但记性差"的实现点。

召回失败时（找不到必需记忆），行为是 `stay_silent` 或降级，**不得用模型猜测填补**。

<a id="perception"></a>

## 六、感知与有限知情

### 6.1 三道过滤

```
1. 目标过滤     只投给能被感知的主体
2. 通道过滤     朝向、距离、遮挡、听觉可达
3. 质量过滤     清晰度、确定性
```

**第 2、3 道必须真实生效。** 现有实现中朝向闸门恒为真、清晰度恒为 1.0，这使"背对看不见"与"看不清楚"都不成立（见 §十二）。

### 6.2 质量的真实来源

| 分量 | 取值范围 | 来源 |
|---|---|---|
| `clarity` | 0..1 | 距离、遮挡、光照、天气 |
| `certainty` | 0..1 | 通道可靠性、来源可信度 |

**两者都不能是常量。** 常量意味着所有感知等价，等于取消了这个机制。

### 6.3 失真

失真分两级：

| 级 | 位置 | 内容 |
|---|---|---|
| 感知失真 | L1 | 清晰度低导致的细节缺失、误认 |
| 传播失真 | 投影层 | 见 [传播延迟与失真](../01-内核/05-传播延迟与失真.md) |

**内容级失真必须在 L1 发生**，不能只有"置信度降档"。一个角色把 3000 人看成 5000 人，这是感知失真；他听到"敌人很多"然后转述为"敌人上万"，这是传播失真。

### 6.4 不允许全知

| 禁止 | 表现 |
|---|---|
| 快照包含未感知事实 | 值为空但有键 |
| 模型读到全局状态 | 通过 prompt 泄露 |
| 表现层显示未感知信息 | UI 全知 |
| 记忆被凭空补全 | 召回失败时猜测 |

<a id="presentation"></a>

## 七、表现一致性

### 7.1 单一语义路径

**只能有一条从意图到动画的路径。**

```
意图 → 语义 action id → 表现参数 → 动画
```

现有实现中 `presentation_plan` 与 `semantic_action_id` 两条路径并行，是隐性重复，必须合并（见 §十二）。

### 7.2 表现必须反映感知

| 情形 | 表现 |
|---|---|
| 未看见目标 | 不朝目标方向行动 |
| 看得模糊 | 犹豫、靠近、张望 |
| 确信有危险 | 戒备、后退 |
| 完全不知 | 无反应 |

**这是"表现符合设定"的核心**：角色的动作来自他的认知，不是来自玩家的认知。

### 7.3 L4 的产出边界

| 产出 | 不产出 |
|---|---|
| 语义动作 id | 骨骼变换 |
| 动作节奏倾向（急促/从容） | 位置 |
| 姿态倾向（戒备/放松） | 速度 |
| 表达提示（语气、停顿） | 世界事实 |

**`hesitation` / `weight_shift` 这类细粒度表达**属于表现层参数，可由 L4 给提示，由表现层决定是否、如何呈现。

### 7.4 暂停与降级

暂停时表现冻结，尾动画可播但标 `presentation_tail`。

降级时（远场）表现精度降低，**但语义不变**——远处的人也"看见"了，只是不播完整动画。

## 八、激活与去激活

### 8.1 谁决定

**司命决定。** 详见 §十。

### 8.2 四级认知

| 级 | 名称 | 运行内容 | 写入权 |
|---|---|---|---|
| C0 | dormant | 不运行 | 无 |
| C1 | batch_reasoned | 群体批处理 | 无（群体代写） |
| C2 | agent_prepared | 预热，不读私有记忆 | 无 |
| C3 | agent_active | 完整 L1–L4 | 意图提案 |

### 8.3 激活不改变的事

| 不变 | 说明 |
|---|---|
| `character_id` | 身份不变 |
| 私有记忆 | 不随激活新建或清空 |
| 事实归属 | 世界事实仍由 Owner 写 |
| 物理位置 | 不因激活而迁移 |

<a id="boundary"></a>

## 九、与世界事实的边界

### 9.1 能读

| 来源 | 限制 |
|---|---|
| 自己的私有世界快照 | |
| 自己的记忆池 | |
| 自己的设定 | |
| 公开投影 | 按可见性过滤 |
| 目标目录 | 仅在已感知范围内 |

### 9.2 能写

**只有 `actor_private` 领域**：

```
自己的快照
自己的记忆
自己的需求/情绪/目标态
意图提案
```

### 9.3 不能写

| 不能写 | 由谁写 |
|---|---|
| 世界事实 | 领域 Owner |
| 他人状态 | 该人的 Owner |
| 结算结果 | 对应 Owner |
| 身体数值 | Body |
| 位置 | Presence |

**写意图必须带 receipt。** 无 receipt 的 `outcome_fact` 必须拒绝。

<a id="siming"></a>

## 十、司命智能体

### 10.1 定位

**司命决定谁被精细模拟，原则是平衡游戏性与游戏体验。**

```
司命治理「事情和资源」，
然后为需要处理的事情选择合适参与者、精度和预算。
它不是逐个角色的人生编剧，也不拥有世界真相。
```

| 拥有 | 不拥有 |
|---|---|
| 全局态势与公平快照 | 角色私有记忆与私有感知 |
| 候选角色的激活建议 | 世界真相（不写 ESM / 领域事实） |
| 高层催化事件（impulse / opportunity / fact_reveal） | 角色的具体行为决定 |
| 计算资源的分配 | Godot 表现或低层动作 |

**关键边界**：司命可以决定「让某角色进入精细模拟」，但不能决定「该角色接下来做什么」。前者是资源分配，后者是角色智能体的职责。

### 10.2 激活决策

#### 四级精度

| 级别 | 名称 | 运行内容 | 谁驱动 |
|---|---|---|---|
| B0 | dormant | 不运行 | 群体统计 |
| B1 | batch_reasoned | 群体批处理 | 群体模拟 |
| B2 | agent_prepared | 预热，不读私有记忆 | 群体模拟 |
| B3 | agent_active | 完整 L1–L4 | 角色智能体 |

**只有 B3 由角色智能体驱动。** B0–B2 由群体模拟驱动，即使被"预热"也不产生自主判断。

#### 判定规则

按顺序判定，先命中者生效：

```
1. actor 不受支持，或 revision 过期        → requeue
2. 预算 <= 0                              → requeue
3. 交互类型 ∈ {对话, 冲突, 重大后果} 且 focused   → active（B3）
4. focused                                → activation_candidate
5. 距离 <= prewarm_distance 或有待处理种子  → prewarm（B2）
6. 否则                                    → dormant（B0）
```

#### 因素的权重

| 因素 | 作用 | 说明 |
|---|---|---|
| **玩家聚焦** `focused` | 决定性 | 目标是否是该角色。是进入 B3 的必要条件 |
| **交互类型** | 决定性 | 对话/冲突/重大后果才值得完整模拟 |
| **距离** | 门槛 | 只影响 B2 预热，不影响 B3 |
| **预算** | 硬约束 | 为 0 时一切降级 |
| **重要性/公平/叙事** | 排序 | 多个候选竞争时决定先后 |

**重要区分**：前四项是**门槛**（确定性判定），最后一项是**排序**（竞争时的加权）。混在一起会让"为什么这个角色被激活"不可解释。

#### 排序权重

当多个候选竞争有限的激活名额时：

```
score =
    player_proximity            × w1    玩家邻近度
  + unresolved_owner_consequence × w2    未解决的后果
  + propagation_pressure        × w3    影响扩散压力
  + narrative_obligation        × w4    叙事义务
  + starvation_credit           × w5    长期未被模拟的补偿
```

**最后一项 `starvation_credit` 是关键**：它保证长期被忽略的角色迟早获得一次模拟机会，避免"只有玩家附近的角色活着"。

### 10.3 激活时长与降级

#### 时长由租约决定，不是固定时间

```text
activation_lease:
  deadline_monotonic    结束时刻
  token                 唯一标识
  generation            代数（防旧租约复活）
```

**不是"激活后维持 N 秒就降级"**，而是"租约到期前必须续期或结束"。区别在于：前者会打断正在进行的重要交互，后者由实际操作结束触发。

#### 降级的三种触发

| 触发 | 时机 | 结果 |
|---|---|---|
| 正常完成 | 交互结束 | `completed` → 释放 |
| 玩家离开焦点 | 不再是 focused | 应降级（**设计目标，实现待补**） |
| 预算耗尽 | 需要让位给更高优先级 | 按排序挤出最低分者 |

#### 预算耗尽时的降级顺序

```
1. 先降 B3 中「无未决后果」的
2. 再降「非对话中」的
3. 最后降「有未决后果」的
```

**有未决后果的角色最后降级**——中断会导致世界状态悬空。

### 10.4 配额

| 配额 | 含义 | 典型值 |
|---|---|---|
| 同时激活上限 | B3 并发数 | 4 |
| 每 tick 激活上限 | 单次调度最多激活几个 | 4 |
| 预热距离 | 进入 B2 的距离门槛 | 12 m |
| 租约默认期限 | | 60 s |
| 降级后批量唤醒 | 低负载时可多唤醒几个 | 2 |

**这些数值不是设计常量，是可调参数。** 它们体现"平衡游戏性与体验"的具体权衡，需要在实测中调整。

### 10.5 与群体模拟的交接

#### 交接包内容

**上行（B1→B3）必须包含**：

| 内容 | 必需性 | 说明 |
|---|---|---|
| `actor_ref` | 必需 | 身份 |
| 已确认窗口与 revision | 必需 | 从哪里接续 |
| 来源 revision 向量 | 必需 | 读取一致性 |
| 硬约束（禁止字段/维度） | 必需 | 边界 |
| 未决提案 | 必需 | 不能丢失的上下文 |
| 位置锚点 | 必需 | 空间连续性 |
| **记忆范围授权** | **必需** | 能读哪些私有记忆 |
| **感知范围** | **必需** | 能感知什么 |
| **能力封套** | **必需** | 受什么限制 |
| **租约引用** | **必需** | 唯一推进者证明 |
| 过期时刻 | 必需 | 何时失效 |

**加粗的三项是现有实现缺失的**（见 §十一）。

#### 下行（B3→B1）

回归时要求：

```
1. 已消费到窗口末
2. 无未消费结果
3. 无活跃租约
```

三条同时满足才能回归群体模拟，否则会出现两个推进者。

### 10.6 唯一推进者

四层保证，缺一不可：

| 层 | 机制 |
|---|---|
| 事件层 | 锁的提交走 CAS + 幂等，重复提交返回原结果 |
| 来源层 | 锁事件必须由激活权威写入，其它来源拒绝 |
| 进程层 | token + generation fencing，旧句柄不能释放新锁 |
| 跨 Owner | 群体准入显式排除持锁角色；交接时校验两侧锁一致 |

**关键约束**：锁的 `world_ref` 必须在全链路一致。若角色智能体与群体模拟用了不同的 world 标识，两侧看不到彼此的锁，"唯一推进者"不成立（见 §十一）。

### 10.7 可玩性如何落地

"平衡游戏性与体验"不能只是一个原则，必须有可计算的落点。三层：

| 层 | 落点 |
|---|---|
| **门槛** | 交互类型与聚焦决定谁值得模拟 |
| **排序** | 五项加权分决定竞争时的先后 |
| **补偿** | `starvation_credit` 保证长期未模拟的角色不被饿死 |

**不引入"可玩性分数"这种单一标量。** 它无法解释，也无法调参。

### 11.5 一处会造成双推进者的接线缺陷

**这是本文档核实过程中发现的最严重问题。**

```
角色智能体写锁： population:world:default        （硬编码 runtime_loop.py:191，无 setter）
群体模拟查锁：   population:world:bakery-district （main.py:2605 的实际世界）
```

两侧的锁在**不同的流**上，因此彼此看不到对方的锁。结果是「唯一推进者」在真实世界标识下不成立。

flood 测试之所以通过，是因为它恰好用 `world:default`。

**影响**：这是唯一推进者的基础，若在实现中不修，会导致双写。

**修法**：`_activation_world_ref` 必须来自世界模式，不得硬编码。这是一行改动，但需要验证所有调用路径。

## 十二、验收

### 12.1 智力调节

| # | 用例 | 期望 |
|---|---|---|
| A1 | 两个角色同设定、同事件 | 判断相同或近似 |
| A2 | 同事件、reliance 不同 | 路由不同（一个走快思考，一个升级） |
| A3 | 同事件、effort 不同 | 慢思考的推理深度不同 |
| A4 | `effort=deep` 但 `maximum=low` | 实际用 low，不越界 |
| A5 | 简单事件 + reliance=0 | 仍走快思考（threshold=67） |
| A6 | 极复杂事件 + reliance=100 | 仍升级慢思考（complexity≥33） |
| A7 | 缺 `cognitive_capability_layer` | profile 加载拒绝 |
| A8 | `supported=false` | 标记为 unsupported，不伪装 low |

### 12.2 感知

| # | 用例 | 期望 |
|---|---|---|
| P1 | 角色背对目标 | 快照中无该目标 |
| P2 | 目标被遮挡 | 快照中最多是模糊线索 |
| P3 | 距离远 | clarity 下降，产生 partial/missed |
| P4 | 第三方旁观 | 若在视线内应能感知（fan-out） |
| P5 | 未感知事实 | 表现层不显示 |

### 12.3 边界

| # | 用例 | 期望 |
|---|---|---|
| B1 | 智能体试图写世界事实 | 拒绝 |
| B2 | 意图无 receipt | 拒绝 |
| B3 | 记忆召回失败 | stay_silent 或降级，不猜测 |

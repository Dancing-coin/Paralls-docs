# 03-聚合与精度

- 版本：1.0
- 状态：已定义

<a id="scope-vs-precision"></a>

## 一、作用域与精度是两件事

```text
作用域 authority_scope   这个事实说的是谁        character / squad / garrison / theater
精度   fidelity          这个事实怎么表示        full / aggregate / marker
```

两者独立：

- `Morale@squad + full` —— 队长所在的精锐小队，逐个跟踪
- `Morale@squad + aggregate` —— 远处的普通队伍，只存统计量
- `Morale@garrison + aggregate` —— 整个守军，只有总体士气

**精度切换不改变 FactType，也不改变 Owner。**只是同一条事实流的表示方式变化。

---

<a id="four-modes"></a>

## 二、四种聚合方式

| 方式 | 语义 | 展开/收拢 | 例 |
|---|---|---|---|
| `none` | 各实例独立 | 不适用 | 个体生命、门扇耐久 |
| `sum` | 总量 = 各实例之和 | **守恒** | 弹药总数、粮草总量 |
| `distribution` | 存统计量而非个体 | **不守恒，按 refold 重算** | 远场队伍、五阶段人口 |
| `ordered` | 有序序列 | 保序 | 排队、优先级 |

<a id="conservation"></a>

## 三、守恒只对 sum 成立

这是本设计相对讨论稿最重要的一处修正。

> 讨论稿要求"个体和聚合两种精度来回切换，池的总量和身份守恒"。

这条对 `sum` 成立，对 `distribution` **不成立**。

### 反例：士气

两支残部合并：

```
A 队：士气 20，剩 30 人
B 队：士气 20，剩 40 人

合并后士气 = 20 吗？    不一定——可能因"我们还有 70 人"而回升，也可能因"两个残部"而更低
```

士气不是可加的量。要求守恒会逼出一个假守恒量，或者逼出分布表示——对十几个队伍单位的 Demo 是纯过度设计。

### 正确做法：refold_model

```text
aggregation:
  mode: distribution
  refold_model_ref: morale_refold_v1
  refold_triggers: [split, merge, fidelity_change, scope_change]
```

`refold_model` 是一个 L4 Resolver，输入：

```text
成员当前值（若有）
成员构成（人数、训练、损失）
触发原因（拆分 / 合并 / 精度切换）
近期相关事件（伤亡、军旗、指挥）
```

输出：聚合后的值。

**每次都重算，不做增量加减。**

<a id="identity"></a>

## 四、守恒的是什么

守恒的只有**身份**，不是数量：

| 项 | 守衡？ |
|---|---|
| 成员身份（谁在这支队伍里） | ✓ 必须守恒 |
| `character_id` 在精度切换中不变 | ✓ 必须守恒 |
| 事件不重复不丢失 | ✓ 必须守恒 |
| 士气数值 | ✗ 不守恒 |
| 健康数值（个体生命） | 若用 sum 则守恒；用 distribution 则不 |

**身份守恒的检查方式**：精度切换前后，成员 `character_id` 集合必须完全相同。任何成员凭空出现或消失即为缺陷。

<a id="fidelity-change"></a>

## 五、精度切换协议

```
1. 冻结当前作用域的读集
2. 记录成员身份集合与各自 revision
3. 按 refold_model 计算目标精度表示
4. 提交 fidelity_changed 事件（携带来源 revision 向量）
5. 新精度下的写入开始，旧精度视图作废
6. 校验：成员身份集合一致
```

切换期间不得有并发写入。切换本身是一次切窗事件。

### B2/P2 → B3/P3（升级）

升级到高精度时必须**个体化**：

- 若原为 `distribution`，需按 refold 展开为个体值 — 此时个体值带有不确定性
- 必须记录 `expanded_from: aggregate_ref`，表示这是推导值，不是观测值
- 个体差异只能来自档案种子与已确认事件，不能凭空发明

### B3/P3 → B2/P2（降级）

降级聚合时必须保留已确认的个体结果：

- 已提交的个体事件不删除
- 聚合值由 refold 计算
- 保留 `last_individual_revision`，供再次升级时恢复

<a id="population"></a>

## 六、五阶段规模的表达

十三州人口如果逐个体存储会爆炸。用 `distribution`：

```text
fact:region:jizhou:population
  aggregation: distribution
  refold_model_ref: population_refold_v1
  存储：按 (年龄带, 职业, 健康状态) 的桶计数
```

桶的数量有限，桶内的个体不存在独立 FactType。当某个个体需要升级为 B2/B3 时，**从桶中生成一个具名个体**，此后该个体有自己的 FactType 流。

这是"人数守恒、身份按需实例化"的混合模式——不是所有个体都在任何时刻拥有身份。

<a id="acceptance"></a>

## 七、验收

| # | 用例 | 期望 |
|---|---|---|
| G1 | sum 型池在精度切换前后 | 总量相同 |
| G2 | distribution 型士气在拆分/合并后 | 按 refold 重算，不守恒 |
| G3 | 任何精度切换前后 | 成员身份集合相同 |
| G4 | 聚合→个体展开 | 记录 `expanded_from`，个体值标为推导 |
| G5 | 个体→聚合降级再升级 | 已确认个体事件不丢失 |
| G6 | 五阶段人口用分布存储 | 内存不随人口线性增长 |

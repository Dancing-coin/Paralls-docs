## 一、阻塞全案的待决

### D1. 六原语能否收敛

| | |
|---|---|
| 问题 | Pool 与 Bond 原型能否收敛到统一规格 |
| 来源 | 本轮原语反推 |
| 阻塞 | L2 及以上全部内容 |
| 建议 | 先做两个原型；Bond 压不进则改 5 或 7 个 |
| 状态 | **原型层面已验证**（2026-11-03） |

**验证结果**：Pool 与 Bond 两个原型各 25 项用例全部通过，并用 4 个真实模块的字段做了跨验。原语数量维持六个。

跨验附带的规格修正（已写入 [六原语规格](../02-原语/02-六原语规格.md)）：

1. **Bond 属性必须不可变**（新增不变量 B7）。可变量走独立 FactType——债务的 `outstanding_amount` 拆为 `bond.obligation` + `pool.debt` + `machine.debt` 三件。
2. **Bond 的 target 允许指向实体物品**，以支持凭证机制。

**仍未验证**：与现有 34 个 runtime 的对接成本、性能、双端等价。这三项属阶段 2 与阶段 5。

证据见 [原型验证记录](../09-验收/04-原型验证记录.md)。

## 二、高优先级

### D2. `writes_fact_types` 校验收紧到哪一层

| | |
|---|---|
| 问题 | 只校验 owner 一致（宽松），还是要求剖面每层的 Resolver 也由该层 FactType 的 owner 注册（严格） |
| 影响 | 双端等价的唯一保障点 |
| 建议 | **严格**。宽松会让"模型跨域写权"仍有可能通过间接路径 |
| 阻塞 | Resolver 注册实现 |

### D3. 代码模型是否进同一注册表

| | |
|---|---|
| 问题 | 原生 Owner 的 Resolver 是否与规则包模型共用一个注册表 |
| 影响 | "模型不允许隐式存在"是否有一半领域是例外 |
| 建议 | **进**。否则一半领域游离在治理之外 |
| 阻塞 | L3/L4 注册实现 |

### D4. `resolution_order` 由谁分配

| | |
|---|---|
| 问题 | 包作者手填整数，还是由管线拓扑自动生成 |
| 影响 | 手填会撞车、留空洞、升级时漂移 |
| 建议 | **拓扑生成 + 包只声明偏序** |
| 阻塞 | L2 实现 |

### D5. 原生 / 托管的边界由谁裁定

| | |
|---|---|
| 问题 | 某个 Owner 的某部分事实升级为原生（长出 Resolver）时，谁批准 |
| 影响 | 托管 Owner 可能缓慢长成原生，破坏划分 |
| 建议 | 设显式评审门槛，且要求该 Resolver 无法用数据表达 |
| 阻塞 | Owner 注册流程 |

### D6. 可见性改造的性能影响

| | |
|---|---|
| 问题 | 读取端按 principal 过滤会引入多少延迟 |
| 影响 | 近场高频链是否可用 |
| 建议 | 按 principal 缓存资格；投影增量更新；先测量再定策略 |
| 阻塞 | 可见性强制实现 |

## 五、已关闭的待决

### C1. 规则包能不能带逻辑

| | |
|---|---|
| 原问题 | 允许受限 DSL 更灵活，但双端等价与回放成本高 |
| 结论 | **不能**。C++/Python 逐位等价 + 旧版本回放已排除 DSL |
| 依据 | [规则包总纲](../05-规则包/01-规则包总纲.md#no-logic) |

### C2. Owner 该不该是固定名单

| | |
|---|---|
| 原问题 | 23 个固定，还是由配置派生 |
| 结论 | **名字固定，内容由 FactType 组成**。写权必须可指名到人；机制必须只实现一次 |
| 依据 | [设计原则](../00-总纲/01-设计原则.md#principles) |

### C3. "实体与构成"是不是原语

| | |
|---|---|
| 结论 | **不是**。是 L4 schema + L0 身份注册。当原语会长出实体表 |
| 依据 | [原语总则](../02-原语/01-原语总则.md#not-primitives) |

### C4. "属性与修正"是不是原语

| | |
|---|---|
| 结论 | **不是**。是投影。代码中 `EffectiveStatResolver` 明确是 read-only |
| 依据 | 同上 |

### C5. "效果"是不是原语

| | |
|---|---|
| 结论 | **不是**。是 Process 的 temporal 特化 |
| 依据 | 同上 |

### C6. 聚合是否守恒

| | |
|---|---|
| 原问题 | "个体和聚合切换时总量与身份守恒" |
| 结论 | **身份守恒，数量按 `refold_model` 重算**。守恒只对 `sum` 成立，对士气不成立 |
| 依据 | [聚合与精度](../03-事实类型/03-聚合与精度.md#conservation) |

### C7. 是否要建父 Owner → 子 Owner 的分权

| | |
|---|---|
| 结论 | **不要**。Owner 平级；规模用 scope，宿主用 epoch |
| 依据 | [反模式与硬约束](../00-总纲/03-反模式与硬约束.md#anti-patterns) |

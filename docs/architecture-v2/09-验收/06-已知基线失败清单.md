<a id="consequence"></a>

## 二、这对后续工作意味着什么

### 验收标准必须改

| 错误标准 | 正确标准 |
|---|---|
| 「全部测试通过」 | 「相对基线无新增失败」 |
| 「通过数 ≥ N」 | 「失败集合 ⊆ 基线失败集合」 |

**理由**：基线有 201 个已知失败，任何「全绿」要求都无法达成，只会导致：
- 忽略所有红灯（包括真回归）
- 或花大量时间修与当前目标无关的旧缺陷

### 后续每一次改动

```
1. 在 baseline/env-fix 上跑目标测试范围 → 记录失败集合 B
2. 在改动分支上跑同一范围 → 记录失败集合 C
3. 判据：C − B = ∅
```

## 三、失败原因分类

抽样核实后的四类。**按可修复性排序，不是按数量。**

### 类型 A：接口漂移（最大宗，约 120 个）

测试调用旧签名，实现已改。典型：

```text
TypeError: PopulationActivationPresenceService.__init__()
           missing 1 required keyword-only argument: 'producer_ref'

TypeError: RuntimeCadencePublisher.__call__()
           got an unexpected keyword argument 'population_projections'

AssertionError: assert 'ack' == 'embodied_controller_bound'

pydantic ValidationError: 9 validation errors for CognitionPolicy
```

**性质**：实现重构时同步了调用方，但没同步测试。
**可修复性**：高。机械修改。
**风险**：修好未必代表实现正确——测试断言的是旧契约。

### 类型 B：缓存/编码行为断言（约 6 个）

```text
assert [b"x\x01\xabV...xe8\x0b\x901"] == []
```

**性质**：`test_gameplay_event_store_json_cache` 一类，断言内部缓存的具体字节。
**可修复性**：中。需要判断是缓存行为变了还是断言写死了实现细节。
**风险**：这类测试本身脆弱。

### 类型 C：StopIteration（约 9 个）

```text
test_obj_archive_door_embodied_authority  → StopIteration
```

**性质**：测试里用生成器取下一个元素，取不到时抛裸 `StopIteration`。
**可修复性**：中。需查是实现变了还是测试假设变了。
**风险**：`StopIteration` 掩盖了真正原因。

### 类型 D：环境依赖（约 15 个）

```text
test_siming_llm_tls_context        依赖真实 TLS / CA 环境变量
test_siming_ingress_snapshot       依赖特定快照状态
test_siming_heavenly_godot_static  依赖 Godot 场景文件
```

**性质**：这些测试需要外部环境，当前环境不具备。
**可修复性**：低（或不该修——它们本来就该在特定环境中跑）。
**建议**：标记为 `skipif`，不计入回归判据。

<a id="recommendation"></a>

## 六、建议

### 现在不做

不修复这 201 个。理由：

- 它们与 v2 的目标（分层 Owner）无关
- A 类修好只是让测试追上实现，不产生新价值
- 修复它们会掩盖真正的问题：**我们不知道这些实现是否仍然正确**

### 应当做

**在开始 L2 及以上实现之前**，先做一件事：

```
选 5–10 个核心域的测试，逐个确认：
  是实现对了而测试旧了？
  还是实现和测试都错了？
```

判据：至少覆盖 `Inventory`、`Body`、`Equipment`、`Combat`、`Ownership` 五个域——它们是近场实时链的基础。

**若发现某域的测试与实现都不对，说明该域需要重写而非迁移。** 这直接影响 v2 的迁移工作量估算。

### 长期

把 D 类（环境依赖）标记为 `skipif`，让基线失败数降到可管理的规模。

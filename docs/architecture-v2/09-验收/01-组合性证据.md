<a id="principle"></a>

## 一、两类证据必须分开

| | 架构证据 | 玩法证据 |
|---|---|---|
| 回答 | 分层是否成立 | 玩家是否获得体验 |
| 判据 | 零改动新增、结果一致、可回放 | 能选择、有后果、看得到、能解释 |
| 失败含义 | 设计错了 | 玩法定错了 |
| 失败后动作 | 回到原语层重审 | 调内容、调参数、重设计玩法 |

**一个玩法好玩的 Demo，可能架构完全没分层。一个分层正确的 Demo，可能一点都不好玩。**两者都必须验，但不能用一个证明另一个。

## 二、七条组合性证据

### A1. 同一原语结算不同实体

**命题**：同一个 Pool 引擎、同一条冲击管线，同时结算士兵生命和城门耐久。

**做法**：一次冲击分别打到士兵与城门，观察两者走同一套 Pool 不变量与同一套管线调度。

**证据**：事件流显示两条 FactType 流按各自 `resolution_order` 结算，机制代码路径相同。

**失败含义**：Pool 未被真正抽出，或管线与实体类型耦合。

---

### A2. 只加规则包即可新增资源

**命题**：加精神力，内核与引擎零改动。

**做法**：见 [分水岭实验](../08-迁移/04-分水岭实验.md) 实验 A。

**证据**：`git diff --stat` 中代码改动 0 行。

**失败含义**：机制仍嵌在 Owner 里。

---

### A3. 同一过程原语复用于多处

**命题**：传令、运输、修缮、医疗用同一 Process 原语。

**做法**：四条流程各自的步骤机由同一实现驱动。

**证据**：四条流程的中断/恢复/幂等行为一致；无独立的步骤机实现。

**失败含义**：Process 未归并（当前真实代码有 8 处独立实现）。

---

### A4. 跨 Owner 组合

**命题**：一个原子批次 + 异步订阅（伤亡 → 士气 → 阵型）。

**做法**：命中导致死亡，死亡触发士气重算，士气跨阈值触发阵型变化。

**证据**：
- 前段是一次 AtomicEventBatch 与一个 receipt；
- 后段是两次独立 Command 与两次 receipt；
- 顺序在事件流中可见，无同批次混入。

**失败含义**：跨 scope 被误做成同批次，或 reaction 机制缺失。

---

### A5. 只改登记即可迁移

**命题**：把某类事实迁到另一个 Owner，回放结果一致。

**做法**：修改 FactType 的 `owner_ref`，走 epoch 迁移，重放同一事件流。

**证据**：迁移前后回放得到相同事实状态。

**失败含义**：写权与事实绑定过死，或回放依赖当前注册而非事件携带。

---

### A6. 个体与聚合切换，身份守恒

**命题**：精度往返切换时成员身份不变；数值按 refold 重算而非守恒。

**做法**：一支队伍从 aggregate 切到 full 再切回 aggregate。

**证据**：
- 成员 `character_id` 集合切换前后完全相同；
- 士气值按 `refold_model` 重算，不假设守恒。

**失败含义**：把守恒套在了不该守恒的量上，或身份在切换中丢失。

---

### A7. 换包版本后旧存档可回放

**命题**：换了规则包版本，旧存档按旧版本回放。

**做法**：存档记录完整解析路径与内容哈希；升级产生迁移事件；回放分段应用。

**证据**：旧事件段用旧包解释，迁移事件之后用新包，结果与当时一致。

**失败含义**：回放读了当前包，或存档只记 pack_id 未记版本。

## 三、v2 新增的三条证据

以下三条不在 v1 的原清单中，但 v2 必须验。

### B1. 结算顺序确定性

**命题**：同批次与分阶段对同一事件产生同一结果。

**做法**：同一次命中分别走两种模式。

**证据**：逐字段比较，结果相同。

**失败含义**：`resolution_order` 未真正约束，或分阶段未校验前序 revision。

---

### B2. 可见性强制

**命题**：不同 principal 读取同一事实，得到不同的可知结果。

**做法**：同一战报对不同角色与玩家投影。

**证据**：
- 未到达报告的角色投影中不存在该事实；
- `secret` 事实对非持有者**拒绝**而非空集；
- `debug_only` 事实对玩法路径拒绝。

**失败含义**：可见性仍是装饰性字段（当前状态）。

---

### B3. 结构上不能变成万能 Owner

**命题**：`play_pattern` 无法表达事实写入。

**做法**：尝试在 play_pattern 中写 `writes`，或在 reaction 中 emit 事实写入。

**证据**：注册期拒绝，报 `pattern_declares_writes`。

**失败含义**：组合层获得了写权，`SiegeOwner` 反模式在结构上变得可能。

<a id="evidence-format"></a>

## 四、证据格式

每条证据必须有可复查的产物，不接受口头结论。

```text
证据编号：A2
命题：只加规则包即可新增资源
执行时间：YYYY-MM-DD
环境：commit <hash>，pack <version>
操作：<具体步骤或脚本路径>
产物：
  - git diff --stat 输出（代码改动 0 行）
  - 固定向量测试报告（N 项通过）
  - PIE 截图（非桌面截图）
  - 事件流片段
结论：通过 / 不通过
剩余风险：<如有>
```

**没有产物不得宣称完成。** 这条继承 v1 的证据纪律。

# 03-性能基准

- 版本：1.0
- 状态：已定义（**未实测**）
- 上级：[架构入口](../README.md)

本文件定义**在承诺任何性能结论之前必须做的测量**。当前无任何实测数据。

---

<a id="honest"></a>

## 一、先说清楚

数据化的架构**不会自动更快**。

| 方面 | 数据化后 |
|---|---|
| 性能上限 | 更高（同类计算集中，可统一批量化） |
| 原型阶段 | **更慢**（间接寻址、解释执行、调度开销） |
| 热路径 | 取决于是否编译 |

讨论稿已指出这一点，v2 保留这个诚实判断。**"新方案明显更好"这句话在没有基准测试前不成立。**

<a id="prerequisites"></a>

## 二、性能成立的前提

三条前提，缺一则性能优势不成立：

### 1. 规则包加载时编译

```
load → schema 校验 → 静态检查 → 编译为扁平表 + 槽位索引
```

热路径不跑脚本、不做字符串查找、不做类型判断。

**否则**：每次结算都要解释配置，比专用代码慢一个数量级。

### 2. 池与效果的统一调度

Pool 的积分与 `temporal_process` 的 tick 必须走**同一条编译后的循环**。

**否则**：近场每帧仍有 34 套调度器（当前真实代码的状态）。

### 3. 按聚合方式选择存储

| aggregation | 存储 |
|---|---|
| `none` | 个体数组（SoA） |
| `sum` | 总量 + 变更记录 |
| `distribution` | 桶计数 |
| `ordered` | 有序数组 |

**必须是注册时就决定，不能运行时判断。** 运行时判断会让热路径带上分支。

<a id="four-benchmarks"></a>

## 三、四个必须跑的基准

### B1. 近场 Actor 池计算

```
场景：100 / 500 个近场 Actor，每人 3 个池 + 5 个 temporal_effect
测量：每模拟步耗时
对比：手写专用结构 vs 编译后的通用实现
阈值：通用实现不超过手写的 1.5 倍
```

### B2. 单次命中全链路

```
场景：一次命中，5 层剖面，结算到提交
测量：端到端耗时
对比：v1 的 4–6 个 Owner 协调 vs 编译后的剖面表
阈值：不劣于 v1
```

### B3. 远场规模

```
场景：1 万实体，个体存储 vs 分布存储
测量：内存占用 + 每窗口耗时
阈值：分布存储内存不随人口线性增长
```

这条是**收益最大的地方**，也是必须证明的地方。

### B4. 事件流与回放

```
场景：30 世界日的事件流
测量：回放速度、checkpoint 大小、投影重建时间
阈值：回放不慢于实时；checkpoint 可接受
```

<a id="hotspots"></a>

## 四、压力热点

| 热点 | 来源 | 缓解 |
|---|---|---|
| 近场每模拟步 | 体力积分、效果 tick、士气 | 统一调度 + 惰性求值 |
| 远场规模 | 县城约 5 万人口，五阶段十三州 | 分布存储 |
| 事件量 | 存储、回放、checkpoint | 统一增量事件、同窗口合并 |
| 桥接同步 | UE ↔ Paralls | 单一差量编码路径 |
| 不变式校验 | 跨 FactType 读取 | 只校验本批次触及的事实 |

<a id="costs"></a>

## 五、数据化带来的开销与缓解

| 开销 | 原因 | 缓解 |
|---|---|---|
| 间接寻址 | FactType 是引用不是字段 | 加载时编译为槽位索引表 |
| 解释执行 | 参数查表 | 编译为扁平表，热路径不查表 |
| 写权检查频繁 | 每批次校验 | 按批次和作用域检查一次，epoch 缓存 |
| 事件更大 | 携带 FactType 引用与版本 | 定义表 + 整数编码，版本放批次头 |
| 调试困难 | 堆栈浅、定义深 | 按 FactType 打统计标签；提供定义追溯投影 |

最后一条是真实的开发成本，不能用"性能"掩盖。

<a id="when-to-abandon"></a>

## 六、什么情况下应放弃数据化

明确的止损条件：

| 信号 | 含义 | 处置 |
|---|---|---|
| B1 超出手写 3 倍以上 | 通用实现的间接成本不可接受 | 热路径池用专用结构，其余用原语 |
| B3 分布存储无内存收益 | 聚合机制没起作用 | 检查 refold 设计；可能是建模错误 |
| B4 回放明显慢于实时 | 事件膨胀 | 检查事件编码；可能需要快照 |
| 编译产物与解释结果不一致 | 编译层有 bug | 停止使用编译产物，先修正确性 |

**混合方案是合法的**：热路径池用专用结构，其余用原语。这不违背架构，只违背"所有东西必须同一实现"的教条。

## 七、不填虚构数值

所有阈值上方标注的是**验收目标**，不是**测量结果**。实测数据须单独记录，附环境、commit、配置。

<a id="acceptance"></a>

## 八、验收

| # | 用例 | 期望 |
|---|---|---|
| N1 | 规则包热加载后首次结算 | 无解释开销（已编译） |
| N2 | 500 Actor 每步耗时 | ≤ 手写实现的 1.5 倍 |
| N3 | 1 万实体分布存储内存 | 不随人口线性增长 |
| N4 | 30 日事件流回放 | 不慢于实时 |
| N5 | 编译产物与解释结果 | 逐位一致 |

N5 若失败，宁可放弃编译也不接受结果不一致。

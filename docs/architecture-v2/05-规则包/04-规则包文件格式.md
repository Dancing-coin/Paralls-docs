# 04-规则包文件格式

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)
- 前置：[规则包总纲](01-规则包总纲.md)、[校验器规则](03-校验器规则.md)

总纲定义了规则包**有哪些内容**。本文件定义**它们如何写成文件、如何组织、如何解析**。

---

<a id="format-choice"></a>

## 一、格式选择：YAML

### 决定

规则包用 **YAML 1.2**，utf-8，LF 换行。

### 理由

| 候选 | 结论 |
|---|---|
| JSON | 无法写注释。规则包需要大量解释性注释（为什么这个阈值） |
| YAML | 有注释、可读性好、解析器成熟 |
| TOML | 深层嵌套笨拙，本项目大量嵌套 |
| 自定义 DSL | 排除——规则包不能带逻辑 |
| 二进制 | 不可评审 |

### 硬约束

| 约束 | 理由 |
|---|---|
| 只允许 YAML 的**数据子集** | 禁止锚点、别名、标签、多文档、自定义类型 |
| 禁止 `!!` 类型标签 | 解析器行为差异 |
| 键必须是字符串 | 避免 `yes`/`no` 被解析成布尔 |
| 所有字符串必须加引号 | 同上 |
| 数值必须是数字字面量 | 不用科学计数法 |
| 文件 ≤ 512 KB | 超过说明该拆分 |

最后一条的判据：**规则包应当能被一个人在一个屏幕上读懂一半。**

## 二、目录结构

```
packs/
  han_realistic/
    pack.yaml                    包清单（必需）
    entity_types/
      soldier.yaml
      gate.yaml
      siege_ladder.yaml
    pool_defs/
      health.yaml
      stamina.yaml
      gate_durability.yaml
    machine_defs/
      gate_latch.yaml
      lifestate.yaml
    temporal_effects/
      bleeding.yaml
      burning.yaml
    impact_profiles/
      soldier.yaml
      gate.yaml
    aggregation/
      morale_refold.yaml
    command_catalog/
      orders.yaml
    fact_types/
      character_health.yaml
    models/
      damage_models.yaml          模型引用与参数
    bindings/
      soldier_bindings.yaml
```

### 规则

| 规则 | 说明 |
|---|---|
| 每个文件一个主题 | 文件名即主题名 |
| 同一主题可拆多文件 | 按实体/场景拆，不按字段拆 |
| 文件名小写蛇形 | 与 FactType 命名一致 |
| 目录名与总纲的 content 键一致 | 便于机械校验 |

<a id="manifest"></a>

## 三、包清单 pack.yaml

每个包必须有且仅有一个：

```yaml
pack_id: "han_realistic"
pack_version: "2.1.0"
schema_version: 1

parent_pack: null
# 或
# parent_pack:
#   pack_id: "han_realistic"
#   pack_version: "2.0.0"

description: "汉末写实设定：县城守城所需的最小规则集"
authors: ["..."]
license: "..."

# 内容清单：列出本包含哪些条目，用于校验完整性
contents:
  test: []
  entity_types: ["soldier", "gate", "siege_ladder"]
  pool_defs: ["health", "stamina", "gate_durability"]
  machine_defs: ["gate_latch", "lifestate"]
  temporal_effects: ["bleeding", "burning"]
  impact_profiles: ["soldier", "gate"]
  aggregation_models: ["morale_refold"]
  command_catalog: ["orders"]
  fact_types: ["character_health"]
  models: ["damage_models"]
  bindings: ["soldier_bindings"]

# 依赖的模型实现（代码，不在包内）
requires_models:
  - "shield_absorb@v2"
  - "armor_mitigation@v3"
  - "body_damage@v2"
```

### 校验

| 检查 | 拒绝码 |
|---|---|
| `contents` 列出的条目必须存在 | `pack_content_missing` |
| 目录中存在但 `contents` 未列出 | `pack_content_undeclared` |
| `requires_models` 引用的模型未注册 | `pack_model_unknown` |
| `parent_pack` 成环 | `pack_cycle_in_parents` |

**双向校验是有意的**：只查「声明了但不存在」会漏掉「存在但忘了声明」，而后者会让覆盖叠层失效。

<a id="entry-shape"></a>

## 四、条目通用形状

每个条目文件是一个**映射**，键是条目 ID：

```yaml
# pool_defs/health.yaml
health:
  bound_lower: "0"
  bound_upper: "100"
  initial: "100"
  integration:
    mode: "none"
  hysteresis: []

stamina:
  bound_lower: "0"
  bound_upper: "100"
  initial: "100"
  integration:
    mode: "rate"
    rate_per_tick: "-0.05"
  hysteresis:
    - state: "exhausted"
      enter_below: "20"
      exit_above: "30"
```

### 通用字段

| 字段 | 必需 | 说明 |
|---|---|---|
| `description` | 否 | 人类可读说明 |
| `version` | 否 | 该条目自身的版本，缺省继承包版本 |
| `deprecated` | 否 | 标记弃用，附替代者 |

<a id="numeric-convention"></a>

## 五、数值约定

### 定点小数

所有小数用**带引号的十进制字符串**：

```yaml
bound_upper: "100"          # 整数也建议加引号，统一处理
rate_per_tick: "-0.05"
enter_below: "20.5"
```

**禁止**：

```yaml
value: 0.1                  # 浮点，双端不等价
value: 1e-5                 # 科学计数法
value: !!float 0.1          # 类型标签
```

### scale

每个会参与计算的量必须声明 scale：

```yaml
decimals: 4
```

含义：所有值按 10^4 定点存储。`"62.5"` → `625000`。

**同一条计算链上所有量的 scale 必须一致**，否则注册失败。

### 为什么不用 YAML 原生数字

YAML 1.1 会把 `yes`/`no`/`on`/`off` 解析成布尔，`1.0` 的精度依解析器而异。全部加引号 + 显式 scale 可以消除这些不确定。

<a id="inheritance"></a>

## 六、继承与覆盖

### parent_pack 叠加

```yaml
# zhaoling_siege_tuning/pack.yaml
pack_id: "zhaoling_siege_tuning"
pack_version: "1.0.0"
parent_pack:
  pack_id: "han_realistic"
  pack_version: "2.1.0"
contents:
  pool_defs: ["gate_durability"]      # 只覆盖这一项
```

### 覆盖规则

| 规则 | 说明 |
|---|---|
| 按条目 ID 覆盖 | 同 ID 的条目整体替换，不逐字段合并 |
| 未列出的条目继承父包 | |
| 可新增条目 | 不在父包中的 ID |
| **不可删除父包条目** | 只能 `deprecated` |

### 逐字段合并不允许

**理由**：逐字段合并会让「这个值到底来自哪个包」不可判定，而规则包必须能被精确固定。

整体替换 + 显式引用父版本，保证任一时刻的解析结果是确定的。

### 解析路径

```text
resolved_packs:
  - pack_id: "han_realistic"
    pack_version: "2.1.0"
    content_hash: "sha256:..."
  - pack_id: "zhaoling_siege_tuning"
    pack_version: "1.0.0"
    content_hash: "sha256:..."
```

`content_hash` 是包内容的规范序列化摘要，用于存档固定。

<a id="no-logic"></a>

## 七、禁止的写法

| 禁止 | 示例 | 理由 |
|---|---|---|
| 条件分支 | `if armor > 0: ...` | 规则包不带逻辑 |
| 表达式 | `"health * 0.3"` | 同上 |
| 函数调用 | `clamp(x, 0, 100)` | 逻辑 |
| 锚点别名 | `<<: *base` | 解析器差异 |
| 多文档 | `---` 分隔多个文档 | 一文件一主题 |
| 自定义类型 | `!!pool` | 解析器差异 |
| 环境变量 | `${HOME}/packs` | 不可回放 |

### 例外：模型引用与参数

```yaml
damage:
  model_ref: "armor_mitigation@v3"
  params:
    armor_ratio: "0.5"
```

`armor_ratio` 是**参数**，不是逻辑。计算在已注册的 `armor_mitigation@v3` 里。

<a id="loading"></a>

## 八、加载流程

```
1. 读 pack.yaml
2. 解析 parent_pack 链（深度上限 8）
3. 逐包读取 contents 列出的文件
4. 双向校验声明与存在性
5. 计算 content_hash
6. schema 校验（YAML 数据结构）
7. 静态检查（校验器规则 40+ 条）
8. 编译为运行时结构
9. 注册到 FactType / 模型 / 绑定表
```

任一步失败 → 整体拒绝加载，**不部分加载**。

### 编译产物

| 源 | 产物 |
|---|---|
| 池定义 | 边界表 + 积分参数表 + 滞回带表 |
| 状态机 | 转移矩阵（状态 × 事件 → 目标态） |
| 受击剖面 | 层序表（按 resolution_order 扁平化） |
| 绑定 | 目标类型 → 模型列表查找表 |
| 命令目录 | 命令 → 处理 Owner 路由表 |

**热路径不读 YAML、不做字符串查找、不做类型判断。**

<a id="hot-reload"></a>

## 九、热加载

**只允许在非运行态。**

| 时机 | 允许 |
|---|---|
| 编辑器中（未进入 PIE） | ✓ |
| 世界创建前 | ✓ |
| 运行中 | ✗ |
| 迁移事件之后 | ✓（新段用新包） |

**理由**：运行中换设定会让同一场战斗前后用不同参数，且无法回放。

---

<a id="versioning"></a>

## 十、版本语义

用**语义化版本**，但含义专门化：

| 段 | 何时递增 |
|---|---|
| MAJOR | 删除或重命名已有条目；改变条目语义 |
| MINOR | 新增条目；新增可选字段 |
| PATCH | 只改参数值；修错别字 |

**关键**：MAJOR 变更会导致旧存档无法用新包解释，必须走迁移事件。

<a id="acceptance"></a>

## 十一、验收

| # | 用例 | 期望 |
|---|---|---|
| P1 | 包内含 `if` 写法 | 加载拒绝 |
| P2 | 数值用浮点字面量 | 加载拒绝 |
| P3 | contents 声明了不存在的文件 | 拒绝 |
| P4 | 文件存在但未声明 | 拒绝 |
| P5 | parent_pack 成环 | 拒绝 |
| P6 | 同一包两次加载 | `content_hash` 相同 |
| P7 | 覆盖包只改一个参数 | 其余条目继承父包 |
| P8 | 运行中热加载 | 拒绝 |
| P9 | 加载后同一输入两次结算 | 结果相同 |

# 04-与 v1 的对照

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)
- v1 全文备份：`docs/_backups/architecture_v1_20261103_1241/`

本文件回答两个问题：v1 的每条内容去哪了；哪些原样保留。

---

<a id="disposition"></a>

## 一、处理方式四分类

| 标记 | 含义 |
|---|---|
| **继承** | 原样保留，概念和条款都不变 |
| **替换** | 概念保留但组织方式改变 |
| **新增** | v1 没有的能力 |
| **降级** | 从"必须交付"降为"一种配置" |

<a id="preserved"></a>

## 三、明确不变的部分

以下 v1 条款**逐字保留其语义**：

1. 每条事实在每个作用域和 epoch 内只有一个 canonical writer。
2. 模型结果不是事件。
3. 未知不默认零 / false / 成功。
4. 回放用旧版本，不按新公式重算。
5. 补偿追加新事件，不擦除损失。
6. 医疗是 Workflow，不是领域 Owner。
7. 城门政令 / 机械状态 / 通行 / 控制分属 Government / Production-Facility / Presence / Territory，互不代写。
8. `Objective` 只读已确认事实，不写控制权、身体、合法性。
9. 本地权威 receipt 前保持 pending/predicted；仅后端 store 时断线不擅自升格。
10. 角色档案三分：`authored_static` / `world_dynamic` / `agent_private`。

## 四、v1 声称但代码中缺失的三项

这是 v2 与 v1 文档之间唯一实质性的证据冲突。三项均为 v2 的内核必修项。

| # | 项 | v1 | 代码实际 | v2 处理 |
|---|---|---|---|---|
| 1 | 可见性强制 | "有限知情"是正式技术成功判据 | `visibility_policy` 有字段、`settlement_plan.py:22` 校验数量；`event_store.py` **读时不查**。全仓仅两个专用视图做过裁剪 | [可见性强制](../01-内核/02-可见性强制.md) 升为 L0 强制 |
| 2 | 三本账时间 | `event_time/known_time/presented_time` 统一回放 | grep `known_time` / `presented_time` **零命中** | [时间与暂停](../01-内核/01-时间身份与暂停.md) 列为必修 |
| 3 | 权威栅栏 | authority epoch fencing | `authority_epoch` 仅在 `ws_protocol.py:45` 有字段，无 fencing | [权威栅栏](../01-内核/03-权威栅栏与提交.md) |

另有一项从未写明的假设：v1 的"`world_tick` 来自 UE 战场时钟"与"WRK 拥有唯一 `world_tick`"要求两者同进程。v2 在 [时间与暂停](../01-内核/01-时间身份与暂停.md) 中显式登记为部署前提。

<a id="v1-defects"></a>

## 五、v1 内部不一致（讨论记录第 2.2 节的 9 项）

| # | v1 问题 | v2 处理 |
|---|---|---|
| 1 | 命令类型与 Owner 不一一对应（`retreat` 同时在 Combat 与 Morale） | 命令归 L4 `command_catalog`，每个命令显式绑定唯一的处理 Owner |
| 2 | 在途消息归属不清（Dispatch vs Information） | 两者共用 L1 `Process` 原语，事实类型分开 |
| 3 | "谁知道什么"双写（Information vs 角色记忆账） | Information 写公共知情事实；记忆账写私有认知。二者由 `visibility` 的 `learnable_by` 连接 |
| 4 | 授权三处来源，Capability 范围未定义 | 授权集中为 `Bond` 原语的一类（授权契），Organization/Government 各自写自己的授权事实 |
| 5 | Workflow 有持久状态但无登记规则 | L5 `workflow` 有正式登记 schema |
| 6 | Territory 依赖晚于它的批次 | 由生产计划重排，v2 不处理（见 [待决](../10-待决/01-待决清单.md)） |
| 7 | 时间权威措辞矛盾 | 显式登记部署前提（§四） |
| 8 | Gateway 在时序图里充当编排者 | Gateway 只治理与路由；编排归 L5 |
| 9 | `Body/Resource` 与 `Inventory/Resource` 同叫 Resource | 一律改名：Body 不再带 Resource 后缀 |

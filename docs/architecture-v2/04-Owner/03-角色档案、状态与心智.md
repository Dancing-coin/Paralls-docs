# 03-角色档案、状态与心智

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)
- 前置：[三本账与投影](../01-内核/04-三本账与投影.md)、[Agent 接入规格](../05-运行时接入/02-Agent接入规格.md)

本文件定义角色数据的三个命名空间、静态档案如何接入世界事实、以及主观心智与客观指标的边界。

---

<a id="three-namespaces"></a>

## 一、三个命名空间

角色数据必须分三类，**不能用一个大 `DynamicState` 统称**。

| 命名空间 | 内容 | 写入者 | 智能体用途 |
|---|---|---|---|
| `authored_static` | 身份、人格、价值观、动机优先级、身体基线、能力/关系种子 | 内容配置；成为运行事实前必须由对应 Owner 接纳 | 稳定设定与决策偏置 |
| `world_dynamic` | 生命、体力、饥饿、疲劳、伤势、装备耐久、位置、库存、实时士气 | 对应 Gameplay Owner | L1 的权威事实投影 |
| `agent_private` | 信念、主观体感、解释、目标、动机冲突、记忆写回 | 角色智能体私有运行时 | L2/L3/L4 的输入与输出 |

### 三者的关系

```
authored_static  ──(Owner 接纳)──→  world_dynamic
       │                                  │
       └──────────┬───────────────────────┘
                  ↓
            agent_private
```

**关键约束**：

| 约束 | 说明 |
|---|---|
| 档案不直接写世界事实 | 人格影响解释与规划，不改生命/库存/公式 |
| 私有心智不回写世界 | 恐惧、怀疑、误解都留在 `agent_private` |
| 世界事实不直接改心智 | 必须经感知与解释 |

最后一条最容易被违反：**角色受伤不等于他"知道"自己受伤**。受伤是 `world_dynamic`，疼痛是 `agent_private`，中间隔着感知。

<a id="dossier-projection"></a>

## 二、静态档案的可见性投影

`CharacterDossier` 的原始内容**不能直接进入 L2/L3/L4**，必须经 audience/visibility 投影。

### 可见性档位

| 档位 | 含义 |
|---|---|
| `visible` | 完整可见 |
| `summarized` | 摘要 |
| `partial` | 部分字段 |
| `belief_only` | 只作为"他以为的"给出 |
| `constraint_only` | 只给约束，不给内容 |
| `action_relevant_only` | 只给与当前动作相关的 |
| `hidden` | 不可见 |

### 按 audience 裁剪

| audience | 能看到的范围 |
|---|---|
| `author` | 全部 |
| `self` | 本人的全部 |
| `player` | 按玩法允许的部分 |
| `l2` | 解释所需 |
| `l3` | 规划所需（秘密只给 `constraint_only` 计数） |
| `l4` | 仅具身动作线索 |

**L3 拿不到秘密内容，只知道"有 N 条秘密约束"。** 这保证规划不会"因为知道秘密而做出不该有的判断"。

### 种子不是事实

```text
relationship_seed_profile   → candidate_only
capability_seed_profile     → candidate_only
```

**档案里有关系或能力，不等于运行时有关系或能力。** 必须经对应 Owner 接纳并返回 receipt，才成为 live 事实。

<a id="survival-vs-motivation"></a>

## 三、两类"需求"必须分清

这是本文件最重要的一节。

| 语义 | 名称 | 例子 | 归属 |
|---|---|---|---|
| 客观生理指标 | `SurvivalMetricState` | 能量储备、水分、疲劳值 | Survival / Body |
| 指标定义与公式 | `SurvivalMetricDefinition` | 衰减率、范围、单位、阈值 | Survival / Rule Registry |
| 阈值条件与持续效果 | `PhysiologicalCondition` / `StatusEffect` | `condition:hunger`、`effect:starvation` | Status / Effect |
| **主观动机压力** | `MotivationalPressureState` | 生理压力、安全压力 | **Character Agent** |
| 静态动机偏好 | `MotivationalPriorityProfile` | 生理/职责/荣誉的权重 | Character Dossier |
| 角色准备做什么 | `ActionIntent` | 吃、请求配给、忍耐、偷取 | Character Agent |

### 关系

```
SurvivalMetricState（客观：我缺什么，缺多少）
  → threshold rule
PhysiologicalCondition（身体状态）
  → scoped self projection
Character Agent + MotivationalPriorityProfile + 记忆 + 命令
  → MotivationalPressureState（主观：我有多在意）
  → ActionIntent（我要做什么）
```

### 为什么必须分开

**「饥饿」是客观的，「我觉得饿」是主观的。**

- 客观指标低 → 产生身体条件
- 主观压力高 → 产生行动意图

两者可以不一致：

| 情形 | 客观 | 主观 | 行为 |
|---|---|---|---|
| 一样的饥饿程度 | 相同 | 低（训练有素） | 继续执勤 |
| | 相同 | 高（体质弱） | 请求轮换 |
| 一样的饥饿程度 | 相同 | 低（在守城 deadline 前） | 忍着 |
| | 相同 | 高（有人在看着） | 当众抱怨 |

**如果混用，缺粮就会自动变成行为**——那就没有角色差异了。

### 旧名兼容

`NeedState`、`NeedTensionState` 等旧名可保留兼容解析，但**新接口不应继续扩大歧义**。

<a id="admission"></a>

## 四、静态档案如何接入世界事实

| 档案内容 | 接入方式 |
|---|---|
| 人格、价值观、动机优先级 | **不接入**。只影响解释与规划 |
| 年龄、体型、先天体质 | 需 Body/Survival Owner 声明为公式输入，并固定 `profile_revision` |
| 官职、权限、职责 | 必须由 Identity / Organization / Capability Owner 接纳 |
| 关系种子 | 进入 Social Owner 的候选接纳流程 |
| 能力种子 | 进入 Ability / Skill Owner 的候选接纳流程 |
| 身体外观、姿态基线 | 影响表现与物理可行性投影，**不覆盖**已有伤势 |

**最后一条的理由**：外观参数热更新不能覆盖运行时已发生的伤势、疲劳、疼痛。

<a id="dynamic-closure"></a>

## 五、动态状态的完整闭环

```text
Owner 提交事实
  → source_owner + source_revision + captured_at + freshness
  → CharacterSelfStateProjection
  → L1 私有感知
  → L2 解释
  → L3 规划
  → L4 执行语义
  → ActionIntent / typed Command
  → 目标 Owner 结算
  → receipt + 新投影
```

### 角色动态状态不是什么

`CharacterDynamicState` 主要保存 affect、tension、motivation。

**它不是生命、饥饿或护甲耐久的总状态。** 那些属于 `world_dynamic`，由 Owner 拥有。

`NeedTensionState` 也不是饥饿计量表，而是角色根据事实、档案、记忆、关系和目标形成的**主观压力**。

<a id="examples"></a>

## 六、两个完整示例

### 进食

```
Survival Owner：能量储备下降
Status Owner：派生 condition:hunger
Character Agent：判断 吃 / 请求配给 / 忍耐 / 偷取 / 继续执勤
Inventory Owner：检查归属、位置、预留和消耗
Survival Owner：接受营养结果并恢复指标
Character Agent：收到结果，更新主观满足/挫败与下一步策略
```

**系统不能仅因阈值低就自动扣粮**，除非存在被组织政策或失能护理流程授权的自动行为 Command。

### 受伤

```
Combat / ESM：产生命中证据
Body Owner：生命、部位功能、伤势变化
Equipment Owner：护甲耐久变化
Status Owner：根据条件生成 bleeding / impaired / critical
Character Agent：读取权威投影与主观体感，决定撤退、求医或继续
```

**标签是投影载体，持续效果必须有实例。** `status:bleeding` 是标签，它的本体是带来源、强度、层数、生命周期的效果实例。

<a id="acceptance"></a>

## 八、验收

| # | 用例 | 期望 |
|---|---|---|
| D1 | 档案含秘密，L3 请求 | 只得到 `constraint_only` 计数 |
| D2 | 关系种子存在但未接纳 | 不产生 live relationship |
| D3 | 缺粮但未达阈值 | 不自动扣粮，角色可自主行动 |
| D4 | 同客观指标、不同档案 | 主观压力不同，行为不同 |
| D5 | 受伤但未感知 | 心智状态无变化 |
| D6 | 档案热更新外观 | 不覆盖已有伤势 |
| D7 | 效果标签查询 | 标签存在但实例必须可追溯 |

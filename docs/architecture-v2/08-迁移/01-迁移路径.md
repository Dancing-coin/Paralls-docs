# 01-迁移路径

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)

**不重写 81k 行。** v2 的迁移是"先减重，再分层"。

---

<a id="principle"></a>

## 一、原则

| 原则 | 含义 |
|---|---|
| 行为保持 | 抽取机制时不改语义，靠约 1000 个现有测试兜底 |
| 逐域 | 一次只迁一个域，迁完验证再下一个 |
| 先减重后分层 | 先消除重复实现，再引入 FactType 声明 |
| 原语最后落地 | Pool / Bond 原型验证通过前，不动 L2 以上 |
| 不删除 | 旧 runtime 保留为原生 Owner 实现，不推倒 |

<a id="phases"></a>

## 二、五个阶段

### 阶段 0：证据与前提

**不做改动，只核实。**

| 任务 | 产出 |
|---|---|
| 修正 v1 文档中的失效路径 | `docs/architecture/01-系统边界/02-现状基线与证据.md` 的七组参考路径当前指向不存在的 `D:\Users\User\Documents\paralls-phase-0-demo`；真实位置 `D:\Paralls-phase0-1` |
| 建立"文档主张 ↔ 代码事实"对照表 | 已完成三项冲突：[可见性](../01-内核/02-可见性强制.md)、三时间、epoch 栅栏 |
| 确认测试基线 | 现有测试全部通过的 commit 作为迁移起点 |

**放行条件**：三项冲突的处置方式已定，测试基线与迁移起点已记录。

---

### 阶段 1：原语原型（**阻塞全案**）

见 [分水岭实验](04-分水岭实验.md)。

| 任务 | 判定 |
|---|---|
| Pool 原型：有界 + 预留 + 窗口积分 + 滞回 | 固定向量通过 |
| Bond 原型：五种契压成同形状，支持 scope + term + 多类型共存 | 固定向量通过 |
| 收敛判定 | 若 Bond 压不进，原语清单重审，L2 以上全部重写 |

**放行条件**：两个原型通过。**不通过则停止，不要继续。**

---

### 阶段 2：抽取共享基类

**行为保持重构。** 目标是把重复实现收进一处。

| 现状 | 目标 |
|---|---|
| 28 个 runtime 各自实现幂等 | 1 处 |
| 33 个各自处理 revision | 1 处 |
| 29 个各自处理可见性 | 1 处 |
| 16 个各自处理 receipt | 1 处 |

**方法**：

```
1. 选一个域（建议 Inventory，已验证最完整）
2. 抽出基类，该域改用手写
3. 对比迁移前后全部测试结果，必须完全一致
4. 逐个迁移其余域，每迁一个做一次全量回归
5. 任一域出现行为差异 → 停止，回退该域
```

**风险**：34 个域、81k 行，回归风险最高的一步。**不允许"顺手改逻辑"。**

**放行条件**：全部域迁移完成，测试 100% 通过，无行为差异。

---

### 阶段 3：补 L0 三个洞

| 洞 | 当前状态 | 目标 |
|---|---|---|
| 可见性强制 | 字段有，读端不过滤 | `read_as(principal)` 强制过滤 |
| 三时间 | 零命中 | `event_time` / `known_time` / `presented_time` 可查 |
| epoch 栅栏 | 仅 `ws_protocol.py:45` 一个字段 | 提交时校验，旧 epoch 拒绝 |

**顺序**：可见性优先——它是体验内核，且是唯一"当前有明确漏洞"的一项。

**放行条件**：三项各自的验收用例通过（见各文档）。

<a id="what-not-to-do"></a>

## 三、明确不做的事

| 不做 | 理由 |
|---|---|
| 重写 34 个 runtime | 成本收益相反 |
| 把原生 Owner 改成托管 | Dispatch / Politics / Economy 的规则无法数据化 |
| 一次性迁移全部域 | 回归风险不可控 |
| 在原型未通过前写 L2 以上规格 | 切法错了会全部重写 |
| 为 Demo 快速路径建临时旁路 | v1 已明确禁止，v2 继承 |

---

<a id="risk-table"></a>

## 四、风险与止损

| 风险 | 早期信号 | 止损动作 |
|---|---|---|
| Bond 收敛失败 | 五种契无法用同形状表达 | 原语改 5 或 7 个，重写 L2 以上 |
| 基类抽取引入回归 | 任一测试结果变化 | 停止，回退该域，不改逻辑只改结构 |
| Process 归并失控 | 8 个模块的步骤语义差异过大 | 分批归并，先归 3 个 |
| 规则包变成配置堆 | FactType 数量快速膨胀、无人能读懂 | 原语封顶 + 命名规范 + 校验器 |
| 可见性改造影响性能 | 投影延迟上升 | 按 principal 缓存资格；投影增量更新 |
| 迁移期双写 | 同一结果两条 receipt | 立即停止迁移，定位第二写入口 |

<a id="effort"></a>

## 五、工作量信号

粗略量级，用于排期而非承诺：

| 阶段 | 相对成本 | 说明 |
|---|---|---|
| 0 证据与前提 | 低 | 文档 + 核对 |
| 1 原语原型 | **中高** | 决定全案，不能省 |
| 2 基类抽取 | **高** | 34 域、81k 行，最重的一步 |
| 3 L0 三洞 | 中 | 可见性最重，另两项中等 |
| 4 FactType 与管线 | 中 | 单域打通 |
| 5 分水岭 | 低 | 验证实验 |

对比 v1 的 207 个交付格：v2 把交付量集中到"6 个原语 + 2 个原型 + 1 个基类 + 1 个域"，其余环节是声明。

**但前期出效果更晚**——这是本设计的已知代价，不能否认。

<a id="rollback"></a>

## 六、回退

| 已完成的阶段 | 回退方式 |
|---|---|
| 阶段 1 原型 | 独立模块，删除即可，不影响主库 |
| 阶段 2 基类 | 行为保持重构，git revert 即可 |
| 阶段 3 L0 | 可见性过滤可降级为"记录不拦截"；epoch 校验可降级为告警 |
| 阶段 4–5 | FactType 注册表可回退到上一个 pack 版本 |

**阶段 2 一旦开始，必须逐域提交，保证任一域可独立回退。**

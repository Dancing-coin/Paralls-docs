# 01-原语总则

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)

原语是**事实的状态形状**。它只守不变量，不含任何设定（界值、阈值、状态集都在 L4 规则包）。

---

<a id="six"></a>

## 一、六个原语（封顶）

| 原语 | 不变量一句话 | 生命体例 | 非生命体 / 集体例 |
|---|---|---|---|
| **Pool 量** | 有界；预留后才消耗，不超支；按窗口积分；阈值带滞回 | 生命、体力、精神力、个人士气 | 门扇耐久、城墙完整度、燃料、队伍士气 |
| **Machine 态** | 只允许合法转移；转移条件有版本 | 存活/倒地/濒死/死亡 | 完好/破口/废墟；门开/关/闩；阵型 |
| **Holdings 集** | 总量守恒；预留与转移原子 | 随身携带 | 仓库、车厢、账户 |
| **Bond 契** | 有向、有作用域、有有效期、可撤销 | 亲缘、忠诚、授权 | 产权、保管、控制 |
| **Process 程** | 每步幂等；有进度与开放义务；可中断恢复 | 治疗、训练 | 传令、运输、修缮、生产 |
| **Place 位** | 占用互斥；通行性有语义提交点 | 人的位置 | 车、器械、队伍位置 |

**六个是上限，不是起点。** 新增第七个必须走 [新增原语流程](../00-总纲/03-反模式与硬约束.md#adding-primitive)。

<a id="not-primitives"></a>

## 二、不是原语的三样

这三样在讨论中反复被误认为原语，必须明确归属。

### 1. 实体与构成 → 不是原语

"实体类型声明自己有哪些构成"是 **schema**，属于：

- L4 规则包的 `entity_types`
- L0 身份注册表的实体类型登记

**若把它当原语，原语引擎里会长出一张实体表——那就是第二个万能 Owner。** 原语只描述"某个值长什么样"，不描述"世界上有哪些东西"。

### 2. 属性与修正 → 不是原语，是投影

"只存基础值，有效值由修正源推导"——这正是"派生、不存储"的定义。

归属于：

- L0 投影机制（`effective_stats.py` 的 `StatBaseline` / `StatModifier` / `EffectiveStatResolver` 是它的第一个实现）
- 修正源本身是 `Bond`（谁给谁加什么）或 `TemporalEffect`（效果带来的修正）

存储有效值会引入双写：基础值与有效值不一致时以谁为准？

### 3. 效果 → 不是原语，是 Process 的特化

效果实例的唯一特殊行为是"按 tick 向某个 Pool 的 Owner 发请求"，这正是**带 tick 触发器的 Process**。

`TemporalEffect` 作为 `Process` 的子型定义，不新增第七个原语：

```text
TemporalEffect ⊂ Process
  额外字段：source_event / stacks / tick_policy / exit_condition
  额外约束：tick 时只能向 Pool 的 Owner 发结算请求，不能直接改值
```

`status_tags.py` 的 `StatusTagRegistry` / `StatusTagInstance` / `StatusTagExpiry` 直接作为它的第一个实现。

### 合并说明

同理，"关系"与"凭据"合并为 `Bond`——两者同形状：有向、有作用域、有有效期、可撤销。分开会导致两套几乎相同的实现。

<a id="why-six"></a>

## 三、为什么是这六个

判据：**能否用其它五个的组合表达，且保持不变量。**

| 尝试组合 | 失败原因 |
|---|---|
| 用 Pool 表达状态机 | Pool 是连续量 + 阈值，无合法转移集；阈值跨越不等于状态互斥 |
| 用 Machine 表达池 | Machine 无界、无积分、无预留 |
| 用 Process 表达 Holdings | Process 无总量守恒，无预留原子性 |
| 用 Holdings 表达 Bond | Holdings 无方向，无作用域，无有效期 |
| 用 Bond 表达 Process | Bond 无步骤，无进度，无开放义务 |
| 用 Process 表达 Place | Place 需要占用互斥，Process 不需 |
| 用 Holdigns 表达 Place | **位置上没有"量"**，占用是关系不是数量 |

最后一行的对照说明了 Place 为何不可省：它表达"同一位置同时只能有一个占用者"，是**互斥**语义，不是数量语义。

<a id="common-spec"></a>

## 四、每个原语的统一规格

六个原语必须提供完全同构的五项，缺一不得注册：

```text
1. 不变量         是什么永远成立
2. 命令语义       可接受哪些操作，幂等语义如何
3. 事件 schema    提交的事件形状，由 event_schema_registry 登记
4. 积分与切窗     连续变化如何按窗口结算，何时必须切窗
5. 聚合方式       在 scope / 精度之间如何表达与重算
6. 提交片段格式   授权 fragment 的形状
```

第 4、5 项是全设计减重的关键：v1 中这些散落在各域正文，每域重写一遍；v2 中写一次，所有 FactType 继承。

<a id="scope"></a>

## 五、原语与作用域

每个原语在任意 `authority_scope` 上实例化，**scope 不改变原语语义**：

```
Pool@角色     生命
Pool@小队     队伍士气
Pool@战区     战区补给
```

三者用同一个 Pool 机制，不同的 `aggregation` 与 `refold_model`。

<a id="layering"></a>

## 六、原语不含的东西

明确排除，防止原语层腐化：

- 不包含任何界值、阈值、初值（→ L4 池定义）
- 不包含状态集与转移表（→ L4 状态机定义）
- 不包含公式（→ L4 Resolver）
- 不包含可见性类别（→ L2 FactType）
- 不包含结算顺序（→ L2 `resolution_order`）
- 不包含任何实体类型知识

原语层只剩：**不变量 + 积分规则 + 幂等形状 + 事件 schema + 聚合方式 + 片段格式。**

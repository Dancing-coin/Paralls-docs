# 02-六原语规格

- 版本：1.0
- 状态：已定义
- 上级：[架构入口](../README.md)

每个原语按统一五项规格定义：不变量、命令语义、事件 schema、积分与切窗、聚合、片段格式。

---

<a id="pool"></a>

## 一、Pool 量

### 不变量

```
P1  0 ≤ value ≤ bound
P2  reserved ≥ 0 且 reserved ≤ bound
P3  available = value - reserved ≥ 0
P4  消耗必须先预留；未预留的消耗一律拒绝
P5  同一世界窗口内不重复积分
P6  阈值跨越必须触发切窗
P7  滞回带内的值变化不触发状态翻转
```

### 命令语义

```text
adjust(delta, reason, window_ref)       幂等键：window_ref
reserve(amount, holder, purpose)        幂等键：reservation_ref
release(reservation_ref)
consume(reservation_ref, actual)
set_bound(new_bound)
```

`consume` 是 `release + adjust` 的原子形式，不可拆成两次调用。

### 事件 schema

```text
pool.initialized        { fact_type, initial, bound }
pool.adjusted           { fact_type, previous, delta, next, window_ref, model_ref }
pool.reserved           { fact_type, reservation_ref, amount, holder, purpose }
pool.released           { fact_type, reservation_ref, amount }
pool.consumed           { fact_type, reservation_ref, amount, actual }
pool.bound_changed      { fact_type, previous, next }
pool.threshold_crossed  { fact_type, threshold_ref, direction, value }
```

### 积分与切窗

```
value(t) = value(t0) + ∫ rate(τ) dτ   over [t0, t]
```

窗口在以下边界结清：输入 revision 变化、阈值跨越、暂停、交接、版本升级。

**投影积分不得掩盖中途不足。** 若窗口内某点 value 曾为 0，必须在事件中保留该事实，不能只提交窗口首尾值。

### 聚合

| 方式 | 含义 | 适用 |
|---|---|---|
| `none` | 各实例独立存储 | 近场个体生命、门扇耐久 |
| `sum` | 总量 = 各实例之和 | 弹药总数、粮草总量 |
| `distribution` | 存统计量而非个体 | 远场队伍、五阶段人口 |
| `ordered` | 有序序列 | 排队、优先级 |

展开与收拢时，`sum` 守恒；`distribution` **不守恒**，按 `refold_model` 重算（见 [聚合与精度](../03-事实类型/03-聚合与精度.md)）。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision, read_set_revisions
  operations: [adjust|reserve|release|consume], 按窗口顺序
  model_ref, input_revision_vector
```

<a id="machine"></a>

## 二、Machine 态

### 不变量

```
M1  当前态 ∈ 声明的状态集
M2  只能沿合法转移表转移
M3  每次转移记录 from / to / condition_ref / condition_revision
M4  条件三值：true 转移 / false 不转移 / unknown 保持并标记待定
M5  终态不可退出（除非规则包声明为可重入）
```

### 命令语义

```text
evaluate(condition_inputs)      幂等键：fact_type + world_tick
transition(to_state, evidence)  校验合法性与条件
```

### 事件 schema

```text
machine.transitioned   { fact_type, from, to, condition_ref, condition_revision }
machine.pending        { fact_type, target, reason: unknown }
machine.locked         { fact_type, state, reason }
```

### 积分与切窗

Machine 无连续积分。但**每次条件输入 revision 变化都触发一次评估**，避免长期不评估导致状态陈旧。

### 聚合

`ordered`（状态序列）或不适用。**Machine 不需要 `sum` 或 `distribution`。**

集体状态（如队伍阵型）是独立 FactType，不是成员状态的聚合。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision
  operation: transition {from, to}
  condition_ref, condition_revision, evidence_refs
```

<a id="holdings"></a>

## 三、Holdings 集

### 不变量

```
H1  总量守恒：Σ entries.quantity + reserved + in_transit = total
H2  预留与转移是原子操作
H3  转移必须指定源与目标，不产生凭空增减
H4  容量约束：Σ quantity ≤ capacity（若声明）
H5  单位与规格兼容才能合并
```

### 命令语义

```text
reserve(lot_ref, amount)                 幂等键：reservation_ref
transfer(src, dst, amount, step_ref)
consume(lot_ref, amount, reason)
split(lot_ref, amount)  → new lot
merge(lot_refs)         → new lot
```

### 事件 schema

```text
holdings.lot_created    { lot_ref, item_ref, quantity, quality, container_ref }
holdings.reserved       { lot_ref, reservation_ref, amount }
holdings.transferred    { src, dst, amount, step_ref }
holdings.consumed       { lot_ref, amount, reason }
holdings.split          { source, results[] }
holdings.merged         { sources[], result }
holdings.lost           { lot_ref, amount, reason }
```

### 积分与切窗

Holdings 本身无积分。但**质量变化是 Pool**——同一批次的数量是 Holdings，质量是 Pool，两者是不同 FactType：

```
fact:lot:wheat-07:quantity    Holdings
fact:lot:wheat-07:quality     Pool
```

这个切分很重要：数量的守恒语义与质量的连续衰减语义不同。

### 聚合

`sum` 为主。`ordered` 用于队列。`distribution` 用于远场大宗物资。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision
  operations: [reserve|transfer|consume|split|merge]
  unit_ref, quality_ref
```

<a id="bond"></a>

## 四、Bond 契

### 不变量

```
B1  有向：subject → target，方向不可互换
B2  有作用域：只在 scope 内有效
B3  有有效期：可永久，但必须显式声明
B4  可撤销：撤销产生新事件，不删除历史
B5  同一 (type, subject, target, scope) 的有效契不得冲突
B6  凭据来源必须可追溯（source_event_ref）
B7  属性是不可变描述符：grant 时写入，此后不改
```

**B7 是原型跨验后补的。** 若某个属性会随事件推进而改变（如债务的未偿额），它不是 Bond 属性，而是一个独立的 FactType（通常是 Pool）。见 §四 "属性不可变"。

### 命令语义

```text
grant(subject, target, type, scope, term)   幂等键：bond_ref
revoke(bond_ref, reason)
transfer(subject, new_target)
supersede(old_bond, new_bond)
```

### 事件 schema

```text
bond.granted     { bond_ref, subject, target, type, scope, term, source_event_ref }
bond.revoked     { bond_ref, reason }
bond.transferred { bond_ref, previous_target, new_target }
bond.expired     { bond_ref }
bond.superseded  { old_ref, new_ref }
```

### 五种契

同一原语的五个类型，不是五个原语：

| 类型 | 语义 | 例 |
|---|---|---|
| `ownership` | 产权 | 这块地属谁 |
| `custody` | 保管 | 谁看着这批粮 |
| `authority` | 授权 | 谁能征发 |
| `affiliation` | 归属 | 谁属哪支队伍 |
| `obligation` | 承诺/债务 | 谁欠谁 |

**关键区分**：产权 ≠ 保管 ≠ 控制。三者可同时存在且归属不同人。v1 已正确保持这个区分，v2 只把它归为一个原语。

### 属性不可变（B7）

Bond 的属性（`attributes`）是**不可变描述符**：在 `grant` 时写入，此后只随 `revoke` / `transfer` / `supersede` 一起作废或重建，**不原地修改**。

各类型允许的属性集是封闭的：

| 类型 | 允许属性 | 说明 |
|---|---|---|
| `ownership` | `share` | 份额 |
| `custody` | `capacity` | 保管容量上限 |
| `authority` | `command_scope`, `delegable` | 授权范围、可否转授 |
| `affiliation` | `rank`, `slot` | 编制等级、阵位 |
| `obligation` | `amount`, `unit`, `due_tick` | **初始**金额、单位、到期 |

未知属性注册期拒绝（防止某类型悄悄长出专属语义）。

**可变的量必须走独立 FactType。** 原型跨验中发现的实例：

```
DebtClaim.outstanding_amount  随还款递减，不是 Bond 属性
  ↓ 拆为
bond.obligation        债权人 → 债务人，契约存在（可撤销、有期限）
pool.debt.<id>         outstanding_amount，界 [0, principal]，按还款递减
machine.debt.<id>      active → overdue → satisfied / cancelled
```

这不是 Bond 的失败，而是"一个领域事实由多个 FactType 组成"的正常结果——与食品变质拆成 Pool + Machine + Process 同理。

若允许可变属性，Bond 会退化成一个可以装任意状态的袋子，那正是万能 Owner 的雏形。

### target 可以指向实体物品

`target_ref` 是一个字符串引用，可以是抽象资产（`asset:granary-01`），也可以是实体物品（`item:credential-07`）。

这条来自凭证机制的跨验：`CredentialLink` 把一条产权契绑定到一件具体物品上，验证时同时读 Inventory 投影（物品是否在出示者身上）与 Ownership 投影（出示者是否是权利持有者）。

```
Bond      存契约关系：谁对什么享有什么
Credential 存证明物：哪件实体物品可以证明它
```

两者是引用关系，不合并。凭证有效性若绑定在某个 Inventory revision 上，那是**跨 FactType 不变式**，由 Owner 持有，不是 Bond 的属性。

### 积分与切窗

到期由世界时钟驱动，到期即切窗并产生 `bond.expired`。

### 聚合

不适用。契不是可加的量。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision
  operation: grant|revoke|transfer|supersede
  subject, target, scope, term, source_event_ref
```

<a id="process"></a>

## 五、Process 程

### 不变量

```
R1  每步幂等：同一 step_index 重复执行返回原结果
R2  步骤只能前进，不可回退（回退是补偿，新事件）
R3  进度与开放义务必须可恢复
R4  中断保留已消费资源与已发生步骤
R5  取消不撤销已提交步骤
R6  每步声明依赖的输入 revision
```

### 命令语义

```text
start(process_def_ref, inputs)
advance(step_index)            幂等键：process_id + step_index
interrupt(reason)              保留当前状态
resume(from_step)
cancel(reason)                 不撤销已提交步骤
```

### 事件 schema

```text
process.started     { process_id, process_def_ref, input_revisions }
process.step_done   { process_id, step_index, result_ref, receipt_ref }
process.interrupted { process_id, step_index, reason, open_obligations[] }
process.resumed     { process_id, from_step }
process.completed   { process_id, outputs[] }
process.failed      { process_id, step_index, reason, compensations[] }
process.cancelled   { process_id, committed_steps[], reason }
```

### 时间型过程（temporal_process）

Process 的子型，用于带周期触发的过程：

```text
额外字段：tick_policy, next_tick, exit_condition
额外约束：tick 只能向 Pool 的 Owner 发结算请求，不直接改值
幂等键：process_id + scheduled_world_tick
```

`TemporalEffect`（流血、燃烧、恐慌）是它的一个形态：

```
temporal_process
  ├─ 医疗过程（包扎、服药）
  ├─ 训练过程
  ├─ 传令过程
  ├─ 运输过程
  ├─ 生产过程
  └─ 效果过程（流血、燃烧、锈蚀）    ← v1 的 "Status / Effect"
```

**统一的价值**：v1 中"治疗幂等 `treatment_id + step`"与"效果幂等 `effect_id + scheduled_world_tick`"是两条独立规则，各域各写；v2 中它们是同一个原语规格的两个键形状。

### 积分与切窗

Process 无连续积分，但 tick 型过程必须按 `scheduled_world_tick` 结算，跨 tick 不合并。

### 聚合

不适用。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision
  operation: start|advance|interrupt|resume|cancel
  step_index, input_revisions, open_obligations[]
```

<a id="place"></a>

## 六、Place 位

### 不变量

```
L1  同一位置同一时刻只能有一个占用者（若声明互斥）
L2  到达与脱离是语义提交点，不是每帧坐标
L3  路径与占用有 revision，冲突必须可检测
L4  通行性变化必须由独立的语义提交点声明，不由其它原语自动继承
L5  位置事实引用空间注册表，不用表现层坐标替代
```

### 命令语义

```text
occupy(place_ref, holder)     幂等键：occupancy_ref
vacate(occupancy_ref)
move_to(target_ref, path_ref)  产生阶段与到达提交点
block(place_ref, reason)       通行性变更
```

### 事件 schema

```text
place.occupied      { place_ref, holder_ref, occupancy_ref }
place.vacated       { place_ref, occupancy_ref }
place.departed      { holder_ref, from_ref, path_ref }
place.arrived       { holder_ref, to_ref }
place.blocked       { place_ref, reason, source_event_ref }
place.rerouted      { holder_ref, previous_path, new_path }
place.intercepted   { holder_ref, by_ref, place_ref }
```

### 积分与切窗

位置本身不积分。**但 Actor 连续轨迹不得逐帧写入事件账**，只在语义提交点提交：

```
move_started / arrived / blocked / rerouted / intercepted / withdrawn
```

### 聚合

`none`。位置不是可加的量。

集体位置（队伍中心、行军纵队）是独立 FactType，由 `distribution` 表达精度，不是个体位置的求和。

### 片段格式

```text
fragment:
  fact_type_ref, owner_ref, expected_revision
  operation: occupy|vacate|depart|arrive|block|reroute
  place_ref, holder_ref, path_ref, evidence_refs
```

## 七、六原语对照速查

| | Pool | Machine | Holdings | Bond | Process | Place |
|---|---|---|---|---|---|---|
| 连续量 | ✓ | | | | | |
| 有界 | ✓ | | | | | |
| 互斥 | | ✓ | | | | ✓ |
| 守恒 | | | ✓ | | | |
| 有向 | | | | ✓ | | |
| 有步骤 | | | | | ✓ | |
| 有 tick | | | | | ✓ | |
| 可聚合 | ✓ | | ✓ | | | |
| 需切窗 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 有幂等键 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

**没有一列能省。**这是六原语的论证：每一种组合都缺一列。

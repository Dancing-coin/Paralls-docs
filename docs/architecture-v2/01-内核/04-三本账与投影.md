<a id="three-ledgers"></a>

## 一、三本账

「三本账」不是三个事件库，而是**同一条事件流的三个观察面**。

| 账 | 回答 | 存储 |
|---|---|---|
| **世界真相账** | 世界上实际发生了什么 | EventStore（唯一权威） |
| **角色记忆账** | 某个角色知道了什么 | Character Agent 私有（`agent_private`） |
| **表现账** | 玩家此刻看到什么 | UE 表现层（可丢弃、可重建） |

三者之间的关系：

```
世界真相账  ──(可见性过滤)──→  角色记忆账
     │                              │
     └──(可见性过滤)────────────────→  表现账
```

**关键**：后两者都是**从前者推导的**，不拥有独立事实。角色记错、表现延迟、UI 缺失，都不改变世界真相。

---

<a id="three-times"></a>

## 二、三种时间

每条事实对每个观察者有三个时间：

```text
event_time       事实在世界上发生的时刻
known_time       某个观察者可知该事实的时刻
presented_time   某个表现层呈现该事实的时刻
```

### 恒等关系

```text
known_time     = event_time + delay(visibility, principal, context)
presented_time = known_time + presentation_lag
```

三者都必须单调：

```text
event_time ≤ known_time ≤ presented_time
```

违反单调 → 该投影请求被拒绝，不静默修正。

### 三者不可互替

| 混淆 | 后果 |
|---|---|
| 用 `event_time` 当 `known_time` | 角色全知 |
| 用 `known_time` 当 `event_time` | 迟到的事实被当作当时发生，因果错乱 |
| 用 `presented_time` 当 `known_time` | 表现层缺失导致角色失忆 |

第三条是最隐蔽的：如果表现层被裁掉（远场转近场），角色不能因此失去本该记得的事。

<a id="derivation"></a>

## 三、投影的定义

投影是**给定主体与时刻，从世界真相账推导出的只读视图**。

```text
projection = f(principal, scope, as_of_tick, fact_types)
```

四个参数缺一不可：

| 参数 | 作用 |
|---|---|
| `principal` | 决定可见性过滤 |
| `scope` | 决定读哪些实体/区域 |
| `as_of_tick` | 决定读到哪个时刻为止 |
| `fact_types` | 决定读哪些事实 |

**没有默认值。** 不传 `principal` 的投影请求拒绝（这是 [可见性强制](02-可见性强制.md) 的强制点）。

<a id="incremental"></a>

## 四、投影的增量更新

### 问题

现有实现的形态是每条命令都全量重建：

```python
projection = self._projector.rebuild(self._store.read_events())
```

`read_events()` 无参数时从全局序号 1 开始并深拷贝全部事件。成本 O(事件总数)/命令。

### 规格要求

投影必须支持**按游标增量推进**，不得要求每次全量重建：

```text
projection_state:
  cursor_global_sequence   已消费到的全局序号
  fact_state               map<fact_type_id, 原语状态>
  revision_vector          map<stream_id, stream_revision>
```

推进一步：

```text
1. 读 (cursor, cut] 区间的事件
2. 校验区间连续（无空洞）
3. 按 resolution_order 逐条应用
4. 更新 cursor 与 revision_vector
5. 原子替换状态；失败不安装半成品
```

### 硬约束

| 约束 | 理由 |
|---|---|
| 区间必须连续 | 有空洞说明漏读，投影不可信 |
| 失败不安装半成品 | 半成品投影会产出错误决策 |
| cursor 只增不减 | 回退需要显式重建，不是静默倒退 |
| 状态必须可丢弃重建 | 投影是推导物，不是事实 |

### checkpoint

允许持久化投影快照以加速恢复：

```text
checkpoint:
  checkpoint_id
  projector_ref
  scope
  cursor_global_sequence
  state_digest
  created_at_tick
```

**checkpoint 不是事实。** 删除后必须能从事件流完全重建。任何"重建后结果不同"都是缺陷。

<a id="per-principal"></a>

## 五、按主体的投影

不同主体读同一批事实，得到不同结果。

```text
read_as(principal, scope, as_of_tick, fact_types) -> ScopedProjection
```

### 过滤顺序

```
1. 事实类型过滤   只读请求的 fact_types
2. 可见性过滤     class 与 learnable_by
3. 时间过滤       known_time ≤ as_of_tick
4. 失真应用       distortion model
5. 字段裁剪       按 principal 可见字段集
```

顺序不可调换：先时间过滤再可见性过滤会让"不可见但已过期"的事实穿透。

### 投影结果字段

每条投影事实至少携带：

```text
fact_type_ref
value                     按原语结构
source_owner_ref
source_revision
event_time
known_time                按该 principal 计算
freshness                 as_of_tick - known_time
confidence                full | degraded | inferred
```

`freshness` 与 `confidence` 是本文件相对 v1 的新增要求。

**理由**：这个游戏的核心是「守将依据三天前的军情做决定，可能判断错」。若投影不表达"这条信息有多旧"，角色和玩家都无法做有意义的判断。

<a id="memory-ledger"></a>

## 六、角色记忆账

### 不是事件库

角色记忆账是 `agent_private`，不是世界真相的子集副本。它记录：

```text
belief:     我认为 X 是什么      可与事实不同
source:     我从哪知道的        渠道、来源、时刻
confidence: 我有多确信          full | partial | hearsay
```

### 写入路径

```
世界事件提交
  → 可见性过滤（该角色的 learnable_by 与 channel）
  → known_time 到达
  → 记忆写入（Agent 私有）
```

**Agent 不得直接读世界真相账。** 它只能消费投影。

### 与士气、恐惧的关系

| 概念 | 归属 | 说明 |
|---|---|---|
| 士气 | 世界真相（Morale Owner） | 客观的部队状态 |
| 恐惧 | 角色记忆账 | 该角色的主观感受 |
| 队伍报告 | 世界真相（Information） | 谁向谁报告了什么 |
| 我相信队伍士气低 | 角色记忆账 | 基于报告形成的判断 |

四者不可互相替代。这是 [角色档案、状态与心智](../04-Owner/03-角色档案、状态与心智.md) 的投影侧对应。

<a id="presentation-ledger"></a>

## 七、表现账

### 可丢弃

表现账的任何内容丢失后，都必须能从投影重建。若某内容不可重建，说明它被错误地当成了事实。

### 与投影的区别

| | 投影 | 表现 |
|---|---|---|
| 生命周期 | 按 tick 推导 | 帧级插值 |
| 权威性 | 只读，可被引用 | 纯视觉，不可被引用 |
| 暂停时 | 冻结 | 冻结（尾动画除外） |

### presentation_tail

暂停或降级时，允许播放已确认动作的尾段动画，但必须标记：

```text
presentation_tail: true
```

尾动画**不得产生新的语义行动或世界写入**。

<a id="rebuild"></a>

## 八、重建与一致性

### 三种重建

| 场景 | 输入 | 期望 |
|---|---|---|
| 投影重建 | 全部事件 | 与 checkpoint 快照一致 |
| 记忆重建 | 该角色曾可见的事件 | 与当时信念一致（含失真） |
| 表现重建 | 当前投影 | 视觉正确，允许差异 |

### 一致性判据

| 项 | 判据 |
|---|---|
| 投影 | `state_digest` 逐字节相同 |
| 记忆 | 信念集合与来源完全相同 |
| 表现 | 无判据（不作为验收依据） |

**表现层不接受逐字节一致性要求。** 插值、LOD、帧率都会造成差异，那是设计允许的。

<a id="acceptance"></a>

## 九、验收

| # | 用例 | 期望 |
|---|---|---|
| L1 | 同一事件，两个 principal 读 | `known_time` 不同，或一方不可见 |
| L2 | 投影请求缺 `principal` | 拒绝 |
| L3 | 增量推进遇到事件空洞 | 拒绝推进，不安装半成品 |
| L4 | 删除 checkpoint 后重建 | `state_digest` 相同 |
| L5 | 投影字段缺 `freshness` | 拒绝该投影 |
| L6 | 角色依据过期信息做决定 | 允许，且决策可追溯到 `known_time` |
| L7 | 表现层丢失后重建 | 从投影恢复，不丢事实 |
| L8 | 暂停期间有网络消息到达 | 不进投影，不触发玩法 |
| L9 | 同一 tick 两次投影 | 结果完全相同 |

<a id="what-is-saved"></a>

## 一、什么是「存档」

存档**不是**世界状态的快照，而是**恢复所需的全部输入**。

```text
存档 = 事件流 + 提交基础设施状态 + 版本固定信息
```

世界状态是**推导出来的**，不是存下来的。

### 这个区分为什么重要

| 若存档存状态 | 后果 |
|---|---|
| 状态与事件不一致 | 无法判断哪个是真的 |
| 状态漏存某个字段 | 静默丢失，难以发现 |
| 改了公式 | 旧存档的数值不再符合新公式 |

推导演进的模式：事件是唯一的真值来源。

<a id="recovery-unit"></a>

## 二、恢复单元

一次完整恢复必须包含下列全部内容。缺任何一项都不算「存档完整」。

### 2.1 事件与提交

```text
事件流全集
每个 stream 的 stream_revision
全局序号到事件的映射
事务批次与事件的关系
```

### 2.2 幂等与回执

```text
幂等记录：principal_ref + idempotency_key → payload_digest
原 receipt：每个已提交命令的完整回执
```

**这一项最容易漏。** 缺了它，重启后的重复命令会被当成新命令执行。

### 2.3 outbox

```text
未投递的 outbox 条目
投递游标
重试计数与最后错误
```

### 2.4 投影与游标

```text
投影 checkpoint（可丢弃，用于加速）
confirmed cursor
角色记忆游标
```

### 2.5 未决状态

```text
未决命令（已受理未完成）
开放义务
定时器与世界窗口的 due 点
```

### 2.6 权限与租约

```text
authority_epoch（每个 scope）
lease 与 TTL
control epoch
```

### 2.7 版本固定

```text
规则包解析路径（完整，不是 pack_id）
模型 / Binding / Static Data 版本
schema 版本
固定输入与随机 seed
稳定排序依据
```

**2.7 是「回放用旧版本」这条不变式的物理依据。**

<a id="not-saved"></a>

## 三、不存的东西

| 不存 | 理由 |
|---|---|
| Actor 字段 | 表现可重建 |
| 屏幕现状 | 事实不能靠画面反推 |
| 动画状态 | 表现 |
| UI 状态 | 投影 |
| 任何可由事件推导的领域状态 | 推导物 |

**判据**：删除后能否从事件流 + 版本信息完全重建？能，就不存。

<a id="replay"></a>

## 四、回放

### 三种回放

| 类型 | 输入 | 输出 |
|---|---|---|
| **状态回放** | 事件流 | 领域状态 |
| **投影回放** | 事件流 + principal | 受限视图 |
| **记忆回放** | 事件流 + 角色可知性 | 角色信念 |

三者分开验证，不可互相替代。

### 回放的硬约束

| 约束 | 说明 |
|---|---|
| 用事件携带的版本 | 不用当前版本 |
| 不重新执行判定 | 不再跑命中检测、随机伤害、物资消耗 |
| 按 `resolution_order` 应用 | 不按存储顺序 |
| 不产生新事件 | 回放是只读的 |

**第二条是关键**：回放应用已提交的事件，不是重新模拟。若回放时重新掷骰子，就不可能得到相同结果。

### 回放与迁移事件

规则包或模型升级时：

```
旧事件段  → 用旧版本解释
迁移事件  → 显式记录版本切换
新事件段  → 用新版本解释
```

**不允许**用新版本重新解释旧事件段。那会改写历史。

<a id="checkpoint"></a>

## 五、checkpoint

### 定位

checkpoint 是**性能优化**，不是事实。

| 是 | 不是 |
|---|---|
| 可删除 | 权威 |
| 可重建 | 存档的必要部分 |
| 加速恢复 | 验收依据 |

### 内容

```text
checkpoint_id
projector_ref
scope
cursor_global_sequence
state_digest          用于校验重建一致性
created_at_tick
pack_resolution_path  用于判断是否仍适用
```

### 校验

删除全部 checkpoint 后重建，`state_digest` 必须与删除前相同。

不同 → 说明投影重建有缺陷，不是 checkpoint 坏了。

<a id="unknown-results"></a>

## 六、未知提交结果

### 三种情形

| 情形 | 判定 | 处置 |
|---|---|---|
| 未提交 | 幂等键查无记录 | 可以重试 |
| 已提交未收到 receipt | 幂等键查有记录 | 返回原 receipt，不重算 |
| 查询本身失败 | 无法判定 | **保留开放义务，禁止重发** |

**第三种最危险。** 查询失败不等于未提交。

### 硬约束

| 约束 | 违反后果 |
|---|---|
| 未知结果不得盲目重发 | 重复扣血 / 重复消耗 |
| 未知结果不得当作失败 | 丢失已提交的事实 |
| 未知结果必须进入恢复流程 | 静默丢失 |

<a id="crash"></a>

## 七、崩溃恢复

### 崩溃点分类

| 崩溃发生在 | 期望行为 |
|---|---|
| 事件写入前 | 无副作用，可重试 |
| 写入后、receipt 前 | 重启后能查到原 receipt |
| receipt 后、outbox 前 | 重启后 outbox 补发 |
| outbox 后、投影前 | 重启后投影增量推进 |
| 投影后 | 正常 |

### 必须保证的不变量

```
1. 已确认的事实不丢
2. 重复请求返回原 receipt
3. 不重复扣血 / 消耗 / 产出
4. 不静默丢弃未决状态
```

### 不允许的做法

| 做法 | 为什么不行 |
|---|---|
| 内存状态 + 定期异步上传 | 上传前崩溃即丢失 |
| 只存最终状态，不存事件 | 无法回放，无法对账 |
| 崩溃后「重新开始」 | 丢失已发生的后果 |

<a id="pause-vs-save"></a>

## 八、暂停、保存、断线是三件事

| | 时间 | 会话 | 状态 |
|---|---|---|---|
| 暂停 | 停止 | 继续 | 内存 |
| 保存 | 可能继续 | 继续 | 落盘 |
| 断线 | 可能继续 | 断开 | 可能有分歧 |

**三者不能互相替代。**

- 用保存代替暂停 → 世界还在走
- 用暂停代替保存 → 崩溃后全丢
- 用断线恢复代替保存 → 丢失本地未提交的预测

<a id="pause-recovery"></a>

## 九、暂停与恢复

### 暂停时

| 项 | 行为 |
|---|---|
| 世界推进 | 停止 |
| 效果 tick | 停止 |
| Timer / 回调 | 隔离，不触发玩法 |
| 网络返回 | 入站缓存，不触发 |
| 记忆写入 | 停止 |

### 恢复时校验

```
1. authority_epoch 未变
2. 读集 revision 仍有效
3. 证据未过期
```

任一不成立 → 进入恢复流程，不是直接继续。

### 暂停期间到达的消息

**不得**因为暂停结束就当作「刚刚发生」。它们的 `event_time` 是它们实际发生的时间，`known_time` 按可见性计算，与暂停无关。

## 十、必须覆盖的故障序列

以下每一项都必须有固定 fixture。

### 提交边界

| # | 故障 | 期望 |
|---|---|---|
| F1 | 事件写入后崩溃 | 重启查到原 receipt，事实不丢 |
| F2 | 重复提交同一命令 | 返回原 receipt，事件数不变 |
| F3 | 旧 revision 提交 | CAS 拒绝 |
| F4 | 旧 epoch 提交 | fencing 拒绝 |

### 投影

| # | 故障 | 期望 |
|---|---|---|
| F5 | 删除投影后重建 | 与 checkpoint 的 digest 相同 |
| F6 | 投影推进遇事件空洞 | 拒绝推进，不安装半成品 |
| F7 | 投影重建跨版本 | 用旧版本解释旧事件段 |

### 并发

| # | 故障 | 期望 |
|---|---|---|
| F8 | 伤害 + 治疗并发 | 按 resolution_order 结算，不超支 |
| F9 | 效果 tick 重复 | 幂等键 `effect_id + tick` 去重 |
| F10 | 治疗步骤重复 | 幂等键 `treatment_id + step` 去重 |
| F11 | 已死亡目标接受治疗 | 拒绝，不复活 |

### 交接

| # | 故障 | 期望 |
|---|---|---|
| F12 | 交接中途崩溃 | 旧 epoch 写入被拒 |
| F13 | 未知结果带过交接 | 新推进者从恢复状态开始 |
| F14 | 迟到命令 | 拒绝 |

### 存档

| # | 故障 | 期望 |
|---|---|---|
| F15 | 存档重载 | 状态与事件流一致 |
| F16 | 跨阶段 fixture 继承 | 不重写下层事实 |
| F17 | 规则包升级后加载旧存档 | 旧段用旧版本 |

<a id="acceptance"></a>

## 十一、验收

| # | 用例 | 期望 |
|---|---|---|
| S1 | 完整存档 → 重启 → 回放 | 状态逐字节相同 |
| S2 | 删除所有 checkpoint 重建 | digest 与删除前相同 |
| S3 | 存档中删除幂等记录 | 该存档判定为不完整，拒绝加载 |
| S4 | 回放时重新掷骰 | 不可能——回放不执行判定 |
| S5 | 规则包升级后回放旧段 | 结果与当时一致 |
| S6 | 暂停期间消息到达 | 不进投影，不触发玩法 |
| S7 | 三种回放分别验证 | 状态 / 投影 / 记忆各自一致 |

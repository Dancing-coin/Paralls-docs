<a id="design"></a>

## 二、可见性模型

### FactType 必须声明

每个 FactType 的 `visibility` 无默认值，缺失即注册失败：

```text
visibility:
  class:          public | faction | private | secret | debug_only
  learnable_by:   [principal_selector ...]     # 谁可以最终知道
  channel:        direct | report | rumor | inference | none
  delay:          { model_ref, params }        # 从 event_time 到 known_time
  distortion:     { model_ref, params }        # 可选：传播中的失真
  persistence:    permanent | until_expiry | memory_only
```

### 五个类

| class | 含义 | 例 |
|---|---|---|
| `public` | 辖区内公开可见 | 城门被攻破 |
| `faction` | 特定势力可见 | 本方伤亡统计 |
| `private` | 单个主体可见 | 某角色的疼痛 |
| `secret` | 仅持有者可见，需主动泄露 | 密信内容 |
| `debug_only` | 永不进入玩法读取路径 | 调试真相视图 |

`debug_only` 是硬隔离：任何非调试 principal 读取都返回空，**不是过滤后为空，而是拒绝**。

### 三种时间由可见性推导

```text
event_time   事实发生
known_time   = event_time + delay(params, distance, channel, ...)
presented_time = known_time + 表现层延迟
```

`known_time` 不是存储字段，是**按 principal 计算的投影**。同一条事件对不同 principal 有不同 `known_time`。

<a id="enforcement"></a>

## 三、强制点

### 唯一合法的读取入口

```
read_stream(...)                        ← 无 principal 参数，禁止玩法层调用
read_as(principal, scope, ...)          ← 唯一玩法读取入口
```

`read_as` 必须：

1. 解析 principal 的可见性资格；
2. 过滤 `class` 不允许的事件；
3. 计算每条事件的 `known_time`，丢弃 `known_time > now` 的；
4. 应用 `distortion`；
5. 返回带 `source_owner + source_revision + event_time + known_time + freshness` 的投影。

### 拒绝而非裁剪

对 `secret` / `debug_only`，行为是**拒绝访问**，不是返回空集后让调用方误以为"什么都没发生"。

调用方必须能区分：

```text
"没有这条事实"      ≠ "这条事实存在但你看不到"
```

后者在玩法中应表现为角色不知道，而不是世界没有。

### 投影是唯一出口

任何 L5 玩法组合、Agent、UI 都只能消费 `read_as` 的结果。直接读 EventStore 视为架构违规。

<a id="propagation"></a>

## 四、传播与失真

这是本设计相对 v1 的主要补全。v1 只说过"不能让传播后果瞬时全城知晓"，从未定义如何展开。

### 渠道

| channel | 语义 | 默认延迟源 |
|---|---|---|
| `direct` | 亲眼所见 | 0 |
| `report` | 经正式报告链（信使、传令） | 距离 / 传递过程 / 是否被截 |
| `rumor` | 非正式传播 | 社会网络 / 时间 |
| `inference` | 由其它已知事实推出 | 推理模型 |
| `none` | 不可知 | ∞ |

### 延迟模型

`delay` 是一个 L4 Resolver 引用。它读固定输入（距离、渠道、天气、是否封锁）返回 `known_time` 偏移。

参数由规则包提供。缺输入时返回 `unknown`，此时该事实对请求者**视为不可知**，不能默认 0 延迟。

### 失真

`distortion` 可选，是 L4 Resolver 引用，可返回：

```text
同一条事实的不同表述：数值偏差、来源错误、时间偏差、内容缺失
```

**关键设计**：失真后的表述仍然是一条事实，携带 `distortion_ref` 与原始 `source_event_id`。角色据此做判断，可能做错。**这是玩法，不是 bug。**

### 泄露

`secret` 类事实只能通过显式命令变为可知：

```text
leak / betray / intercept / interrogate
```

每条泄露产生一条新事实（`information_leaked`），不修改原事实的 `visibility`。历史不可变。

<a id="report-vs-fact"></a>

## 五、报告不是事实

必须区分：

```
事实        敌人有三千人              ← event
报告        信使报称敌人约三千人        ← event（内容是"某人这么说了"）
认知        我认为敌人有三千人         ← agent_private，不是世界真相
```

- 报告本身是事实（谁、何时、向谁、说了什么）。
- 报告内容可以是假的。
- 角色接收报告后形成的信念属于 `agent_private`，不写入世界账。

这条约束在 v1 已正确，v2 只补上投影层的强制点。

<a id="four-questions"></a>

## 六、必须能回答的四个问题

可见性强制上线后，系统对任意一条事实必须能回答：

1. **谁知道？** —— 给定 principal，返回知道 / 不知道 / 知道但过期
2. **怎么知道的？** —— 渠道与来源链
3. **什么时候知道的？** —— `known_time`
4. **他以为是什么？** —— 是否有失真，失真内容是什么

第四个问题在 v1 完全缺失，而它是"县城守城"这个玩法的核心：守将依据三天前的军情做决定，可能判断错。

<a id="acceptance"></a>

## 七、验收

| # | 用例 | 期望 |
|---|---|---|
| V1 | 无 principal 调用 `read_stream` | 玩法层禁止；调试层需显式提权 |
| V2 | 同一事件，两个不同 principal 读 | `known_time` 不同，或一方不可见 |
| V3 | `secret` 事实被非持有者读 | 拒绝，非空集 |
| V4 | `debug_only` 事实进入 UI 投影 | 拒绝 |
| V5 | 报告延迟未到 | 角色投影中不存在该事实 |
| V6 | 报告已到但内容失真 | 投影显示失真内容 + `source_event_id` |
| V7 | 泄露一条 secret | 原事实不变，新增 `information_leaked` 事件 |
| V8 | 暂停期间有网络消息到达 | 不进入投影，不触发玩法 |

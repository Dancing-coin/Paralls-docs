<a id="command-lifecycle"></a>
## 1. 从意图到获知结果

本流程串联[具身位置](../02-玩法模块/具身操作、骑乘与视角.md#embodied-movement)、[授权与预案](../02-玩法模块/军制、指挥与自主行动.md#military-organization)、[媒介与信息](../02-玩法模块/社交、关系与情报.md#media-interface)及实际执行模块，不新增领域或写入者。

| 步骤 | 条件与行动 | 成本、结果与反馈 |
|---|---|---|
| 1. 形成意图/草稿 | 依据合法可知信息，选择授权对象、语义目标、条件和保持/切换预案 | 提案或草稿即时确认，不代表已送达；暂停可编辑但不推进世界 |
| 2. 校验并发出 | 校验来源、身份/权限、目标、有效期及冲突；正式字段由技术合同维护 | 无权拒绝入队列，说明缺少的权限来源，不改变战场事实 |
| 3. 选择媒介并中继 | UI 形成现实可达意图，或语音、书信、手势、口令、旗语、亲卫/传令人员经组织层级转发 | 消耗时间、通信机会、信用和可能资源；显示来源、当前/下一节点、路径、可达性、时效 |
| 4. 抵达、验证与理解 | 通过约定凭据、应和或复核，接收者理解内容 | 区分已抵达、已理解与已接受；失真、误解、截获、无法抵达不能伪装成功 |
| 5. 接受、拒绝或等待 | 接收者依权限、预案、能力、训练、士气、补给、恐惧、疲劳、家庭责任和现场判断响应 | 可拒绝、拖延、部分执行或在授权内改写；明确原因和责任，而非强制服从 |
| 6. 实际执行 | 执行者在当前资源、位置和条件中行动；具体行动引用相关模块 | 显示执行中及中断、损失、部分结果；动画和命令接受不等于完成 |
| 7. 结果确认与回报 | 执行事实经领域承认后生成回执/战报，沿有效观察和通信进入玩家认知 | 分开“事实已经发生”和“玩家已经获知”，带来源、发生/获知时间、可信度及后果 |

<a id="command-states"></a>
## 2. 状态与改令

策划状态完整保留为：草拟、已发出、传递中、已抵达、已理解、已接受、执行中、完成、拒绝、过期、取消。它们解释不同阶段，不在本页另建技术枚举；“已下达”“已送达（验证结果）”“已接收”等旧表述须映射到[公共 Command/Event/Receipt](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)并保留理解与接受的差别。

命令链面板允许发送、取消、改令、检查路径和原因；具体输入/快捷键待定。取消与改令也受权限、通信、有效期和已发生事实约束，关闭界面不取消已发出的命令，不能撤回已经消耗或造成的结果。

<a id="command-exceptions"></a>
## 3. 异常、验证制度与回退

| 异常 | 必须产生的结果 |
|---|---|
| 无权限或资格变化 | 拒绝或重新校验，保留来源/范围，不新增第二份授权 |
| 阻挡、失联、截获、误解、失真 | 等待、改路、复核、失败或其他合法结果；具体计算待定，不能凭空到达 |
| 超过有效期、目标改变或失效 | 标记过期/失效，解释时间与原因；队伍回到有效预案或替代策略 |
| revision 冲突、重复、过时请求 | 按[网关与失败恢复](../../architecture/02-公共契约/02-Command事件与Receipt.md#failure-recovery)处理，不提前显示完成 |
| 凭据或多源异常 | 依[验证制度](../02-玩法模块/军制、指挥与自主行动.md#authentication)暂缓、复核、接受风险或追溯；破译和伪造有资源与预警证据 |
| Bridge 中断 | 在有效本地领域权威、意图/执行许可及最近有效预案内继续；无权的动作保持待处理或安全中断，记录接管原因 |
| 暂停后恢复或重新联通 | 按[时间与控制权](../../architecture/02-公共契约/01-时间身份与控制权.md#authority-epoch)及[断线恢复](../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#disconnect-recovery)重验，不能刷出未知信息或重复执行 |

<a id="succession-flow"></a>
## 4. 指挥权轮替

1. 在拥有指挥头目及至少一条继任链的组织中，检测失能、死亡、离场或通信条件变化；具体触发边界由授权/剧本规则确认。
2. 按有效顺序逐一校验候选资格、身体、权限与现场条件；候选失能则继续校验下一人。
3. 对有效候选幂等交接允许保留的权限与预案，不重复发放，不默默扩大授权。
4. 队伍继续执行或重规划；无合格继任时进入自治降级，不能停摆或无条件获胜。
5. 经合法报告说明继任者、资格来源、交接时间、保留/丢失权限和行为变化；执行质量、信任或授权可能下降。

可见状态为正常指挥、失能待交接、继任中、已接管、无合格继任、自治降级。重复事件、版本冲突与候选失能需可回放；控制权与执行许可引用[时间身份与控制权](../../architecture/02-公共契约/01-时间身份与控制权.md#authority-epoch)及[军事领域](../../architecture/03-Owner领域/02-领域Owner详细契约.md#military-domain)。即时指挥接管不等于[长期政治/角色传承](../02-玩法模块/角色生存、成长与传承.md#failure-inheritance)。

<a id="command-validation"></a>
## 5. 观察与待定

正常传令须能追到节点和队伍结果；无权不改事实；过期有后续自治；离场和 Bridge 关闭后仍可解释地运行；重复失能不重复交接。命令应确实改变协调机会而非纯等待，职责/命令差异可辨。

完整路径、覆盖、延迟/失真计算、媒介输入识别、语言/识字要求、命令优先级与抢占、过期时长、取消生效点、继任资格、无合格候选后续和反馈频率待定。县城场景的求援、守备、城门、巡墙、军需、修缮、生产、护送、出城与失败指令由阶段配置维护；不恢复 `10/22/34` 独立验收。

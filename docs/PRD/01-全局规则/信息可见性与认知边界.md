# 信息可见性与认知边界

> 文档版本：v1.0（专题重组版）  
> 更新日期：2026-10-30  
> 评审状态：事实/认知/表现分离及合法信息规则沿用；未定 UI 和阈值保持待决  
> 实现状态：信息体验设计，不是已完成 UI、查询或运行验证声明

<a id="three-ledger-semantics"></a>
## 1. 真相、角色认知与呈现不是同一件事

| 层次 | 玩家语义 | 不可冒充 |
|---|---|---|
| 世界真相 | 相应领域已承认的资源、伤势、库存、产权、组织、战斗和生命事实 | 角色猜测、脚本推演、视觉刷新或未经承认的模型输出 |
| 角色记忆 | 某角色所见、收到、推断、相信、计划和记住的内容；可以错误、有偏差或过时 | 全局真相镜像；别的角色知道不代表玩家知道 |
| 世界表现 | 当前加载、显示、播放和可交互的局部投影 | 权威事实写入；有表现不代表领域结果成立，未加载也不代表世界不存在 |

三本账及其技术关系只在[三本账与 WRK](../../architecture/01-系统边界/03-三本账与WRK.md#three-ledgers)维护；本文解释玩家可知边界，不复制字段、版本或交接协议。

例如，角色说“粮仓充足”可以是错误、欺骗或旧认知；这句话的发出和送达可以真实发生，却不能直接把库存变为充足。实际交易、伤害、控制、库存和生命变化仍由相应领域判定。

<a id="three-times"></a>
## 2. 发生、获知与看到的三个时间

- `event_time`：事情在世界中实际发生的时间。
- `known_time`：特定角色经合法渠道获知的时间。
- `presented_time`：信息在玩家界面或 UE 表现中被显示/播放的时间。

远方事件可能先发生，经传令后才被获知，再在适当时刻呈现。迟到报告不能被包装为即时真相；稍后显示不改变其发生时间。精确时间与可见性元数据见[时间契约](../../architecture/02-公共契约/01-时间身份与控制权.md#time-identity-control)和[受限查询与投影](../../architecture/02-公共契约/03-受限查询与投影.md#restricted-projections)。

<a id="legitimate-knowledge"></a>
## 3. 合法渠道、最后已知与未知

玩家只能使用本人感知、观察、斥候、传令、书信、口信、可用媒介与组织汇报实际抵达的信息。职位高、地图打开、切换镜头、工作层激活或司命提出机会都不能自动暴露未到达真相。

情报应可辨认来源、获知时间、可信度、陈旧/过期程度和覆盖范围。离开或失联后保留最后已知状态，并随时间增加不确定性，不把远方状态实时刷新。事实、推断和未知分别标记；推断可以帮助计划，但不能伪装为已确认事实。不同角色可能因观察和利益形成不同判断。

侦察、审问、窃取、商旅消息与细作属于获得信息的行动方式，不自动提高到全知。谣言、伪报、截获或被操纵的报告可改变认知和决策，不能反向改写原事实；具体玩法见[社交、关系与情报](../02-玩法模块/社交、关系与情报.md#information-knowledge)。

主动暂停冻结新信息暴露和通信推进，只能使用暂停前已合法获得的内容；不能在暂停中刷新斥候、完成查询揭密或扩大视野。暂停与恢复见[完整暂停规则](连续世界、时间与暂停.md#active-pause)。

<a id="command-feedback"></a>
## 4. 命令过程必须可辨

玩家应能区分意图提出、信息/命令传达中、对象理解、对象接受或拒绝、执行中、结果已发生和结果已获知。最基本的可见差异包括待传递、已送达、已接收、执行中、拒绝、过期及其原因。“已下达”不能冒充“已执行”；即时确认收到输入，不表示远方即时完成。

命令过程显示发令者、合法对象、传达/中继路径、当前可达性、有效性与已获知的执行结果。不可达、失真、拒绝、过期、资源不足、目标变化和权限失效应给具体原因。排队草稿、沙盘推演和会议计划不提前标成事实。结果即使已发生，玩家也只能在报告实际抵达后获知。

精确事件名称、状态机和 Receipt 只在[Command、事件与 Receipt](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)维护；可见语义与技术状态的映射不得另建冲突状态机。流程见[命令传递、执行与指挥权轮替](../03-跨模块流程/命令传递、执行与指挥权轮替.md#command-lifecycle)。

<a id="readable-feedback"></a>
## 5. 决策信息与稳定反馈

关键决策前提示合法可知的成本、主要风险和结果类别；决策后给可解释的直接反馈与持续后果。冲锋路线危险、队伍无法接令、军旗受威胁、运输延误等关键风险应在前后有可辨线索。允许误判、未知和损失，但核心失败须留下可学习的因果证据，不能事后凭空补真相。

战斗反馈至少区分接触方向、命中/被阻、阵型、士气区间、目标控制与指挥者状态。重要信息使用稳定的视觉、声音、图标/形状或文本编码，不能只靠颜色。关键接触优先于装饰；镜头震动、暂停帧、音效强度可控，不遮挡后续威胁、军旗、阵型和命令结果。具体动作反馈见[战斗模块](../02-玩法模块/战斗、装备与伤害反馈.md#combat-feedback)。

信息量不能代替决策深度。默认显示少量关键资源、风险和异常，细节可展开到库存、现金、运输、报价、储备和组织账。系统不以文书操作量作为难度，机械验证尽量自动完成，异常与关键取舍才要求玩家介入；自动验证不等于自动授予权限或自动成功。

<a id="interface-categories"></a>
## 6. 界面层级、清单与远方通知

| 界面 | 组织的信息与行动 | 必须保留的边界 |
|---|---|---|
| 世界/统治 | 领地、资源网络、组织权限、市场、历史压力点 | 只显示合法已知与注明的不确定性；不直接全图读真相 |
| 行军/通信 | 行军实体、传令路径、命令状态、情报可信度与陈旧程度 | 可达、到达、获知与执行分开 |
| 战场指挥 | 阵型、士气、军旗、目标、预案、可达性与继任链 | 表现与领域事实对应；未获知目标变化不能立即全知 |
| 角色 | 身份、权限来源、能力、关系、记忆、伤势与候选行动 | 候选行动与正式事实、本人记忆与世界真相分开 |

远方通知说明“谁在何时，通过什么来源，以何种可信度告诉玩家什么”。仅本人已观察或合法收到的事件进入通知；不是瞬时全球地图广播。在领地远程指挥仍需传信；在战场收到领地消息后可回信或赶回，不能切换空间实时处理所有问题。

叙事和对话优先使用稳定的组织、权限、命令、队伍、阵型、士气、目标、来源、时效、可信度与结算词汇。拒绝提示解释权限、距离、过期、资源或目标变化，而非只有通用“失败”。具体角色语气、文本长度、翻译、字幕和内容审核规范仍待定。

<a id="teaching-accessibility"></a>
## 7. 教学、难度与可访问性

各层先共享时间、来源、权限、通信和执行状态的基础认知，再逐步展开细节；首次体验顺序未定。治理教学关注资源流、职责、授权、政策与异常；战争/战役教学关注目标和任务、兵力补给、下令/追踪/改令；个人教学关注移动骑乘、观察交涉、战斗和风险。具体任务、难度曲线、摘要、预警和委派辅助待定。

原案的标准/硬核方向是设计候选：标准方向强调较短且可理解的传令、较宽视野、自动验证与明确破译预警；硬核方向强调信物、封泥、口令轮换、斥候可信度、视野更新、市场误判与细作风险。最终参数尚未确认，二者均不得违背合法信息、领域事实和完整暂停规则。历史倾向开关只改变历史压力强弱，不取消世界因果。

辅助方向包括：字幕开关、字幕大小/背景、语言与文本速度；键位重映射、鼠标灵敏度、镜头距离、视角偏好；难度模式、颜色辅助、音量与可控的反馈强度。重要状态以命令路径/节点/状态词/时效、队伍编号/旗色/形状/编队、士气与阵型的图标/文字/动作/声音/颜色、目标轮廓/归属组合表达，不依赖单一颜色。上述设置是待落实的设计方向，不声明已有设置菜单。慢速是独立扩展候选，不能代替单人完整暂停。具体 UI 版式、正式键位和模式参数统一进待决问题，不凭来源表格自行填数。

<a id="information-validation"></a>
## 8. 验证与来源

检查应覆盖：角色之间知识不同；远方事件发生/抵达/呈现不混同；错误报告不改库存等真相；打开地图不泄露未知；暂停不新增信息；命令提出、送达、接受、执行与结果可区别；失败有来源与因果；默认摘要可用且细节可展开。测试记录区分观察事实、原因推测和设计决定，附实际日志与 PIE 证据；本篇不声明已经验证。

来源为总策划第 2.2—2.4、4.2、11—12、18—19 节，玩法策划第 1、2、6、9—10 节，以及五阶段大纲的同世界、行动层和权限信息约束。技术术语由[架构入口](../../architecture/README.md#technical-reference)维护，内容玩法由社交/情报与司命/角色模块维护。

# 玩家身份、权限与操作入口

> 文档版本：v1.0（专题重组版）  
> 更新日期：2026-10-30  
> 评审状态：既有身份、四类授权与操作边界整理；未决交互不自行定稿  
> 实现状态：玩家规则设计；授权技术字段和验证结果另见架构与执行证据

<a id="derived-identity"></a>
## 1. 身份是推导状态

玩家身份由官职、领地、组织归属、上级关系、部曲登记、声望、名分、所在位置、军队编制和授权记录共同推导。统治、行军、指挥、战斗只是同一人物的关注与操作入口，不是互斥职业，也不会直接赋予权力。

一方诸侯可以亲征；在他人军中任职者保留个人武力，却不会因会打仗或抵达现场获得整军指挥权。切换层级、镜头、UI 或地图不改变身份与权限。个人、经营、战役和战争共享同一组织、资源与事实状态，已授权职责由人员、预案与继任继续。

完整游戏默认角色方向是有限身份与权限的原创代理人，政治晋升由任命、军功、承认、领地、组织和实际控制形成，而非固定职业等级。当前守城 Demo 是此规则的特定配置：玩家为县军政最高统治者；这不意味着无条件知道全部信息、远程瞬时执行或替所有领域宣布结果。

<a id="permission-sources"></a>
## 2. 四类权限来源

| 来源 | 成立依据与边界 |
|---|---|
| 职务权限 | 官职、军职、领地与正式任命授予的对象和范围 |
| 上级授权 | 明确的辖域、目标和期限，可撤回、可过期，不是永久移交全部权力 |
| 权限所有者委托 | 当前军队、部曲或组织实际控制者主动交付的特定权限，不能由 UI 假定已交付 |
| 部曲合法认可 | 指挥官失能、公开拥立或组织仪式形成的临时事实授权，须有可追溯事件 |

到场不等于有权。无权者可个人作战、保护直属人员或向有权者提议；默认不得改他人阵型、调他人部队、夺取他人直属部曲或发高级军令。临时任命、失能后的合法接替或公开拥立必须实际形成，不能把越权尝试先表现为成功。

权限可能依对象、领域、地域、时间与条件变化。界面应显示来源和当前限制，失效时解释原因。精确身份、版本、许可与请求校验由[时间、身份与控制权](../../architecture/02-公共契约/01-时间身份与控制权.md#time-identity-control)维护，本文不另立技术字段。

<a id="direct-retainers"></a>
## 3. 直属亲卫、编队与指挥权轮替

已登记为玩家直属亲卫或部曲的成员有稳定直接从属关系，除非忠诚崩溃或公开改投。编入统一军阵后，战场编队任务服从该编队指挥官；玩家仍保留个人行动和预登记紧急召回的相应权限。

紧急召回只在事先登记的触发条件满足时成立。条件不满足时是普通请求，不能借“我的亲卫”跳过军阵指挥链。指挥官失能、离场和交接时，按既有组织、合法授权与继任安排承接；更换玩家关注层不等于指挥链重置。

军制、预案的编辑/训练/版本、职责与自主行为见[军制、指挥与自主行动](../02-玩法模块/军制、指挥与自主行动.md)；命令交接和指挥权轮替见[跨模块命令流程](../03-跨模块流程/命令传递、执行与指挥权轮替.md#succession-flow)。角色死亡后的长期继承与当前 Demo 失败另见[角色生存、成长与传承](../02-玩法模块/角色生存、成长与传承.md#failure-inheritance)。

<a id="command-reachability"></a>
## 4. 可查看不等于可抵达

命令界面可以持续查看，但每支部队的状态至少分为：

| 可达性 | 玩家含义 |
|---|---|
| 可直达 | 当前条件下可直接传达，仍受权限、理解、接受与执行条件限制 |
| 可经中继 | 依传令、书信、口信、旗语、组织节点等现实路径抵达，伴随时延和风险 |
| 仅能依预案 | 当前无法有效改令，组织按既知目标、职责、有效预案与本地判断继续 |
| 失联 | 当前没有可靠联系，玩家只能保留最后已知状态，不能假装新令已执行 |

不可达命令可显示原因并允许排队，但排队不是生效。送达前可能过期、被截获、被替换，或因权限/目标变化失败。有效管理需要权限并处在势力范围或有效通信覆盖内；离开后可经可用媒介委托，不能把面板操作直写远方。

本人返回、取得合法授权或恢复通信可以改变可行动范围；仅切换镜头不能。详细状态与失败事件由[Command 契约](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)定义，玩家反馈见[信息边界](信息可见性与认知边界.md#command-feedback)。

<a id="operation-entrypoints"></a>
## 5. 操作入口与现实媒介

| 入口 | 能提出或整理什么 | 不得自动跨越什么 |
|---|---|---|
| 个人行动 | 移动/观察、骑乘冲锋、选择目标、交互、战斗、护卫、撤退 | 身体、位置、敌意、伤病、时间与个人风险 |
| UI 面板 | 查看合法信息，整理资源/关系，提出语义命令、授权、预案或请求，追踪执行 | 权限、势力范围、传达、对象理解/接受、资源与领域判定 |
| 语音、手势、口令、书信 | 在对应距离、媒介与组织条件下传达意图和报告 | 可听见/看见、身份识别、时效、失真、截获与拒绝 |
| 传令人员与组织节点 | 携带、转达、确认或回报 | 路径、承载者、训练、风险、可达性和回复延迟 |
| 府署、人物会议、沙盘、舆图 | 激活治理/推演工作层，联合计划与分配职责，利用已抵达战报 | 未知信息、未授予权力、尚未传达执行的计划与真实成本 |

每个操作应说明其改变的是角色位置/注意力、命令意图、组织授权还是已经承认的领域事实。点击、对话、草稿、会议讨论与模型候选都不是最终结果。正式键位、交互消耗、切换条件及全部 UI 布局尚待定，具身基线 WASD、鼠标朝向与视角方向由[具身操作模块](../02-玩法模块/具身操作、骑乘与视角.md#embodied-movement)维护。

<a id="permission-influence-fact"></a>
## 6. 权限、影响力、统治与事实分开

- 权限回答是否有资格对某对象、某领域提出请求。
- 通信回答请求或报告是否、何时、以何种形态抵达。
- 影响力、关系与利益影响对方愿否响应；有权不保证忠诚、理解或成功。
- 统治是特定辖域和领域持续执行、资源、组织与承认支持的状态，不是随身万能分。
- 领域事实由对应权威判定；接受命令、播放动作和宣布目标完成均不能替代结算。

影响力与统治的具体维度和生效/失效规则见[治理、政治与领土控制](../02-玩法模块/治理、政治与领土控制.md#influence-rule)。各宿主与领域的唯一写入权见[系统边界与权威写入](../../architecture/01-系统边界/01-系统边界与权威写入.md#system-boundaries)，只有[Owner 注册表](../../architecture/03-Owner领域/01-Owner注册表.md#owner-registry)维护完整名单。

<a id="identity-validation"></a>
## 7. 验证与来源

验证至少区分：有权且可达、有权但失联、可到场但无权、直接部曲编入军阵、紧急条件成立/不成立、代理授权到期、指挥者失能与合法继任。玩家应能复述权限来源、通信限制与拒绝原因。此处列设计检查，不声明系统已通过。

来源为总策划第 1、2.4、5、6 节，玩法策划第 1.2—1.6、2.1、2.3、2.5 节，以及五阶段大纲行动层和已确定的 Demo 身份。术语与未决项分别由[术语表](../00-产品总纲/术语表.md)和[设计决策与待决问题](../00-产品总纲/设计决策与待决问题.md)维护。

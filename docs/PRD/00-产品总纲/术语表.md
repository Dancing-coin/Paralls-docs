<a id="product-terms"></a>
## 1. 产品、体验与状态

| 术语 | 统一语义与边界 |
|---|---|
| 完整游戏 | 连续汉末世界中的个人行动、组织、战争、治理、资源、关系和历史后果的长线目标；不等于当前 Demo 内容清单 |
| 当前 Demo | 召陵县县城守城 Demo；玩家为县军政最高统治者，固定守城视角；正式门槛由当前执行路线维护 |
| 骑将冲阵 | 已取消独立开发/独立验收的历史切片；通用骑战与传令等机制继续服务当前 Demo。三队、10/22/34、3–8 分钟不转为当前硬要求 |
| 具身 / 个人 ARPG 底座 | 玩家作为有位置、身体、感知、记忆和关系的人持续存在；不是进入战斗后才存在的单位 |
| 工作层 | 经营统治、战役、战争等注意力和组织工具；可共存，不是互斥职业、独立世界或自动授权 |
| 战役 / 战争 | 战役聚焦具体地域、时间窗口、部队与阶段任务；战争聚焦持续冲突目标、战区、投入、同盟、谈判和收束 |
| 连续世界 | 共享身份、时间、存档和事实；加载、距离和关注层改变不重置未关注世界 |
| 主动暂停 | 单人完整世界时停，允许思考和编辑草稿；详见[暂停规则](../01-全局规则/连续世界、时间与暂停.md#active-pause) |
| 设计已描述 / 已覆盖 | 文档已表述某规则；不代表批准、实现或运行验证 |
| 已确定设计 | 有明确决策依据的规则；批准范围不自动扩展到所有候选 |
| 设计候选 / 待决 | 有来源的备选、建议数值或留白；需要评审、原型或用户决定 |
| 评审状态 | 文档或规则是否待用户评审、已确认或被取代，与实现状态分别记录 |
| 实现状态 | 未实现、部分实现或已实现等须由实际代码/资产与证据支持，不能从 PRD 推断 |
| 运行证据 | 指定版本和环境下的日志、资产/Actor 数量、PIE 状态、定向编辑器/PIE 截图或测试结果；设计意图不属于证据 |
| 现有底座 | 已有基础设施或通用能力的来源标签；不代表所需玩法领域、接入和运行验收都已完成 |
| 本案设计 | 本策划描述的产品规则与体验要求；实施状态须另有证据，不因设计定稿而自动成立 |
| 增量领域 | 在底座之外仍需建设、明确 Owner 或接入的业务领域；不得当作现成可调用能力 |
| 延期 | 当前阶段暂不交付的内容；保留长期设计边界，但不进入本阶段强制验收 |

<a id="authority-terms"></a>
## 2. 身份、权力与组织

| 术语 | 统一语义与规则入口 |
|---|---|
| 玩家身份 | 官职、领地、组织、授权、部曲、声望、承认与位置等共同推导的当前状态，非固定职业 |
| 权限 | 在对象、领域、地域、期限与条件内提出某行动的合法资格，不保证命令抵达、愿被接受或成功 |
| 影响力 | 对特定对象/群体在特定领域与时间内的响应倾向影响；不等于权限、事实统治或全局万能分 |
| 事实统治 / 统治力 | 辖域内有持续执行、资源、组织合作和承认支撑的控制能力；分领域/辖域/时间，不以单次声明成立 |
| 势力范围 | 实际可组织的对象与资源范围；与有效通信覆盖相关但不等同 |
| 通信覆盖 / 命令可达 | 信息或意图在条件与时效内能否抵达；可为直接、经中继、仅依预案或失联 |
| 授权 | 来自官职、上级委派、合法持有人委派或合法临时承认的限定许可；可撤销、到期或条件失效 |
| 直属亲卫 / 部曲 | 与玩家存在稳定直接从属关系的组织；编入统一阵型后，编队任务须遵守该指挥关系。紧急召回仅在预登记条件成立时生效 |
| 军制层级 | 军队的分层编制、职责、头目与指挥关系；组织单位与表现实体数不必一一对应 |
| 预案 | 可编辑、训练、版本化的条件、优先级与行动安排；不是无条件自动成功脚本，未训练/旧版本有相应限制 |
| 自主行动 | 人物或部队依职责、获准目标、预案、训练、士气、资源和本地信息继续；不等于自动接管一切写权 |
| 指挥权轮替 / 继任 | 指挥者失能或合法交接后按身份、组织和预先规则承接有限权力；与角色死亡后的完整游戏继承不同 |
| 权限 / 意愿 / 事实 | 能否提出、愿否响应、结果是否成立分别判断；见[身份规则](../01-全局规则/玩家身份、权限与操作入口.md#permission-influence-fact)及[治理模块](../02-玩法模块/治理、政治与领土控制.md#influence-rule) |

<a id="world-state-terms"></a>
## 3. 战场、资源与人口

| 术语 | 统一语义与边界 |
|---|---|
| 士气 | 队伍临场继续行动、维持阵型与承受威胁的状态；具体阈值是可调候选，非既定最终数值 |
| 军心 | 军事组织的合作、忠诚和长期服役意愿等；不等于临场士气 |
| 民心 | 人口对生活、治理、征发和统治的态度/支持；不与军心、士气合成一个混乱值 |
| 阵型 | 队伍的空间组织与受接触方向、间距、训练、士气及命令影响的状态，不只是视觉排队 |
| 关键目标 | 军旗、将领、器械、粮道、设施等可改变局部或战役结果的对象；可见效果不自动等于最终控制结算 |
| 所有权 / 保管 / 控制 | 法定或承认归属、物理持有/管理、实际可使用或阻止使用分别成立；资源和产权事实不能混用 |
| 占领 | 军事接触与控制、地方合作、资源和政治承认相互关联的过程；进入地点不自动完成完整统治 |
| 市场影响 | 通过报价、交易、库存、供需、运输、信誉与主体选择改变市场，非直接改写全球价格 |
| 账面库存 / 有效供应 | 登记数量与在时间、路线、预留、损耗、需求等条件下实际可用数量分别计算 |
| 资源网络 | 生产、源头、库存、运输、市场、分配、消费与后果的连续链；详见[资源模块](../02-玩法模块/资源、生产、经济与运输.md#resource-network) |
| 人口职业 / 军事角色转换 | 人物在训练、装备、工具、组织、身体和许可条件下转换岗位，保持身份、关系、伤病和已有后果 |
| 生存需求 / 身体 / 劳力 | 需求压力、身体状态与可用劳动/作战能力分层；短缺通过连续后果变化，不能单次缺货直接判死 |

<a id="knowledge-terms"></a>
## 4. 信息、命令与三本账

| 术语 | 玩家语义；技术权威入口 |
|---|---|
| 世界真相账 | 已被领域承认的世界事实；不意味着所有角色已知。见[三本账](../../architecture/01-系统边界/03-三本账与WRK.md#three-ledgers) |
| 角色记忆账 | 某个角色合法观察、听闻或推断后记住的内容，可过时、错误或有偏差；同上 |
| 世界表现账 | 角色认知和可见性条件下用于呈现的世界内容；不是另一个可写世界真相；同上 |
| WRK / 世界运行核心 | World Runtime Kernel，负责世界的唯一推进与运行协调；领域事实仍由各 Owner 判定和结算。精确定义见[WRK 契约](../../architecture/01-系统边界/03-三本账与WRK.md#wrk) |
| event_time | 事情实际发生的世界时间；精确字段由[时间契约](../../architecture/02-公共契约/01-时间身份与控制权.md#time-identity-control)维护 |
| known_time | 某角色何时合法获知；事件发生后不必立即已知；同上与三本账定义 |
| presented_time | 信息何时显示/播放给玩家；不反向改变发生或获知时间；同上 |
| 事实 / 推断 / 未知 | 已确认内容、依据已有信息推测、尚无合法依据分别标记；报告内容可是假话，报告被发出/抵达可以是事实 |
| 命令意图 / 草稿 | 玩家或角色想让谁做什么；尚未等于送达、接受、执行或结果 |
| 命令生命周期 | 提出、传达、理解、接受/拒绝、执行、结果发生、结果获知可分离；精确事件与状态见[Command 契约](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt) |
| 领域事实 / Receipt | 经相应权威判定成立的结果与其可追踪回执；界面动画或模型输出不能替代，精确结构见同一技术契约 |
| 受限查询 / 投影 | 依角色身份、时间、来源和可见性提供可知内容；见[受限查询与投影](../../architecture/02-公共契约/03-受限查询与投影.md#restricted-projections) |

| epoch / revision / lease / admission | 分别涉及时代/版本、修订、执行或控制许可、请求准入；策划不得绕过其失效与重校验结果 | [时间、身份与控制权](../../architecture/02-公共契约/01-时间身份与控制权.md#time-identity-control) |
| Event / 幂等 / 因果 / replay / checkpoint | 事实记录与可追踪、去重、恢复和重放能力；不表示现有底座已完成所有领域模拟 | [Command、事件与 Receipt](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)与[技术参考](../../architecture/README.md#technical-reference) |
| Bridge / ESM / 语义交接 | UE 与远端运行时同步、具身状态承接等技术边界；断线不自动扩大决策或事实写权 | [运行时接入](../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#ue-paralls) |

## 6. 维护与来源

本表提炼总策划、玩法策划与五阶段大纲中反复使用的产品词，并区分已确定语义、候选规则与实现证据。产品名冲突和未决阈值交[设计决策与待决问题](设计决策与待决问题.md)维护；军制、士气、身体、资源、治理的详细规则由对应玩法模块维护；技术字段与执行契约只在 architecture 中维护。

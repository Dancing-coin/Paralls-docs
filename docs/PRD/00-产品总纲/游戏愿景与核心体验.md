## 1. 产品定位与当前交付

本项目是一款以具身个人行动为底座、叠加经营统治与战争/战役指挥的实时持续世界战争政治 RPG。玩家始终是汉末世界中一个有身体、有位置、有记忆、有社会关系，且受权限与通信约束的人。经营、战役与战争是可以共存的工作层，不是三个互不相干的小游戏。

当前统一交付为**召陵县县城守城 Demo**。《骑将冲阵》已取消独立开发与独立验收目标；骑乘、冲锋、传令、阵型和士气等通用机制仍服务守城 Demo。历史切片中的一营三队、`10/22/34` 和单次 3–8 分钟只保留为历史示例，不构成当前 Demo 的强制配置或门槛。县城/角色来源另有三队配置，仍按[待决 D03](设计决策与待决问题.md#d03)核对，不因旧切片取消而抹去。正式范围、场景和完成条件由当前 Demo 与执行路线文档维护。

<a id="core-experience"></a>
## 2. 核心体验与四项承诺

> 玩家以一个有身体、有身份、受权限与通信约束的人身处乱世；通过亲自冒险、委派组织、调配资源和经营关系，在有限信息与有限时间中争取影响力。每次成功都能追溯到命令、人物响应和领域结算；失败留下可见代价，并改变之后可用的身份、关系与资源。

1. **亲自改变局部战局。** 骑乘、冲锋、视角和战场位置能改变接触与局部机会，但不能自动赢下整场战争。
2. **命令具有可观察的组织过程。** 玩家能知道谁发令、通过谁、是否抵达、谁理解或接受、为什么拒绝，以及部队实际做了什么。
3. **离场后安排仍然有效。** 预案、代理、训练、士气、补给与继任决定组织怎样继续；失控可以追因，玩家在权限与通信允许时重新介入。
4. **成功需要维持，失败留下历史。** 资源、名分、信任与控制需要维护；受伤、失势和死亡改变承接条件，已经发生的事实不因切换工作层而抹除。

玩家可移动、骑乘、观察、侦察、社交、交涉、宴饮、休整、发展亲密关系、履职、旅行、调查传闻和处理现实事务。战斗可以主动发起，也可以因敌意、伏击、追捕或攻击被动升级；它是个人生活的即时变化，不是脱离世界的竞技小游戏。亲密关系属于完整游戏生活方向，不等同于当前 Demo 内容承诺。

<a id="shared-work-layers"></a>
## 3. 个人底座与可共存工作层

| 体验层 | 激活条件与媒介 | 关注与反馈 |
|---|---|---|
| 个人 ARPG 底座 | 始终存在；由角色位置、感知、身体与关系约束 | 当前地点、人物、敌意、可交互对象、身体和已抵达信息；输入即时响应，伤势、关系与位置持续承接 |
| 经营统治 | 相应身份/权限与势力范围或有效通信；治理 UI、府署、会议、文书、口头交互 | 辖域、资源、责任人、组织、市场与承认；请求可即时确认，政策后果经过传达、生产、运输、消费与政治过程 |
| 战役 | 战役权限与足够地图、战报和媒介；UI、沙盘、舆图、将领会议 | 战术目标、军队、补给、路线、预案与阶段结果；推演即时修改计划，实际命令须传达和接受 |
| 战争 | 战争层权限及可用战略情报；UI、战争会议、文书与使者 | 战争目标、战区、投入、同盟、谈判和持续代价；提案即时记录，态势与承认依据事实更新 |

例如，玩家站在营地沙盘前，与将领推演，接收已经抵达的斥候战报、修改计划，再安排传令。此时其身体、附近人物和其他战线仍然存在。玩家也可以不开任何工作层，只在势力范围生活履职，或外出冒险、游历、调查和战斗。

工作层 UI 与语音、书信、手势、口令、传令人员、会议、沙盘和舆图遵守同一世界规则。打开面板不授予权限，也不把意图直接写成远方结果。沙盘推演是计划；只有经过实际传达、接受和执行才形成事实。同一份已拨资源不能同时支持另一项支出，具体资源占用规则由[资源模块](../02-玩法模块/资源、生产、经济与运输.md#resource-network)和技术契约维护。

工作层、镜头和地图切换不暂停、不传送角色、不撤销结果。单人主动暂停为完整时停，详见[连续世界、时间与暂停](../01-全局规则/连续世界、时间与暂停.md#active-pause)。权限与传达约束详见[玩家身份、权限与操作入口](../01-全局规则/玩家身份、权限与操作入口.md)。

<a id="three-loops"></a>
## 4. 三层循环

| 循环 | 行动链 | 必须持续承接的后果 |
|---|---|---|
| 即时：数秒至数分钟 | 观察局部威胁与命令状态 → 选择移动、冲锋、下令、护卫或撤退 → 承担位置、暴露、时间与组织机会成本 → 观察接触、传令、阵型、士气与目标 → 调整行动或改令 | 身体、位置、接触、命令和局部战场变化 |
| 会话/战役：数分钟至一个阶段 | 查看可信情报和组织风险 → 确定目标、政策、预算、授权与预案 → 行军、交涉、调运、亲自介入或委派 → 处理战斗、市场与政治冲突 → 领域结算损失、收益及拒绝原因 → 恢复、治理、训练、补给与继任 | 组织、库存、路线、关系与阶段结果 |
| 长期：多个战役阶段 | 争取职位与承认 → 扩大代理、领地与供应网络 → 建立事实统治并承担成本 → 面对继承、背叛、历史压力与对手 → 选择保全、扩张、称霸、拥立或改写秩序 | 权力结构、角色传承、历史与长期秩序 |

三层共用角色、组织、资源、历史和世界时钟。职位提高不会跳过命令可达性、代理意愿或资源抵达。上述时间只是决策尺度说明，不是当前 Demo 真实分钟数或统一倍率。

<a id="meaningful-decisions"></a>
## 5. 关键取舍与代价

重要决策在承诺前展示角色合法可知的成本、主要风险和结果类别；后果应改变后续选择。

| 决策 | 取舍、可知信息与持续后果 | 不可省略的边界 |
|---|---|---|
| 亲战或留在指挥位置 | 亲战改变局部接触却增加暴露和传令距离；留守利于观察与组织却放弃个人冲击。依据已知命令、敌我阵型/士气、目标和位置判断，后果体现在伤势、接触、目标控制与命令时效 | 个人冲锋不能稳定替代组织协同；损失需有可追溯线索 |
| 执行、改写或拒绝上级目标 | 执行维持信任与支持；改写争取机会却可能失去时机；拒绝可保存力量并留下抗命。提示授权、期限、资源与已知关系，分别结算目标、军纪、声望、信任与未来授权 | 委派目标不是硬锁；不得用单一“任务失败”遮蔽政治代价 |
| 军用断供、城市压迫或稳定供应 | 军用断供较慢、平民代价较低；市场压迫影响更广，却提高合法性与报复风险；稳定供应消耗现金/库存并可能换得承认。以已知路线、报价/成交、库存报告、来源和时效判断 | 不暴露无来源敌方库存；供应、价格、身体/劳力、组织与军事后果分别成立 |
| 亲自处理或委派代理 | 亲自控制细节但占用时间/位置；委派覆盖多线却受职责、权限、能力、预算、意图和通信限制；记录延迟、拒绝、部分成功与信任变化 | 委派不是自动成功；推翻代理决定可能有关系代价 |
| 争名分或扩大个人控制 | 朝廷/世族名分带来秩序和人才，也要求让渡自主；直属部曲提高直接控制，却扩大军饷与继承风险。参考公开承认、关键组织支持、资源负担和已知对手 | 统治按领域、辖域与时间成立，不是永久万能属性 |

具体执行分别见[军制与自主行动](../02-玩法模块/军制、指挥与自主行动.md)、[治理与领土控制](../02-玩法模块/治理、政治与领土控制.md)、[补给与救治](../03-跨模块流程/补给、消耗与伤病救治.md)。

<a id="design-pillars"></a>
## 6. 设计支柱

1. **连续世界。** 战略、行军、战斗、经济与生活共享时间和状态链；空间精度可以变化，身份与事实不重置。
2. **角色即代理人。** 人格与身体连续，统治、指挥、亲征、经营和流亡是同一人在不同权限下的关注状态。
3. **权力可达。** 权限回答能否提出命令，通信回答能否抵达，影响力影响愿否响应，领域权威判定结果能否成立。
4. **军队自治。** 离场后按预案、继任、训练、士气与补给继续，重新介入仍须权限与可达信息。
5. **资源是战争。** 盐、粮、铁、马料、钱、工匠、运输和市场信誉决定持续行动能力，经济战通过供应链与人物选择产生后果。
6. **事实与认知分离。** 真相、角色记忆与表现互不冒充；司命制造压力和机会，不替角色决定信念或替领域承认结果。
7. **失败延续后果。** 完整游戏考虑失利、受伤、被俘、失势与死亡后的承接；当前 Demo 的死亡、投降与逃离依正式县城胜负配置判定，长期继承不能改写当前失败；“失守后投降”与摘要简写的差异见[待决 D08](设计决策与待决问题.md#d08)。
8. **历史是条件性压力。** 历史事件有发生倾向；行动可改变发生时间、参与者与结果，不是无条件强制剧情。

<a id="audience-narrative"></a>
## 7. 受众、叙事与内容规范

目标受众偏好历史战争、策略模拟、角色扮演、组织经营与系统性叙事，动机包括指挥取胜、塑造角色、建立组织、争职位、理解因果和改写历史。具体新手比例尚未确定。较长会话需要摘要、预案、代理、保存与完整暂停支持，不能要求始终盯屏微操；慢速属于另行讨论的扩展。

题材采用史实骨架、演义气质与原创细节，写实低魔。朝廷名分、地方势力、部曲、命令、资源运输与关系共同决定谁知道什么、能命令什么、愿意响应谁。默认角色方向是有限身份与权限的原创代理人；当前 Demo 专门设为该县军政最高统治者。角色姓名、主线、历史压力点与结局未定，不能由重组文档自行补全。

叙事主要来自具身行动、命令/战报、对话、环境信息、关系与事实摘要。玩家选择能改变关系、授权、资源、继任、控制和历史分岔，剧情不能覆盖已经结算的事实。完整游戏的多视角范围、过场安排与具体主线节点待定。

每项任务或战役必须列明：目标来源、参与组织、可用情报、可亲自/委派行动、资源与权限、失败/撤退条件、结算事实和持久后果。主线章节、支线、动态事件、战役类型、势力内容量、解锁与长期节奏尚待设计；本规范不等于已经存在完整任务清单。

<a id="experience-validation"></a>
## 9. 体验验证与设计完成标准

产品方向不以商业留存或付费指标代替核心体验验证，也不以文档勾选代表实现。以下为验证问题；未定比例、样本、阈值与周期保持未定，不自动成为当前 Demo 附加门槛。

| 观察目标 | 证据与判断 | 优先调整方向 |
|---|---|---|
| 具身行动与权限边界 | 记录位置、发令、委派与玩家复述，能解释位置/权限/通信的作用 | 权限来源、传令路径与状态反馈 |
| 命令与组织分工可辨 | 路由测试和不同职责响应可追踪，玩家能说明差异 | 语义、目标差异与组织反馈 |
| 个人与协同各有价值 | 对照个人介入与组织行动结果，个人影响局部、协同处理更广任务 | 代价、风险、协同收益与任务结构 |
| 离场自治可信 | 离开指挥范围或 Bridge 中断后仍有获准行动及原因记录 | 降低代理复杂度，改善预案与反馈；断线不扩大权限 |
| 长期后果可解释 | 玩家能追溯资源、关系、授权与继任变化及后续代价 | 来源、时效与长期摘要 |
| 长线节奏可用 | 记录战斗、治理、关系与事件的时间分配，检验暂停和摘要 | 时间推进、信息层级与委派；具体时长待定 |
| 跨层事实一致 | 追踪资源、身份、授权、组织、情报的同一事实与来源，无矛盾余额和结果 | 状态源、结算顺序、通知与引用 |
| 未关注层继续且信息不过载 | 观察代理、补给、市场、战役与个人状态持续推进，只接收已抵达信息 | 周期、自治、摘要优先级与授权选项 |
| 各层清晰且统一 | 玩家分别说明个人、治理、战役/战争的目标、操作与反馈，并解释跨层后果 | 目标、信息层级、反馈语言与承接 |

测试记录格式：版本/日期、对象、任务、观察事实、玩家反馈、原因推测、设计决定与后续。保留日志、命令状态、战场事实、PIE 结果与环境，明确事实、推断、决定。规则表、小规模模拟、命令路由测试、Bridge 关闭测试、PIE、跨战役对照与长线试玩各检验不同风险，具体测试任务和周期待定。

调整顺序为反馈 → 目标差异 → 通信提示 → 预案优先级 → 接触风险 → 数值。若核心闭环不成立，应缩小内容，不能通过增加单位掩盖。旧短切片的小样本、30 秒/5 分钟等建议阈值仅在[历史切片档案](../../archive/PRD/骑将冲阵垂直切片（已取消独立开发）.md)保留，不作为当前守城 Demo 的门槛或市场结论。

设计完成须能回答：身份与优先级怎样推导；军队/资源权限何来；命令和情报怎样抵达；离场后谁按什么预案行动；资源经过哪些领域；短缺怎样由供应进入身体、劳力、组织与军队；人物为什么知道或拒绝；司命提出什么；失败怎样承接及损失；历史条件怎样变化。完整游戏的跨层体验、领域结果、部分失败与回放方向见[世界扩展路线](世界扩展路线.md#long-term-acceptance)及[技术架构](../../architecture/README.md)。

## 11. 体验风险与决策窗口

以下完整保留原玩法案的十项风险、发生信号、影响、应对与决策时间；是待验证的风险登记，不表示已发生或已解决。表中技术名词仅提示审查责任，精确契约由[系统边界](../../architecture/01-系统边界/01-系统边界与权威写入.md#system-boundaries)、[Command 与回执](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)及[运行时接入](../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#ue-paralls)维护；断线不能扩大许可或写权。

| 风险 | 发生信号 | 影响 | 应对方案 | 决策时间 |
|---|---|---|---|---|
| 单骑冲锋成为支配策略 | 不发令也稳定赢下关键目标 | 组织和命令玩法失去意义 | 调整目标压力、接触风险、协同回报，保留个人局部影响 | 战场玩法验证 |
| 通信延迟不可理解 | 玩家把拒绝/过期当成系统失灵 | 放弃命令链或形成菜单操作负担 | 显示节点、距离、时效、来源和拒绝原因；提供预案缓冲 | 核心命令测试 |
| 组织职责差异不清 | 玩家无法分辨命令对象或行为 | 命令成为假选择 | 用队旗/编号/编队、目标差异和行为反馈强化辨识 | 命令与组织玩法验证 |
| 玩家离场或通信中断后自治停止 | 玩家离开后部队静止/瞬间完成目标 | 连续世界承诺被破坏 | 先实现稳定的预案和本地战术脑，记录触发原因 | 核心玩法验证阶段 |
| 状态反馈不足 | 玩家无法复盘阵型/士气/目标变化 | 失败显得随机、不公平 | 增加命令 receipt、目标状态、来源/时间和战报 | 每轮体验验证 |
| 信息过载 | HUD 同时显示所有资源和远方事件 | 玩家无法判断优先级 | 默认只显示关键状态和异常，细节按需展开 | UI 首轮评审 |
| Paralls 越权或双写事实 | 远端意图直接改战场最终状态 | 复现、回放和权限失效 | 领域 Owner、revision、幂等、receipt、Bridge 回退 | 技术边界评审 |
| 资源/经济战变成表格 | 玩家只处理报价和库存，没有行动感 | 长线玩法脱离人物和战争 | 关键政策/异常窗口介入，保留源头—运输—消费证据 | 长线原型 |
| 范围膨胀 | 未经验证地扩张地图、单位、政治和内容量 | 核心闭环延期 | 以验证目标和阶段范围控制内容，不以总案篇幅作为排期依据 | 每次版本评审 |
| 资产和性能超预算 | 高模、批量导入或复杂特效遮挡/降帧 | 正式内容不可玩或不可读 | 一次只改变一类资源，先小样本验证，保留可回退版本 | 资产变更前 |

### 11.1 总策划补充风险与取舍

下表保留原总案的风险关注点。其中标准/硬核是候选方向，技术措施是契约导航而非本篇另定实现；原范围取舍中的“骑战子切片”已被取消独立开发的决策取代，完整23 Owner仍是建设目标而非现状。

| 风险 | 设计取舍 |
|---|---|
| 连续世界信息过载 | 默认分层显示，异常才展开细节；保留最后已知状态和可信度 |
| 通信延迟劝退 | 标准/硬核双模式，命令排队、预案和自动中继提供可理解的缓冲 |
| 经济战变成表格 | 玩家只在关键政策、授权、异常和风险窗口介入，日常由手下与 Owner 处理 |
| 经济战过度抽象 | 资源网络必须有源头、仓储、运输、市场和消费证据 |
| 缺盐直接秒杀全城 | 使用需求、身体、劳力和组织的连续因果，长期严重缺口才产生严重生命后果 |
| 司命越权成为上帝 | 司命只能催化，Owner 结算，角色先经过 L2/L3/L4 |
| 群体模拟双写角色 | activation lock、唯一推进者、receipt 和 revision 冲突时回排队 |
| 范围膨胀 | 当前只制作召陵县守城内容，骑战作为子切片；完整五阶段基础设施与 23 Owner 按 08 建成，后续扩展内容而不补占位基建 |
| 复合结算失败无法解释 | 每个 Owner 独立 receipt、部分结算、补偿/重试和 replay |

当前范围由[县城 Demo](../05-阶段与可玩切片/县城守城Demo/体验目标与范围.md)维护；旧骑将子切片和旧 Phase 不构成并行验收。司命/群体边界、跨 Owner 部分失败与恢复只引用[架构入口](../../architecture/README.md#technical-reference)的单一契约。

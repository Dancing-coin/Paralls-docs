## 1. 分级组织与职责

军队以岗位、组织层级、直属关系、授权范围、指挥头目、预案版本和继任链运行。玩家可以任命、授权、编组分工、设目标与预案、核查执行，也可亲自介入；身份、许可、资源、训练与通信决定可操作范围。完整军制、兵种层级规模和授权规则仍待定；旧骑战切片的一营三队不能扩成所有玩法的固定规模。县城 Demo 独立来源中的三队配置是否保留，交阶段配置待决，不自动成为验收门槛。

| 角色/节点 | 行为职责与反馈 |
|---|---|
| 玩家/统治者 | 具身行动与合法命令来源；位置、权限及可知信息限制指挥 |
| 直属护卫、亲卫、传令人员 | 保护玩家或作为授权命令中继，反馈路径与通信状态 |
| 指挥官/指挥节点 | 校验、承接、分发、协调下属；失能后触发有效继任链 |
| 军队/部属组织 | 依职责、命令、训练预案和现场事实自治，影响战场状态与目标 |
| 继任候选 | 依据资格接管获准权限和预案，不继承未授予的全部权力 |
| 敌方指挥头目 | 敌军协调及关键目标，影响敌方队伍、军旗和目标压力；详细行为与识别只在[对手职能](士气、阵型与战场目标.md#enemy-roles)维护 |
| 长线角色与代理 | 组织、政治和资源行动者，通过关系、授权、记忆、利益、意图及领域结算承接委派 |
| 工坊、军需、村落等责任人 | 在各自职责、预算、许可和资源内办理军需与社会协作 |

上述角色的具体性格/背景、继任候选身份及长线角色名单仍待定；角色目录不把空白人物设定补成已定剧本。玩家骑将的骑乘、观察、发令、冲锋与风险选择在[具身操作](具身操作、骑乘与视角.md#embodied-movement)维护。

合法命令不保证服从：失效条件、能力、恐惧、疲劳、家庭责任和现场判断可导致拒绝、拖延或改写执行方式。结果分别记录任务、军纪、信任、声望、关系及后续授权，不用一个“任务失败”覆盖所有后果。命令各阶段与跨层路由只在[命令传递流程](../03-跨模块流程/命令传递、执行与指挥权轮替.md#command-lifecycle)正式维护。

<a id="trained-plans"></a>
## 2. 可训练、可编辑、可继承预案

预案是组织能力，可训练、版本化和继承，编辑能力须与组织层级、权限和规模相符。

| 预案内容 | 玩家决定与约束 |
|---|---|
| 队形、队伍职责、护卫对象 | 定义协同与保护目标，不能直接拖动隐藏战场数值 |
| 目标优先级和士气反应 | 规定不同压力下行动，读取最新合法事实 |
| 撤退条件、撤退路线、补给阈值 | 确定何时继续、等待、重规划或撤退；具体阈值待定 |
| 通信方法与继任顺序 | 明确信息传达和失能承接条件 |

玩家可战前编辑，战中切换已训练预案；临时改案受军队素质、指挥官与通信质量限制，不等同于把未训练规则即时安装到全军。版本、训练成本、所需时长和适用规模待定。预案质量、训练、士气影响稳定性；自治节省注意力但牺牲精确控制。

<a id="autonomy"></a>
## 3. 离场、失联与现场自治

每个决策窗口依次考虑：

1. 已送达且仍有效的命令；
2. 战前训练过的预案；
3. 继任链与现场指挥官；
4. 训练、士气、补给、疲劳、组织文化及个人性格。

读取队伍状态和最新合法事实后，按预案优先级形成候选，经权限、资源与可达性校验，执行本地战术行动或等待，并输出原因。状态包括待命、执行命令、执行预案、重规划、撤退、失联、继任接管；状态不是自动胜利脚本。

离开指挥范围、失能或通信中断后，队伍继续行动。只有超出预案、关键突发、指挥官失能、目标状态改变或通信重建才形成可介入窗口；无通信不能强制改写远处行为，切换界面不能令队伍暂停。无目标、资源不足、权限变化、指挥头目失能或 Bridge 失联时回退最近有效预案，仍须满足合法执行权威及许可。没有有效许可的动作保持待处理或安全中断，不以“本地接管”绕过授权。

反馈需有当前预案、版本、触发事实、动作、未执行原因、下一决策窗口；离场后可收到合法抵达的报告。核心不依赖联网，也不要求 Agent 每次推理才能继续；[断线恢复](../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#disconnect-recovery)与[军事领域](../../architecture/03-Owner领域/02-领域Owner详细契约.md#military-domain)定义实际执行边界。

<a id="authentication"></a>
## 4. 命令验证制度

玩家可制定口令、信物、双传令、多源复核与诱饵制度；封泥、签押、合符、应和及格式校验由制度自动执行。异常时玩家可暂缓、复核、接受风险或追溯。破译需要敌方资源投入；封泥破损、格式异常、多源矛盾、无应和提供可学习预警，不能无证据随机篡改结果。

制度有时间、通信机会、组织信用与可能资源成本；技术命令字段、授权凭据和复核不在本页另造合同，引用[公共命令契约](../../architecture/02-公共契约/02-Command事件与Receipt.md#command-event-receipt)。

## 5. 兵种目录与维护差异

兵种是“装备组合＋训练水平＋组织来源＋士气/忠诚＋战术角色”，不是独立模型清单。长期目录目标约二十种，首轮扩展约十种仅为原案候选，均不构成当前县城 Demo 必做清单。

| 类别 | 原来源完整目录 | 战术方向 |
|---|---|---|
| 步兵（7） | 郡国矛兵、郡国刀盾兵、戟盾兵、长矛兵、募兵戟盾、部曲戟盾、陷阵先登 | 扛线、护卫、反骑、突破、据点争夺 |
| 远程（5） | 郡国弓手、募兵弓手、强弩兵、募兵强弩、弓骑 | 压制、远程杀伤、机动骚扰 |
| 骑兵（5） | 轻骑、突骑、重骑、外族突骑、亲卫骑 | 侦察、冲击、侧翼、护卫 |
| 特殊（3） | 义从、工程队、水军/舟师占位 | 护送、工程、后续水战 |

首轮候选保留为戟盾兵、强弩兵、突骑、轻骑、弓手、亲卫骑、郡国矛兵、郡国刀盾兵、长矛兵、工程队。装备、训练、补给、忠诚与组织来源须可独立结算；派系差异通过可用性、成本、装备变体与关系体现。

郡国兵、募兵、部曲、义从、外族骑、后期水军的招募权、训练成本、维护关系和政治风险不同：部曲偏忠直接主君但受欠饷与声望影响；郡国兵受官府/地方秩序影响；募兵受军饷/军功/战局影响；外族骑受盟约/互市/首领关系影响。不能任意互换为同质兵数。

<a id="military-validation"></a>
## 6. 反馈、验证与待定

队伍面板提供职责、训练、士气、当前预案、继任与最近合法事实；编辑权限和范围待定。用队旗、编号、编队、站位、动作和目标差异辨认职责，不依赖大量专属模型。测试包括正常命令、无权拒绝、过期、指挥失能、无合格继任、Bridge 关闭、目标改变及玩家离场；观察队伍是否继续且可解释，不能静止或瞬时成功。

指挥权轮替的资格、幂等交接和反馈见[轮替流程](../03-跨模块流程/命令传递、执行与指挥权轮替.md#succession-flow)；关系/授权来源见[治理](治理、政治与领土控制.md#governance)，伤势和长期传承见[生存成长](角色生存、成长与传承.md#failure-inheritance)。完整军制、预案编辑范围、训练时长/成本、代理汇报频率、自治阈值和撤换规则仍待定。

## 场景职责与阶段边界

当前体验为汝南郡召陵县县城守城 Demo，目标是收到敌情、求援、守城与维持资源秩序。本篇只维护城内/外功能分区、空间连接、城门/道路、现有尺度假设；不以此扩展新玩法或新增强制骑将冲阵切片。具体资产清单与批次见[场景素材需求](../../../art_resources/requirements/召陵县/场景素材需求.md)；通用建筑制作参数见[建筑模块化与流送标准](../../../art_resources/standards/建筑模块化与流送标准.md)；系统边界只引用 [UE 本地提交与 Paralls 同步](../../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#ue-paralls)。

以下面积、户数、人口、18里和8000+可进入单元是原有长期场景规模假设，不是已完成资产量，也不是当前必须一次铺设的制作指令。首版完整可玩里与S1批次范围沿原需求保全；其余轮廓可由登记的Low Poly/灰盒/HLOD代理分阶段表达。地图并非考古城址复原，具体地籍/墙线/位置尚待核验。

### 城内分区

城内采用 18 个里级区块的长期数据结构，Demo 首版制作 1 个完整里，其他里以可辨认的远景街坊代理和 HLOD 轮廓表达。城内必须保留以下功能分区：

| 区域 | 首版等级 | 作用 | 必须可见/可交互内容 |
|---|---|---|---|
| 衙城/县署 | S1 | 玩家统治、军政命令、报告、继任和 Objective 入口 | 正堂、便坐、诸曹/吏舍、狱舍、门屋、衙墙、望楼、庭院、案几/简牍锚点 |

| 粮仓/军需区 | S1 | Inventory、配给、军需报告、运输入库 | 仓廪、粮囷、装卸台、车位、秤/量器、封存区、库存交互锚点 |

### 城门和道路策略

Demo 设定四门长期数据结构：南门为主要玩家入口和主攻方向；东门、西门、北门首版保持可识别、可封锁、可报告和可作为运输/敌情节点，但不要求同等室内细节。

道路分为：

- 主街：8m 模块，连接南门、县署、市区和粮仓；
- 里巷：4m 模块，支持角色和驮畜通行；
- 车道/粮道：6—8m，支持运输批次和护送；
- 窄巷：2.5—3.5m，只允许行人和单体角色，必要时形成阻挡；
- 城墙巡行道：不低于 2.5m 可通行宽度，支持守军、传令和伤员担架。

所有道路必须有可寻路逻辑体、排水坡向和阻挡点；不能只摆一张贴图道路。

## 原方案场景尺度与 Cell 选型依据（基线保留，待评审）

| 指标 | 原方案值（迁移保全，待评审） |
|---|---|
| 城墙内面积 | **90 万 m²**（950m × 950m） |
| 含城墙城壕 | 约 **1.2 km²** |
| 完整场景边界 | 约 **2.5 km²** |
| 户数 / 人口 | **11,000 户 / 约 50,000 人** |
| 可进入建筑/单元 | **8,000+** |
| 里数 | **约 18 个里** |
| 官寺核心建筑 | **10—15 栋** |
| 市垣列肆 | **60—120 间** |
| World Partition Cell Size | **64m**（城内密集城市核心区） |

Cell Size 的选型依据：64m 是**密集城市环境**的标准选择，优点是流送粒度细、单 Cell 内存低，代价是 Cell 数量多、加载操作频繁。你的县城是 950m 见方的高密度建成区，128m 或 256m 会让一整个街坊的资产在同一个 Cell 里“同生共死”，流送粒度不足以支撑“走进一条巷子只加载这一小片”的需求。

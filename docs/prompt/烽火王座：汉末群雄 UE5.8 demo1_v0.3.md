## 工作顺序

这是一个以可玩 Demo 为目标的分阶段项目。不要在需求未明确时直接改关卡或导入资源。

1. 先和用户讨论本轮 Demo 的体验、成功标准、范围、单位数量、资源风格和验收方式，直到需求明确。
2. 需求明确并得到继续执行指示后，保存现状并清理当前垂直切片关卡；保留原始 World Partition 关卡、`/Game/TopDown/Lvl_TopDown` 和 `Saved` 调试文件。
3. 从网上找许可证清晰的 Low Poly 人物和地编资源，小批量下载并登记到 `docs/art_resources/`。
4. 先建立低成本战场和少量角色，跑通移动、三视角、亲卫传令、`10/22/34`、一营三队行为、士气/阵型变化和关键目标。
5. 用 PIE、UE 日志、Actor 统计、性能数据和定向截图验收阶段一。
6. 阶段一通过后，逐个利用用户提供的本地 FBX 和 Asian Armour 资源替换 Low Poly 资产，进入阶段二表现提升。

体验描述、镜头要求、战场可读性和美术验收标准见 `docs/art_resources/experience_index.md`；资源来源和使用状态见 `docs/art_resources/asset_registry.md`。

## 两阶段边界

### 阶段一：Low Poly 可玩 Demo

- 只做一张小型战场：平地、浅坡、道路/掩体、双方阵地、中央关键目标、军旗、后撤线和 PlayerStart。
- 先放少量玩家骑将、亲卫、一营三队、敌方队伍和敌方指挥官；数量以稳定可玩为准。
- 完成 WASD、鼠标朝向、第一/第三/俯视切换、命令传递、队伍自主反应、士气/阵型状态变化和一次指挥继任。
- 先用网上 Low Poly 资源，不得为了视觉数量一次性生成数百个高模角色。

## 硬件与本地配置

- GPU：RTX 4070，约 12GB 显存；RAM：32GB。
- 最近实测：可用物理内存约 15.8GB，提交内存约 17.2/70.1GB，显存使用约 1.53GB，UE 私有内存约 3.6GB。
- 数值随系统变化；每次大型操作前重新测量。
- 可用内存低于 8GB：禁止大型导入、批量生成、烘焙和大规模扫描。
- 可用内存低于 4GB：停止操作，保存并退出 UE；必要时重启 Windows。
- 显存可用低于 3GB：禁止新增高模、Nanite 和高分辨率材质。
- 只运行一个 UE；不并行启动多个大型导入、着色器编译、烘焙或资产扫描。
- 不得一次性导入 861 个 `.uasset`、多个大型 FBX 或数百个高模角色。

## 必须执行的验证

每一步只做一个小变化，并完成：

- UE 日志成功/错误检查；
- 当前关卡 Actor 数量和关键资产状态检查；
- PIE 是否真实运行检查；
- 编辑器使用 MCP `CaptureEditorImage` 或 Slate 定向截图；游戏效果使用 PIE 截图；
- 内存/显存和帧率或加载时间记录。

没有这些证据，不得声称关卡已生成、资源已接入或 Demo 已完成。出现资源压力时立即停止、保存、记录并回到最近一个可运行版本。

## 后端与 AI 方向

UE 负责实时移动、碰撞、伤害、士气、阵型、军旗、指挥官和攻城器械结算；本地战术脑和未来 Paralls 只产生经过验证的语义意图。Python/Paralls 不得直接写入位置、骨骼、伤害或最终世界状态。Bridge 关闭或断线时，本地 AI 必须继续运行。

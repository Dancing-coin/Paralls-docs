## 共享时间、稳定身份与控制合同

共享身份/时间/能力授权具有明确基础权威和唯一写入口；领域不得各自复制可写时钟和授权表。角色/实体身份贯穿近远场、死亡、表现加载与存档恢复。

`world_tick` 是逻辑世界的单调时间基准；UE 时钟入口只是所选部署下对同一时间合同的实现/投影。渲染时间和网络健康检查的 wall-clock 不等于世界时间。事件发生、角色获知、画面呈现分别用 `event_time`、`known_time`、`presented_time`，迟到报告不能改写发生时间。

## 连续性、时钟与版本的历史设计要求

- 本文不把 Paralls 当前 Godot 表现链路直接移植为 UE 代码；Godot 文档只作为边界参考。

### 核心原则

### 对齐什么

下面五项必须统一对齐：

| 对齐项 | 唯一事实来源 | 说明 |
|---|---|---|
| 身份 | 角色/编制身份目录 | `character_id`、编制归属、继任关系不能因转层生成新身份 |
| 世界时间 | UE 战场时钟投影 | 暂停时不前进；Paralls 不用 wall-clock 推进角色或批次 |
| 状态版本 | 领域 Owner 的 `revision` | 位置、命令、身体、士气、阵型、行动阶段分别带 revision |
| 世界执行权 | UE embodiment lease | 同一角色同一时刻只有一个世界状态写入者；Paralls 不与 UE 双重推进位置/身体/战斗事实 |
| 动作意图权 | 当前 intent lease | C3 Agent 可持有角色动作选择权；UE 玩家控制、强制受击/失能等可按明确优先级临时中断 |
| 交接结果 | handoff receipt | 转层成功、拒绝、过期、冲突和重试都可追踪、可幂等重放 |

### 不统一什么

- Agent 激活不是表现激活。
- 近场完整 Actor 不是语义 Owner。
- `presentation_plan` 不是世界事实，不能直接造成命中、死亡、资源消耗或路径占用。
- Agent 的 `semantic_intent` 不是 UE 的自动执行许可；UE 必须重新校验能力、目标、通信、版本和当前战场事实。

<a id="authority-epoch"></a>

## 领域写权 epoch 与两种 lease

必须分别登记：
- 领域 `authority_scope` / `authority_epoch`：哪个提交端能确认哪类事实流；旧 epoch 被 fencing 后不再可写。
- `intent lease`：哪个推进者可以为角色产生新的自主意图。
- `embodiment lease`：哪个执行/表现绑定当前身体动作；玩家接管与 Agent 的优先级由控制合同处理。

三者不可互相代替。C/P 精度切换、Actor 创建/销毁或 possession 不自动转移 Body/Combat 等领域写权。注册字段见 [Owner Manifest](../03-Owner领域/01-Owner注册表.md#owner-manifest)；控制与领域迁移边界见 [Handoff](04-多精度与Handoff.md#handoff)。

<a id="cadence-contract"></a>

## 六种独立节奏与体力窗口

### 更新节奏与模型输入

高频协作是延迟要求，不等于所有数值每个画面帧全量重算。画面帧、模拟步长、模型评估、事实提交、投影同步和 Agent 决策是不同节奏，均须使用统一 `world_tick`；暂停不推进模拟时间。

| 内容 | 结算触发/节奏 | UE 与角色的即时约束 |
| --- | --- | --- |
| 生命、伤势、身体功能 | 命中、治疗、持续效果到期的事件或定时 tick | 命中后及时更新身体能力；表现插值不产生额外伤害 |
| 体力 | 攻击/格挡等动作成本；冲刺等连续动作按模拟时间积分；恢复按规则窗口推进 | 准入检查与消耗/预留受同一写入口保护；体力耗尽及时中断或降级动作 |
| LifeState | 经授权的身体/效果依据触发状态转换评估 | 倒地/死亡不等待 LLM 推理；禁止 Pawn 或动画自行宣布死亡 |
| 个人及队伍战场士气 | 伤亡、军旗、指挥、鼓舞等事件触发，加周期威胁/压力评估 | 及时更新纪律、阵型维持、溃退约束；保留角色自主判断与解释 |
| 饥渴、长期疲劳 | 生存时间窗口；剧烈活动或阈值变化可提前触发 | 向体力上限、恢复率和功能模型提供输入，不与体力重复扣算 |
| Agent 心智与计划 | 合法感知、命令和关键结果触发，受认知 cadence/预算约束 | 无需每次扣血都推理；正在执行的计划接受实时身体约束 |

Static Data/领域模型配置须声明 `evaluation_cadence`、`trigger_types`、模拟步长/积分策略、稳定顺序、阈值/滞回、单位/精度、输入 freshness 和 `model_version`；Owner Manifest 另记录执行位置、延迟预算、提交边界及恢复策略。适用绑定仍按主体、资源、状态和设施限制模型，部署到 UE 不赋予通用模型任意套用权。

连续体力变化可以用带起止 tick、模型版本和固定输入的窗口事件表达；命中、动作准入、阈值跨越、暂停和交接等边界须切分/结清窗口。不能先按每帧累计，再在窗口结束重复扣除；聚合不得掩盖中途体力不足。发生治疗、负重或疲劳等输入变化时按变化点切窗，保留重建所需依据。具体频率和耗时预算在实现前登记、在 PIE 中测量；本文不把假定帧率当作已测性能。

<a id="numeric-cadences"></a>

## 数值、角色与动画推进方式

### 数值与角色更新节奏

| 事实 | 推进方式 | 必须验证 |
|---|---|---|
| 生命/伤势 | 命中、治疗和持续效果事件/tick | 同一伤害不重复；反馈不等待 Agent |
| 体力 | 动作成本 + 连续活动积分 + 恢复窗口 | 原子准入/消费；输入变化、阈值、暂停和交接切窗，中途耗尽不能被聚合掩盖 |
| LifeState | 授权身体/效果依据触发合法状态转换 | 归零不自动死亡；死亡后普通治疗无效 |
| 战场士气 | 可用事件 + 周期压力评估 | 个人目睹、队伍报告和全局事实分开；同一士气允许不同自主判断 |
| 饥渴/长期疲劳 | 生存时间窗及阈值触发 | 影响体力模型输入，不与体力重复扣算 |
| Agent 与动画 | 合法感知/命令触发决策；当前计划持续执行并接受即时限制 | Agent 慢时强制反应及时；表现不会自行产生新自主策略或世界事实 |

具体模拟步长、提交窗口和响应耗时在 A5 登记，D 实测；不把渲染帧率当成领域结算频率，不在本计划虚构已测毫秒数。

<a id="pause"></a>

## 暂停、时停、control_epoch 与回调隔离

- 玩家直接控制角色时，玩家输入优先于 Agent 的自主身体命令；Agent 可继续观察和建议，但不可争抢身体控制 lease。

### 暂停/时停规则

暂停是 UE 战场时钟的全局冻结，不是只停玩家输入：

- `world_tick` 不增加；
- Agent cadence 不运行，模型不产生新的决策；
- UE 移动、寻路、碰撞、战斗、生产、伤病、运输、动画状态机和表现插值冻结；
- 暂停中只编辑尚未发出的命令草稿；已送出的命令是既成事实，改令/撤令要在恢复后作为新命令沿实际通信渠道传达，不得远程修改传令兵手中的旧命令；
- 未完成的 handoff 保持原 lease 和 pending 状态；
- 恢复时所有系统从同一 tick 继续，先处理版本/lease 校验，再传达暂停期间编辑的命令；
- 暂停界面可以显示已知状态和玩家计划，但不得揭示角色私有认知或未侦察敌情。

<a id="pause-authority"></a>

## 暂停的统一解释

暂停可以编辑/排队意图；不得使传令、Agent 新决策落地、语义动画、领域积分或计时器推进。网络与模型响应可返回，但进入隔离区；恢复后对 epoch、TTL、revision 和权限重新准入。当前计划也服从暂停。WRK 屏障不能只停止画面或仅停止某一个宿主。

<a id="world-cadence-order"></a>

## 连续时钟下的结算层次与推荐因果顺序

### 结算顺序与节奏

世界使用连续时钟，但不同事实使用不同 cadence：

| 节奏 | 典型内容 |
|---|---|
| 即时 | 战斗接触、命令送达、库存破坏、仓库起火、抓捕、军旗变化 |
| 短周期 | 报价、成交、运输队状态、排队、传闻、角色决策窗口 |
| 日级 | 家庭消费、盐粮需求、疲劳恢复、劳力、军队补给、市场库存 |
| 旬/季 | 税粮、征募、屯田、训练、技术生产、政治承认和统治力稳定 |

建议顺序为：已提交资源/环境事实 → 运输和库存可用量 → 市场价格与成交 → 消费计划 → 身体/需求状态 → 劳力和组织候选 → 角色 L1-L4 承接 → 军队士气/预案与政治结果。实际跨域提交仍以 Owner admission 和 revision 为准，顺序不能绕过权限和因果。

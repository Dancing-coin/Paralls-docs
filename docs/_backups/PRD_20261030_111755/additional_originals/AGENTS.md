# Guoshang UE5.8 项目协作规范

## 目标

本项目以完成可玩的“骑将冲阵”游戏 Demo 为目标，而不是以堆积系统、资产或技术概念为目标。玩家应能骑马冲锋，使用 WASD 移动、鼠标控制朝向，在第一人称、第三人称和俯视视角之间切换，并通过一队亲卫向一营三队传递 `10/22/34` 命令，影响敌我士气、阵型和军旗、敌方将领、攻城器械等关键目标。

后续系统要保留军制分级、可训练和可编辑的预案、军队自主行为、士气、训练度、指挥头目、指挥权自动轮替，以及接入本地 `paralls-phase-0-demo` 的角色智能体、司命和群体模拟的边界；这些方向不能被第一阶段的 Low Poly 实现破坏。

## 需求讨论门槛

- 任何新功能、关卡重建或资源替换开始前，先与用户讨论目标体验、成功标准、范围和当前阶段；不要根据模糊描述直接扩大工作量。
- 用户说“跑通 Demo”时，优先确认一个可实际操作和观察的最小闭环：骑马移动、视角切换、三条命令、亲卫传令、三队反应、一次士气/阵型变化和一次关键目标变化。
- 需求未明确时只能阅读、检查、记录和提出方案；不得清空关卡、批量导入资产或启动长时间构建。
- 需求明确并得到继续执行的指示后，第一步才可以清理当前垂直切片关卡；清理前必须保存、记录关卡路径和提供可回退方案。


## 美术资源管理

- 美术资源索引、体验目标、来源、许可证、导入状态、目标 Actor、性能预算和替换记录统一放在 `docs/art_resources/`。
- 每个外部资源都要登记来源 URL 或本地路径、许可证/授权状态、下载日期、文件大小、面数或纹理预算、使用位置和是否已在 UE 中可见验证。
- 资源按 `source/`、`staging/`、`approved/`、`deprecated/` 思路管理；未经验证的资源不得直接覆盖正式资产。
- 项目内资产使用 `/Game/...` 路径；运行时逻辑不得写入机器个人绝对路径。
- 近场可见角色和中远场队伍使用不同预算；优先实例化、LOD、低分辨率材质和简化碰撞。
- 每次只改变一类资源，验证通过后再继续；保留上一版可回退资产。

## 本机配置与操作限制

当前机器基线：RTX 4070 12GB 显存、32GB RAM；最近一次实测约有 15.8GB 可用物理内存、提交内存约 17.2/70.1GB、显存使用约 1.53GB、UE 私有内存约 3.6GB。数值会变化，执行大型操作前必须重新测量，不得把这组数字当成永久保证。

- 只运行一个 UE 实例；不要并行启动大型导入、着色器编译、烘焙或资产扫描。
- 可用物理内存低于 8GB：禁止大型导入和批量生成。
- 可用物理内存低于 4GB：停止构建，保存并退出 UE；必要时重启 Windows。
- 显存可用低于 3GB：禁止新增高模、Nanite 资产和高分辨率材质。
- 不得一次性导入 861 个 `.uasset`、多个大型 FBX、数百个高模角色或复杂植被。
- 不得删除用户的 `Saved` 调试文件，不得修改或破坏 `/Game/TopDown/Lvl_TopDown`，不得重复清空原始 World Partition 关卡。
- 每个步骤都要有日志、资产/Actor 数量、PIE 状态和定向截图证据；没有证据不得宣称完成。

## 验证和汇报

每次操作前说明本步目标和资源预算；每次操作后报告实际修改、内存/显存变化、UE 日志结果、下一步和剩余风险。UE 编辑器截图使用 MCP 的 `CaptureEditorImage` 或 Slate 截图；游戏效果使用 PIE 截图，不得使用桌面截图冒充。

任何批量操作都必须先做一个小样本验证。若导入、编译或运行时间异常增长，立即暂停并回到最近一个可运行版本。

## UI 操作边界

- 如果某项 UI 操作只能通过点击完成，立即停止并请用户亲自点击；不得代替用户点击，也不得尝试坐标点击或其他模拟点击方式。
- 可通过 MCP、键盘快捷键或代码接口完成的非点击操作可以继续。若确认只能点击才能解决，说明当前停点和需要用户执行的操作后等待用户。

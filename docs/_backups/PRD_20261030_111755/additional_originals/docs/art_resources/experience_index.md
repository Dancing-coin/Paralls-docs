# 骑将冲阵体验索引

## 核心瞬间

玩家亲自骑马冲阵，在接触敌阵前后改变敌我士气和阵型，并控制一个关键目标。玩家不是只在地图外下令，而是一个会移动、会暴露风险、能改变局部战局的指挥节点。

## 玩家需要看懂的因果链

```text
骑将接近敌阵
→ 亲卫队收到快捷命令
→ 亲卫队向营指挥头目传令
→ 一营三队按预案和当前士气执行
→ 冲锋接触改变阵型/士气
→ 军旗、敌将或攻城器械的控制状态改变
→ 指挥头目失能时次高指挥官接管
```

## 阶段一美术验收

- 俯视视角能读出道路、坡地、双方阵地、中央目标和后撤线。
- 第三人称视角能清楚看到玩家骑将、亲卫和冲锋方向。
- 第一人称视角能让玩家感到自己正在骑马冲锋，而不是观察一个远处代理。
- 玩家、亲卫、己方三队、敌军、敌方指挥官、军旗和攻城器械具有清晰颜色、轮廓或旗帜区分。
- 写实风角色也要有角色朝向、移动、受击/失能和阵型状态的可读反馈；远层代理只作为性能降级，不作为近景成品。

## 分层表现与替换顺序

- 优先完成玩家骑将和近场亲卫的写实风成品，再完成敌方指挥官和军旗守卫。
- 然后按镜头距离扩充中远场步兵、骑兵、地形、植被和攻城器械的写实风变体；远层使用 HLOD/实例化代理控制成本。
- 每次替换后必须保持相同的 gameplay component、碰撞接口、相机锚点、命令来源和状态事件。

## 讨论清单

在开始下一轮实现前，与用户确认：

- Demo 中最重要的第一场冲锋路线和中央目标是什么；
- 写实风首版允许的单位数量、镜头距离和目标演示时长；
- 角色和地编资源的材质、颜色区分和镜头距离；
- 哪些本地资源先用于玩家骑将、亲卫、步兵和敌军；
- 阶段一验收后，优先提升角色、坐骑、地形还是战场器械的表现。

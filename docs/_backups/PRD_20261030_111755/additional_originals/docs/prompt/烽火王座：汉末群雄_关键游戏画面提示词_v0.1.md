## 1. 使用方法

参考教程采用“先明确游戏画面链条，再制作角色、场景、游戏截图和过场关键帧”的工作方式。本项目只采用这套制作流程，不采用教程中的水墨、武侠、机甲或其他示例内容，并将其改造成一组能够说明三种玩法共存关系的汉末画面链：

1. 先生成统一的视觉基准图、玩家角色锚点和三种可切换视角的构图基准。
2. 再生成个人 ARPG、战斗接触、沙盘/舆图、经营统治和战争态势等静态关键画面。
3. 最后使用静态画面作为首帧/尾帧，生成玩家从个人行动自然关注到工作层、再回到个人世界的转场视频。
4. 每次只改一个变量：视角、角色姿态、地点、天气、关注层或事件状态。保持角色脸部、服饰、武器、军旗颜色、世界事件和 UI 信息编码一致。

本文件只提供提示词，不把生成图当作正式美术资产。生成图不得直接替代 UE 内资产、UI 或游戏功能。视觉基调以玩法策划案中的“写实低魔的汉末战争表现”为准；提示词中出现的镜头语言、关键帧和转场安排来自制作教程的方法抽象。

## 2. 统一视觉基准

### 2.1 全局风格提示词

```text
写实低魔的东汉末年战争世界，历史感汉末服饰与兵器，克制的电影级游戏概念画面，真实材质，泥土、木材、麻布、皮革、青铜、铁器和旧纸张的细节，冷灰天空与土黄大地为基础色，以暗红军旗和低饱和青绿色作状态色，雾气和尘土有层次，光线服务于方向、距离、军旗、阵型和人物关系的识别。游戏支持第一人称、第三人称和俯视视角实时切换：第一人称强调眼高、双手、身体遮挡和近距离交互；第三人称强调动作、坐骑、队形和人物关系；俯视视角强调地形、队伍、道路和战场流动。三种视角共享同一个持续运行的世界事实，不因切换而暂停、传送或获得不应知的信息。它不是海报、舞台剧或孤立的菜单截图。东方历史气质，低魔，不出现超自然光效，不复制任何现有游戏的角色、UI、地图或美术资产。
```

### 2.2 统一角色锚点

```text
同一名玩家角色：汉末年轻军中骑将，成年比例，略显疲惫但警觉，深色短襦与轻甲，暗红窄披风，旧皮护臂，腰间直刀，棕黑战马，马鞍旁挂竹制令牌和简易地图袋。第一人称画面中不展示完整角色脸部，而通过真实双手、袖口、护腕、武器、马缰、身体遮挡、呼吸和受伤动作保持一致；第三人称画面展示同一套服饰、动作和装备磨损；俯视画面用暗红披风、坐骑、军旗和队形确认身份。角色不是神化英雄，身体会受伤、会疲惫，装备有磨损，身份和权限通过服饰、令牌、随从与传令路径表现。
```

### 2.3 全局负面提示词

```text
现代建筑，现代服装，火器，科幻，蒸汽朋克，魔法光环，超自然能量，西式中世纪城堡，日式武士甲，夸张肌肉，塑料材质，过度饱和，霓虹灯，纯黑背景，海报排版，孤立角色展示，重复人物，额外肢体，错误手指，错误马腿，模糊，像素化，噪点，过度锐化，低清晰度，水印，品牌标志，无法阅读的大段文字，随机英文 UI，复制任何现有游戏角色、地图、技能图标或界面
```

### 2.4 UI 统一规则

```text
UI 是贴近世界的克制型游戏界面，不遮挡关键人物和战场信息。使用纸张、木牌、简洁线条、队旗形状和少量汉字标签表达来源、距离、权限、时效、命令状态、士气和阵型。不要使用现代科幻 HUD，不要堆满数值，不要让 UI 产生全知视角。每个 UI 面板都必须能和画面中的人物、文书、信使、沙盘或舆图对应起来。
```

### 2.5 三种视角切换基准

```text
视角切换是同一游戏状态的观察方式变化，不是进入不同玩法副本。
第一人称：镜头位于玩家真实眼高；优先表现双手、袖口、护腕、马缰、武器、文书、身体遮挡、呼吸和近距离人物表情。适合个人 ARPG、交涉、交接物件、感知敌意和战斗接触。
第三人称：镜头跟随玩家身体；优先表现玩家动作、坐骑、受击、亲卫保护队形、NPC 关系和空间障碍。适合移动、骑战、战斗阅读和剧情对峙。
俯视视角：镜头抬高但不变成全知地图；优先表现道路、地形、队伍间距、军旗、阵型和正在发生的战场流动。适合队伍调度、战役态势和多目标观察。
切换时保持角色位置、速度、朝向、受伤状态、命令状态、通信延迟、已知情报和世界时间连续；镜头不得生成玩家在当前位置无法获得的情报。提示词若未指定视角，默认生成第一人称版本，并可追加“同场景第三人称版本”或“同场景俯视版本”作为变体。
```

## 3. 静态关键画面提示词

以下提示词建议按编号顺序生成。九张参考图对应第一人称基准版本，生成 K02–K08 时，尽量把前一张图作为第一人称眼高、双手、袖口、武器、服饰、军旗和 UI 风格参考图。每张图都可在不改变世界事实的前提下生成第三人称和俯视变体；变体只改变镜头位置、可见身体范围和信息组织，不改变事件结果。除非明确要求第三人称或俯视，静态提示词默认使用第一人称。

### K01：身份与进入世界

**画面目标：** 表达“玩家首先是一个有身体、有身份、有位置的人”，不是直接进入全知战略地图。

```text
Use case: historical-scene
Asset type: 第一人称游戏开场关键帧，16:9 横构图
Primary request: [统一视觉基准] [统一角色锚点] 玩家刚从棕黑战马下来，第一人称眼高位于清晨汉末军营边缘；画面下方能看到一只扶住马鞍的手、磨损的护臂、缰绳和衣摆，另一只手自然垂在腰间直刀附近。近处有两名亲卫、木制军旗、拴马桩、粮袋和一名等待传令的士卒，玩家透过营门望向薄雾中的村落、道路和低矮山脊。远方世界只显示为可观察但不全知的信息，身体、马鞍和门框形成真实遮挡。画面边缘只有克制的个人状态、附近人物和可交互提示；没有完整战略地图。
Scene/backdrop: 清晨军营、湿土、木栅、道路、远处村落
Composition/framing: 第一人称眼高，双手、马鞍和门框位于近景，营门与远方道路形成视觉引导，留出少量 UI 空间
Lighting/mood: 冷晨光，薄雾，安静但有即将发生事件的压力
Constraints: 保持双手、袖口、护臂、坐骑和军旗锚点；表达真实位置、观察范围和身份权限；画面可作为后续 K02 的第一人称参考
Avoid: 全知地图，浮空战略图，英雄海报姿势，夸张特效
```

### K02：个人 ARPG 生活与交互

**画面目标：** 表达个人模式是全游戏持续底座，移动、交涉、关系和履职都发生在同一个世界。

```text
Use case: stylized-concept
Asset type: 第一人称游戏内截图式关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，第一人称双手在势力范围内的集市与驿站之间行走，正把一封封好的书信递给身穿朴素服饰的信使；信使的手接住书信，能看见封泥、纸张边缘和双方手指的距离。一名熟悉的女角色在檐下等待交谈，几名民夫搬运粮袋，远处有守门士卒和自己的暗红军旗。玩家没有打开宏观面板，画面保持即时 ARPG 操作感。小型 UI 只显示视线焦点、附近人物、书信状态和一条可交互提示，关系与治理信息通过人物、物件和现场行为表现。
Scene/backdrop: 汉末集市、驿站、木廊、粮袋、车辙和雨后泥地
Subject: 同一玩家角色的双手、袖口和书信与信使交互，周围人物各自有明确行为
Composition/framing: 第一人称近中景，书信交接和信使面部为焦点，女角色和粮运作为第二层叙事信息
Lighting/mood: 阴天柔光，生活感、关系感和职责压力并存
Constraints: 世界继续运行，人物不要像等待玩家点击的 NPC；UI 克制、可读、与书信和人物对应
Avoid: 静态角色选择界面，悬浮任务列表，现代城市，过多图标
```

### K03：敌意感知与即时战斗接触

**画面目标：** 表达战斗可主动发起，也可由敌意、伏击、追捕或攻击在个人行动中自然激活。

```text
Use case: stylized-concept
Asset type: 第一人称游戏内战斗截图式关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，在狭窄河滩道路上突然感知到伏击。第一人称视线贴近一名传令士卒，玩家一只手已经拔出直刀，另一只手挡在士卒前方；刀身、护臂和受惊马匹占据近景，前方两名敌对骑手从芦苇和土坡之间逼近，后方亲卫正在转身结成保护队形。尘土被踩起，但攻击方向、距离、掩体、军旗和队形仍然清晰可读，不出现独立竞技场边界。小型战斗 UI 显示当前危险来源、玩家身体状态、附近可知命令和一条传令状态。
Scene/backdrop: 河滩道路、芦苇、低土坡、浅水、远处村道
Composition/framing: 第一人称近距离视角，刀、护臂和传令士卒形成前景，敌我接触线清楚，亲卫在侧后方形成保护三角
Lighting/mood: 午后逆光夹杂尘土，突然、紧张、可判断
Constraints: 低魔历史质感；动作必须显示承诺、距离和方向；战斗结果可继续影响传令与战场事实
Avoid: 连招光效，竞技场计分板，敌人无限刷新，过度血腥，动作模糊
```

### K04：沙盘与舆图推演

**画面目标：** 表达玩家可以在 ARPG 世界里，与将领共同推演，使用已经抵达的战报形成计划，但推演不会直接改写远方事实。

```text
Use case: historical-scene
Asset type: 第一人称世界内沙盘会议关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，玩家站在营地木桌旁的沙盘和舆图前，第一人称双手正在移动一枚暗红木制军旗并压住被风吹动的舆图，与两名将领共同推演战术。桌面上有木制地形、粮道标记、渡口木牌、已拆封的斥候战报和带泥的信使竹简；一名将领指向已知山口，另一名将领复述命令并提出补给风险。玩家的袖口、护臂和腰间令牌进入画面，旁边能看到自己的马、亲卫、火盆和帐篷，远处营地继续活动。画面 UI 只显示已抵达情报的来源、时间、可信度和“计划/命令意图”，不显示未知地域的真相。
Scene/backdrop: 夜间军营指挥帐、沙盘、舆图、油灯、斥候战报
Composition/framing: 第一人称斜俯视近景，双手、沙盘、战报和将领手势同等重要，帐篷边缘形成身体遮挡
Lighting/mood: 油灯暖光与帐外冷夜形成对比，专注、有限信息、时间压力
Constraints: 沙盘是现实物件，不是悬浮 hologram；明确计划尚未执行；人物之间存在理解和权限关系
Avoid: 上帝视角全地图，发光路线，科幻投影，瞬间完成命令，堆满数值
```

### K05：经营统治与现场执行

**画面目标：** 表达经营统治不是脱离角色的后台菜单，而是责任人、资源、文书和执行过程的组织。

```text
Use case: historical-scene
Asset type: 第一人称经营统治工作层关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，在一座控制范围内的县城厅堂与仓场之间处理治理事务。第一人称双手翻阅账册、接过地方官递来的木牍，并在封泥上核对印记；前方是地方官、粮仓管事和护卫，桌上有账册、封泥、木牍和地图。背景能看见搬运粮袋的民夫、等待核验的车队和正在张贴公文的吏员。右侧只有半透明的克制型经营面板，显示“当前辖域、责任人、库存、运输中、待核查异常”，每项信息都能在现场找到对应人物或物件。玩家没有远程控制城外未知地区。
Scene/backdrop: 汉末县城厅堂、仓场、粮车、木牍、公文和民夫
Composition/framing: 第一人称室内中广角，双手和文书位于近景，责任人和资源流动清楚，面板靠边不遮挡现场
Lighting/mood: 午后斜光，秩序表面下有短缺与责任压力
Constraints: UI 只整理合法可知事实；治理决定必须经过责任人和执行；保留个人身体位置
Avoid: 现代管理仪表板，纯数字城市，资源凭空变化，全知远程操作
```

### K06：战争态势与通信覆盖

**画面目标：** 表达战争层可以被关注，但命令仍受势力范围、通信覆盖、传令路径和时效约束。

```text
Use case: historical-scene
Asset type: 第一人称战争态势关注层关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，玩家站在高地烽火台旁，第一人称双手按住铺在石台上的舆图，边听信使复述战报边关注持续战争。远处能看见数条道路、山口、烟柱和不同距离的军营，几名信使沿道路移动，近处的亲卫正在等待新的命令。舆图上只画出已知的战区、通信节点、最近战报和延迟中的传令路线，用暗红、灰白和青绿区分己方、未知和待确认状态。玩家的袖口、令牌和被风吹动的地图进入画面，世界没有暂停。
Scene/backdrop: 山地烽火台、远方战区、道路、烟柱、信使
Composition/framing: 第一人称斜俯视广角，双手和舆图在前景，远方战区作为可观察但不全知的背景
Lighting/mood: 黄昏风大，压迫、辽阔、信息不完整
Constraints: 不画全知敌军位置；命令路线必须有节点、时效和可能失败；面板与现实舆图对应
Avoid: 抽象 4X 地图，瞬移箭头，实时全局雷达，地图占满整个画面
```

### K07：战后摘要与继续生活

**画面目标：** 表达战斗和战役结束后，玩家不会被送回“重试界面”，而是继续生活、指挥、追查和承担后果。

```text
Use case: historical-scene
Asset type: 第一人称战后叙事关键帧，16:9 横构图
Primary request: 基于 K01 的同一玩家角色，雨后的战场边缘，第一人称双手扶起受伤亲卫，幸存的传令士卒把带泥的战报递到玩家手中；近处能看见湿透的纸、泥水、护臂和军旗杆，远处队伍正在重新整队、收拢军旗和搬运伤员。一名将领在视线前方等待玩家决定是追击、撤退、救援还是继续传达。画面一侧有半透明的战况摘要，按时间顺序显示“命令提出、传达中、已理解、执行结果、玩家获知”，并显示损失、士气、阵型和下一步可行动窗口。摘要是继续行动的入口，不是胜负海报。
Scene/backdrop: 雨后战场、泥地、倒伏木栅、伤员、整队士卒
Composition/framing: 第一人称中广角，双手、战报、亲卫和远处队伍形成一条因果线
Lighting/mood: 雨后冷光，疲惫、损失、仍有选择
Constraints: 不使用“胜利/失败”巨大字样；让结果、来源和后续行动可读；世界继续运行
Avoid: 读档/重试菜单，庆典式胜利画面，尸体堆积的血腥渲染，静止背景
```

### K08：剧情过场与世界事实承接

**画面目标：** 表达剧情线不是脱离玩法的电影，而是由人物关系、命令、战报和现场行动共同推动。

```text
Use case: historical-scene
Asset type: 第一人称剧情过场关键帧，21:9 电影宽画幅
```

## 3.1 同场景视角变体后缀

将以下后缀追加到任意 K01–K08 的 `Primary request` 末尾，用于生成同一时刻的不同视角版本。除镜头位置、可见身体范围和信息排序外，不得改变人物位置、世界时间、已知情报、命令状态、战斗结果或 NPC 行为。

### 第一人称基准

```text
视角变体：第一人称。镜头位于玩家真实眼高，必须看到与动作相关的双手、袖口、护腕、武器、马缰或身体遮挡；近距离人物和可触摸物件优先，不能出现完整玩家脸部或漂浮的第三人称身体。
```

### 第三人称变体

```text
视角变体：第三人称跟随。镜头位于玩家身后或侧后方的可达位置，展示玩家全身或半身动作、坐骑、受击、武器轨迹、亲卫队形和周围障碍；保持真实视线遮挡和镜头距离，不使用英雄海报构图，不增加第一人称无法知道的情报。
```

### 俯视变体

```text
视角变体：俯视战术观察。镜头抬高到能同时读出道路、地形、队伍间距、军旗、阵型和移动方向，但仍受玩家所在位置、观察范围、通信覆盖和已抵达战报限制；未知区域保持未知，不显示全局雷达、敌方真视野或抽象 4X 地图。
```

## 4. 视频与转场提示词

视频生成建议使用静态关键帧作为首帧/尾帧，先保证空间、角色和 UI 连续，再增加动作。不要让视频模型自行发明新的角色、武器、旗帜或地图。

### V01：个人行动到战斗接触

```text
生成一段 12 秒的第一人称实时游戏画面，使用 K02 作为首帧、K03 作为尾帧。0-3 秒，玩家双手在汉末集市边缘把书信交给信使，远处传来急促马蹄和芦苇晃动，玩家先转头观察而不是立即攻击；3-5 秒，玩家感知到敌意，手部拔刀，亲卫从日常队形转为保护队形，战斗 UI 只逐步显现危险来源和距离；5-12 秒，敌方骑手逼近，玩家视线跟随刀尖和敌人动作发生一次清晰、短促、可读的冷兵器接触，表现攻击方向、闪避、受击和地形影响。不要硬切，不要传送，不要暂停世界，不要加入新角色或新 UI。
```

### V02：沙盘推演到命令传达

```text
生成一段 15 秒的世界内实时游戏视频，使用 K04 作为首帧。0-4 秒，玩家与将领在沙盘前讨论已抵达的斥候战报，玩家移动一枚木制军旗，另一名将领复述计划；4-7 秒，计划被写成木牍并交给亲卫传令员，画面跟随传令员离开帐篷，沙盘不会变成全知地图；7-11 秒，传令员沿泥路骑马经过烽火台和粮车，途中受到天气、距离和敌情影响；11-15 秒，远处队伍收到命令并开始调整阵型，画面只显示命令抵达和执行开始，不展示瞬间完成的战果。保持人物、军旗、舆图、天气和 UI 一致。
```

### V03：战后摘要回到个人世界

```text
生成一段 12 秒的第一人称剧情游戏视频，使用 K07 作为首帧。0-3 秒，玩家双手阅读带泥战报，摘要按时间顺序显示命令传达和执行结果；3-6 秒，玩家抬头看向正在整队的亲卫和等待指示的将领，摘要缩到画面边缘；6-9 秒，玩家收起战报、扶伤员上马或选择向将领下达下一步行动，现场人物继续移动；9-12 秒，玩家视线回到双手、雨后道路和出发的传令员，世界保持实时运行。不要出现胜利/失败重试菜单，不要让背景停止。
```

### V04：三种视角实时切换

```text
生成一段 10 秒的实时游戏视频，表现同一场景中的三种视角切换。场景从 K03 的河滩伏击开始：0-3 秒保持第一人称，玩家看见刀、护臂、传令士卒和逼近的敌骑；3-6 秒镜头平滑拉到第三人称，显示玩家的拔刀动作、坐骑受惊和亲卫保护队形；6-10 秒抬升为受限的俯视视角，读出河滩道路、芦苇掩体、敌我间距、军旗和保护三角，然后回落到第三人称或第一人称。三次切换必须保持玩家位置、朝向、速度、受伤状态、敌意来源、命令状态和世界时间连续；俯视阶段不显示未知敌军、全局雷达或玩家当前位置以外的情报。不要硬切、传送、暂停世界或生成新角色。
```

## 5. 生成检查表

## 1. 需求结论

第一阶段角色采用**汉末写实风**，服务于“玩家骑马行动、亲卫传令、一营三队执行守城命令、敌我阵型和士气发生变化”的完整闭环。角色必须在第一人称、第三人称和俯视视角下保持可信的比例、服装构造、材质反应和动作重量感。

角色资产不能只做外观模型。每个可运行角色都必须同时交付：

1. 可用于 UE 5.8 的骨骼网格、材质、LOD、碰撞和 Socket；
2. 与 Presence、Combat、Body、LifeState、Equipment、Status、Morale、Organization 和 Objective 对接的稳定组件接口；
3. 能表达待机、移动、传令、攻击、受击、失能、溃退、重整和暂停冻结的动画状态；
4. 角色身份、阵营、队伍、指挥层级和装备状态可从数据和投影重建，不把事实写死在材质颜色或蓝图变量中。

## 2. 视觉目标与边界

### 2.1 写实风硬约束

- 服装、盔甲、武器和坐骑装备以东汉末年为参考，优先使用可解释的结构、缝制、绑扎、铆接、磨损和污渍；不使用现代扣件、塑料、拉链、科幻结构或无依据的西式骑士装饰。
- 角色采用真实人体和马匹比例，衣物、札甲、披帛、腰带、鞍具和武器应有厚度、重量和碰撞关系；不得使用玩具化比例、纯色块身体或刻意棱角化的 Low Poly 外形。
- 写实不等于每个单位都做电影级高模。近景角色保留面部、手部、装备连接和布料层次，中远场通过 LOD、材质实例和动画简化维持同一套写实视觉语法。
- 阵营识别使用旗帜、队标、臂带、披风边、盾面和局部配色，不给整套服装覆盖高饱和纯色；敌我差异必须在无 UI 时也能辨认。
- 角色不使用血腥夸张的永久伤口作为主要识别手段；受击、失能、溃退和死亡通过动作、姿态、装备损坏、旗号和状态投影表达。

### 2.2 镜头优先级

| 镜头 | 必须看清 | 角色质量要求 |
|---|---|---|
| 第一人称 | 马颈/缰绳、武器、手部、冲锋方向、近距离命中反馈 | 玩家手臂和武器无穿模；马匹颈部、鬃毛、鞍具和缰绳有真实接触关系 |
| 第三人称 | 玩家骑将、亲卫、敌方指挥官、军旗和冲锋姿态 | 玩家与关键角色 LOD0/LOD1 轮廓稳定；动作重心和转向可信 |
| 俯视/远景 | 队伍归属、阵型、军旗、传令方向、溃退与重整 | 角色可用批次/实例化投影承载数量，但旗号、队形和移动状态不丢失 |

## 4. 模型、服装和装备需求

### 4.1 玩家骑将与关键角色

- 玩家骑将：东汉末年地方军政首领的实用型甲胄，包含头盔、护颊/护项、札甲或皮甲层、腰带、护臂、靴、披风或身份标识、主武器和备用武器。
- 敌方将领：与己方共享时代语汇，但在头盔轮廓、披风/旗号、护具磨损和武器组合上形成阵营差异；不得使用“红色换皮”作为唯一差异。
- 营指挥头目和三队队长：通过旗帜、令牌、头盔缨饰、腰牌、武器和局部甲片提高指挥层级可读性；装饰不能妨碍骨骼变形和骑乘动作。
- 关键角色脸部只需支持第三人称近景可读，不要求影视级口型；眼睛、眉骨、鼻口和发际线不能在 LOD0 中出现明显贴图平面感。

### 4.2 普通士兵、民夫和伤员

- 步兵至少提供短兵器、长杆兵器和弓/箭囊三种装备组合；武器必须有独立 Socket 和碰撞规则。
- 己方与敌方步兵用材质实例、头盔/护具、盾面、旗号和磨损差异区分；不同队伍再使用低饱和局部色带区分，不改变基础身体材质。
- 民夫/工匠使用麻布、短袍、围裙、工具袋、木工/石工工具等生活化元素；不穿战斗甲胄，不携带军旗。
- 伤员保留原角色身份、装备和阵营信息，增加包扎、血迹/尘土和行动受限状态；不能用单独一套“红色躺尸模型”替代。

### 4.3 坐骑和驮畜

- 玩家战马必须交付鞍、缰、胸带、尾带、马镫和可见骑乘 Socket；鞍具受力位置、缰绳连接和骑手腿部接触不能漂浮。
- 战马提供站立、呼吸、行走、快走、奔跑、急停、转向、受击、失能和死亡所需骨骼与动画接口；鬃毛和尾毛优先使用稳定的骨骼/卡片方案，避免高成本动态毛发阻塞首版。
- 驮马/驮畜需支持负载变化：空载、粮袋/木料/石料至少三种可切换挂载组合；挂载由资源状态投影驱动，不把货物复制成三套动物模型。

## 5. 骨骼、动画和运行接口

### 5.1 骨骼与导入

- 人形角色首选一套项目统一基础骨架；新增骨骼必须说明无法复用的原因，并提供重定向映射表。
- 骑乘角色与战马分离为两个 Skeletal Mesh，通过稳定 Socket 连接；骑手根骨、马鞍和相机锚点不能写死在某个外部资产的绝对路径中。
- 统一使用厘米单位、Z 轴向上、角色面向项目约定的前方；导出前提供静止参考姿势、骨骼层级、根骨位置和比例说明。
- 每个角色必须提供 Physics Asset、简单胶囊/身体碰撞、武器 Socket、手部握持 Socket、骑乘 Socket 和受击区域标识；逻辑体与视觉网格可独立查询。

推荐 Socket：

```text
S_Weapon_Main
S_Weapon_Secondary
S_Shield
S_Flag_Back
S_Hand_R
S_Hand_L
S_RiderRoot
S_Camera_ThirdPerson
S_Camera_FirstPerson
S_Hit_Head
S_Hit_Torso
S_Hit_Limb
```

运行接入遵循[08 全量 Owner 节奏矩阵](08-基础设施与Owner建设总计划.md#112-全量-owner-的-ue-协作与节奏矩阵)：近场移动、命中、Body、LifeState、装备、效果和士气在获准的 UE Runtime 协作，执行器采用 UE 原生能力；[ESM](01-Paralls现有Owner与接入分析.md#9-esm-复用边界与迁移检查)只复用适合的合同。玩家视野内已激活 Agent 的语义动作由当前有效意图持有者控制；本地受击、体力约束和强制身体反应及时执行，但不得擅自替 Agent 产生新的自主策略。

### 5.2 第一阶段最小动画集

| 类别 | 必需动画 | 适用角色 |
|---|---|---|
| 基础移动 | Idle、呼吸、转身、Walk、Run、Stop、受阻/绕行 | 全部人形 |
| 骑乘 | Mount、Dismount、Ride Idle、Ride Walk、Ride Run、Ride Turn、Ride Stop | 玩家骑将、骑兵 |
| 命令与传令 | Observe、Signal、Receive Order、Deliver Order、Acknowledge、拒绝/迟疑 | 玩家、亲卫、队长、传令兵 |
| 战斗 | Weapon Ready、Attack 1—2、Block/Guard、Hit React、Stagger、Knockdown | 战斗角色 |
| 状态 | Wounded、Carry、Retreat、Rally、Surrender、Death/Disable | 战斗角色、伤员 |
| 阵型 | Form Up、Hold、Advance、Charge、Break Formation、Reform | 三队、敌军 |
| 生活工作 | Carry、Load、Unload、Forge、Treat、Draw Water、Idle Work | 民夫、工匠、医舍角色 |

攻击动画可以先提供少量可验证动作，但必须保留动作标签、武器类型和命中证据接口；动画结束不等于 Combat 已结算。暂停时所有动画、马匹和队伍状态冻结，恢复后从同一世界时间继续。

## 6. 材质、颜色和表现规则

- 使用 PBR 材质，金属、皮革、木材、织物、骨/角、泥尘和血迹必须有可区分的粗糙度与法线响应；不以单一纯色材质覆盖整个人物。
- 玩家和关键角色允许使用 4K 近景贴图，但必须提供 2K/1K 降级版本和纹理流送设置；中远场角色优先共用材质图集和材质实例。
- 角色脸部、手部和武器边缘保留适度磨损；盔甲和服装磨损要遵循角色身份、战斗经历和环境，不使用随机噪声替代制作。
- 己方主识别色使用青蓝/青绿系局部布料、旗带或臂带，敌方使用暗红/赭色局部布料、旗带或臂带；场景中的建筑和地面不得大面积使用相同阵营色。
- 军旗、队旗和令牌属于角色识别的一部分，旗面、旗杆、挂点和阵营字段必须分离；旗帜物品存在/数量读取 Inventory，装备挂接读取 Equipment，位置读取 Presence，部队归属读取 Organization；损坏按实体登记读取 Equipment 或 Facility。Morale 结算军心后果，Objective 消费目标结果，两者不写旗帜物理状态。

## 7. 命名、目录和资产包

## 8. 制作批次和验收闸门

### 批次 A：玩家骑将与战马

交付玩家骑将、战马、第一/第三人称相机锚点、骑乘最小动画集、武器 Socket、碰撞和一套近景材质。

验收：骑乘、转向、急停、冲锋、受击和下马在 PIE 中成立；第一人称无手臂/武器/马颈穿模；第三人称相机不漂移；暂停和恢复不丢失位置、装备或动画状态。

### 批次 B：亲卫、营指挥头目和敌方将领

交付关键角色外观、军旗/令牌、命令和传令动画、近景 LOD、材质实例和角色登记数据。

验收：玩家附近可辨认亲卫和两方将领；`request_aid`、`defend_city`、`hold_gate`、`patrol_wall` 至少各有一次传令路径；指挥头目失能后继任不改变角色身份和装备状态。

### 批次 C：三队步兵、敌军和传令兵

交付己方三队、敌方步兵、骑兵/护卫和传令兵的变体、阵型动作、受击/失能、溃退/重整和中远场 LOD。

验收：俯视能读出三队、敌军、军旗和阵型变化；第三人称能看懂冲锋、接触、受击、溃退和重整；同一角色从近层切到远层不会换阵营、换武器或重置位置。

### 批次 D：居民、民夫、工匠和伤员

交付市区、里区、粮仓、木厂、石料点、铁匠坊和医舍所需角色，以及运输、装卸、生产、收治和担架动作。

验收：资源运输、生产停工、伤员入舍和民夫征召在场景中可见；角色状态由 Owner receipt 和投影驱动，不以一次性蓝图变量伪造。

### 批次出口规则

1. 骨骼、材质、LOD、碰撞、Socket、动画、manifest 和 `/Game/...` 路径齐全后，资源才可从“候选”进入“待验证”；
2. 每批次至少提供一名角色的 UE 导入日志、资产路径、角色/Actor 数量、PIE 状态和第一/第三/俯视截图；
3. 任一批次出现穿模、错骨、朝向错误、材质流送峰值或动画与事实不一致，暂停扩张，回到最近一个可运行版本；
4. 未通过 UE 和 PIE 验收的角色不得覆盖现有 `/Game/Battle` 资产，也不得标记为已用于 Demo。

## 9. 角色资产验收矩阵

| 类别 | 验收项 | 通过标准 | 证据 |
|---|---|---|---|
| 写实表现 | 比例、服装构造、材质反应、装备连接 | 三视角下无玩具化比例、纯色块和明显漂浮；关键材质可区分 | 角色转台图、材质球、PIE 截图 |
| 骨骼导入 | 骨架、根骨、比例、朝向、重定向 | 统一骨架或有映射表；角色朝向与项目一致；无错骨 | 导入日志、骨骼树截图 |
| 骑乘 | 骑手/战马连接、鞍具、缰绳、相机 | Mount、Ride、Dismount 可重复；第一/第三人称无穿模 | PIE 录像、相机截图 |
| 动画 | 移动、命令、攻击、受击、失能、阵型 | 动画标签与状态一致；暂停冻结；恢复不跳帧 | 动画日志、PIE 截图 |
| 玩法接口 | Socket、碰撞、受击区域、Gameplay Component | Combat、Presence、Equipment、Body 能定位并返回结构化结果 | Query/receipt 日志 |
| 阵营识别 | 旗号、队标、局部配色、队伍轮廓 | 无 UI 时可辨玩家、亲卫、三队、敌军和关键将领 | 三视角截图 |
| LOD/性能 | LOD 切换、材质流送、同时数量 | 无明显跳变；达到预算或记录偏差和止损动作 | `stat`/Insights 报告 |
| 资源合规 | 来源、许可证、文件大小、面数、纹理、回退 | 资源登记完整；未验证资源不覆盖正式资产 | 资源登记表、导入记录 |

## 10. 资源登记字段

每个角色、坐骑、动画包和外部服装组件按[美术资源管理 README](../../art_resources/README.md)登记通用治理字段；本需求额外要求记录：

- 身体/装备三角面数、骨骼数量、动画数量、材质槽、纹理分辨率、LOD 和 Physics Asset；
- 是否含面部、手部、骑乘、武器、旗帜和受击区域；
- 目标角色层级、使用场景，以及与既有角色的替代关系；
- 是否保持现有 Gameplay Component、碰撞接口、相机锚点、命令来源和状态事件。

## 11. 本轮不制作

- 全县数千名居民的独立面部、独立服装和独立生活动画；
- 影视级毛发、布料、肌肉模拟、复杂面部捕捉和高成本血液特效；
- 没有命令、战斗、运输、生产、医疗或身份识别用途的装饰性角色；
- 未登记来源或许可证不清晰的外部角色包；
- 为每个阵营复制一套骨架和动画，或把逻辑状态写进单独的换皮蓝图；
- 用静态模型、纯色方块或 Low Poly 代理冒充近景角色成品。

## 12. 完成定义

第一阶段角色素材只有同时满足以下条件才算完成：

1. 玩家骑将与战马能在三种视角下稳定移动、转向、冲锋、受击和暂停恢复；
2. 亲卫、营指挥头目、敌方将领、三队、敌军和传令兵能表达命令传递、阵型、士气、受击、失能、溃退和重整；
3. 居民、民夫、工匠和伤员能支撑运输、生产、医疗和场景生活的最小可见闭环；
4. 所有角色都使用写实比例、真实构造和 PBR 材质，远层代理只做性能降级；
5. 骨骼、动画、Socket、碰撞、LOD、材质流送和 `/Game/...` 路径经过 UE 5.8 导入和 PIE 验证；
6. 角色状态能从 Owner receipt、投影和回放重建，不创建第二套世界事实；
7. 每个角色版本有 manifest，且资源登记、许可证、依赖图、SHA-256、截图、日志、Actor/资产数量和回退位置齐全。

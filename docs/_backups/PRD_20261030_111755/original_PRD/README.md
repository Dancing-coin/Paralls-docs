## 2. 必须共同遵守的边界

1. Owner 是事实写权边界，不是编程语言或进程边界。近场实时链由获准 UE Runtime 协作，不能逐次扣血、扣体力都等待 Python/LLM。
2. Body 管生命、体力、伤势与身体限制；LifeState 管存活/倒地/濒死/死亡；Status 管效果实例。生命归零不自动宣布死亡，激活与卸载也不是生命周期转换。
3. 军旗、城门、器械、弹药按事实归属结算。城门政策归 Government，机械开闭/门闩/登记设施完整度归 Facility，通行占用归 Presence，控制归 Territory，合法产权归 Ownership。Inventory 与 Facility 的实时依赖子域须在 D/V2 正式接入。
4. 动画和预测不冒充事实。Owner 的正式确认需要可靠事件提交、revision/CAS、幂等、receipt、outbox、replay/recovery 及 epoch fencing；跨提交端按开放义务恢复，不宣称全局原子回滚。
5. Agent 保留自主意图权。受击、体力耗尽等本地强制约束及时执行；断线、意图过期或权限失败不能自动授予执行器新的自主策略或领域写权。
6. 世界真相、角色记忆和表现分账。内部 receipt/调试日志不自动成为玩家知识，地图反馈依靠观察、传令和报告等真实手段。
7. 单人暂停为完整时停：世界推进、物理、动画、命令传达、Agent、Owner 提交、语义激活/交接与新信息暴露冻结；UI 可以编辑命令草稿。底层资产 IO 可继续，但不得因此改变世界事实或写权；恢复后重新校验异步结果。

本轮审查原有 19 份 PRD，修订其中 18 份，通用模板保持原样；另增本文作为统一入口。修订覆盖 Owner 名单、阶段门、模型边界、UE 实时要求、ESM 迁移、暂停、断线与受限信息规则。最终静态核验覆盖现有 20 份文档，134 个本地文件链接和 37 个章节锚点均有效，代码围栏闭合、UTF-8 解码正常；05 的领域注册表、08 的最终名单与 UE 协作矩阵均为同一组 23 个 Owner。

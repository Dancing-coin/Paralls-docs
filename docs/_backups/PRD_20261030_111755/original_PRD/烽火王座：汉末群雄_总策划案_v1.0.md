## 0. 文档定位

本案规定游戏最终想成为什么、世界如何连续运行、玩家如何获得和失去权力，以及战争、经济、政治和角色如何在同一条时间线上互相影响。它不等同于第一章 Demo，也不要求所有章节同时实现。

本案的实现约束是：复用 Paralls 已有的 Gameplay EventStore、领域 Owner、receipt/replay、角色 L1-L4、Laya 快循环、Siming 高层催化和 PopulationPlanner 分级模拟；新增内容只能补充缺失领域或组合既有 Owner，不能再造一套平行世界真相、事件总线、调度器或万能结算器。

本次修订重排了玩法阅读路径，补充目标玩家、产品差异、分层循环、决策取舍、反馈规范、Demo 验收和验证指标。新加的验收阈值属于待实测的策划建议，不代表当前版本已经实现或通过测试。

## 1. 游戏概述与体验目标

**全战式战略棋盘 + 骑砍式战场人生 + 汉末君臣部曲政治 + 可被截断和误读的真实通信。**

玩家既是一个有身体、有武力、有记忆和有限视野的人，也是某个组织、军队、郡县或势力的代理人。玩家可以亲自骑马冲阵、经营一座城、统率军队、经营盐粮网络、任命手下或流亡求生；这些身份不是互斥职业，而是由当前官职、授权、领地、部曲、声望、组织关系和所在位置共同推导出来的状态。

游戏追求的不是“点击后全世界立即服从”，而是让玩家感到：命令要抵达，部下要理解，资源要流动，身体会受影响，人物会记仇或拥护，结果要经过世界中的领域结算。玩家没有上帝视角，远方世界继续运行，但玩家只能通过本人感知和合法通信逐步知道它。

### 1.1 核心体验陈述

> 在这个游戏里，玩家感受到自己以一个有身体、有身份、受权限与通信约束的人身处乱世；通过亲自冒险、委派组织、调配资源和经营关系，在有限信息与有限时间中争取影响力。每次成功都能追溯到命令、人物响应和领域结算；失败会留下可见代价，并改变之后可用的身份、关系和资源。

玩家承诺由四个可观察结果兑现：

1. **我能亲自改变局部战局：** 骑乘、冲锋、视角切换和战场位置能改变局部接触，不会自动赢下整场战争。
2. **我的命令有组织过程：** 玩家能看到命令由谁发出、经过谁、是否抵达、谁接受或拒绝，以及部队最终做了什么。
3. **我的安排能在离场后继续：** 预案、代理人、训练、士气和补给决定军队如何自治；失控时能追溯原因并重新介入。
4. **世界不会替我保管成功：** 资源、名分、信任和控制需要持续维护；死亡或失势改变承接条件，不抹去已经发生的历史。

### 1.2 目标玩家与内容边界

| 维度 | 目标取向 | 对设计的影响 |
|---|---|---|
| 受众 | 偏好历史战争、策略模拟、角色扮演与组织经营的 PC 玩家 | 同时提供即时操作与可委派的宏观管理；默认界面克制，细节可展开 |
| 年龄/内容 | 面向能接受战争、伤亡、囚禁、权力斗争和角色死亡的玩家；建议以青少年以上为目标，最终分级待平台与发行规则确认 | 暴力重点表达战场结果与政治后果，不以血腥细节作为卖点；不预设成人向内容 |
| 核心动机 | 指挥取胜、塑造角色、建立组织、改写历史 | 每种动机都必须影响同一世界状态，避免彼此割裂的独立模式 |

### 1.3 市场竞品分析与差异

下表是玩法参照，不是已完成的市场调研；只借鉴类型表达，不复制其 IP、角色、剧情或美术资产。

### 1.5 游戏简介

玩家从一个拥有有限身份和权限的汉末代理人开始，在连续世界中骑马、指挥、经营和结交。玩家的命令必须经过通信和组织链，资源必须经过生产、运输、市场和消费，角色会根据记忆与利益形成意图，最终事实由对应领域 Owner 结算。第一章用一场短时骑将冲阵验证这套体验的最小闭环，后续再扩展到治理、经济战、继承与历史分岔。

## 2. 核心玩法与决策循环

### 2.1 三层循环

**即时循环（数秒到数分钟）：**

```text
观察局部威胁与命令状态
→ 选择移动/冲锋/下令/护卫/撤退
→ 承担位置、暴露、时间或组织机会成本
→ 观察接触、传令、阵型、士气和目标反馈
→ 依据新态势继续行动或改令
```

**会话/战役循环（数分钟到一个阶段）：**

```text
查看可信情报和组织风险
→ 设定目标、政策、预算、授权和预案
→ 行军、交涉、调运或亲自介入
→ 处理战斗、市场冲突或政治危机
→ 领域 Owner 结算并给出损失、收益与拒绝原因
→ 恢复、治理、训练、补给、继任
```

**长期循环（数个战役阶段）：**

```text
争取职位与承认
→ 扩大代理、领地和供应网络
→ 建立事实统治并承担维持成本
→ 面对继承、背叛、历史压力和对手策略
→ 选择保全、扩张、称霸、拥立或改写秩序
```

三层循环共用角色、组织、资源、历史和世界时钟。成长不能让上层决策脱离下层事实：再高的职位也需要命令可达、代理愿意执行、资源能够抵达。

### 2.2 关键决策与代价

重要决策必须在承诺前展示玩家合法可知的成本、主要风险和可能结果类别；结果需持续改变后续选择，不能只有即时加减分。

| 决策 | 选项与取舍 | 决策前可知信息 | 反馈与持续后果 | 失败边界 |
|---|---|---|---|---|
| 亲战还是留在指挥位置 | 亲战能改变局部接触，但暴露玩家、拉远命令距离；留在指挥位置更易观察和传令，但放弃个人冲击 | 当前命令、敌我阵型/士气、玩家位置和已知目标 | 接触、伤势、士气/阵型、命令时延和目标控制变化 | 玩家不应仅靠个人冲锋替代三队协作；遭到不可见攻击时必须有来源可追溯 |
| 执行/改写/拒绝上级目标 | 执行可维持信任和资源支持；改写可争取局部机会但可能失去时机；拒绝保留部队或个人但产生抗命记录 | 授权范围、目标期限、所需资源、已知上级关系 | 目标得失、信任、军纪、声望和未来授权分别结算 | 委派目标不是硬锁；系统不得只用“任务失败”遮蔽政治代价 |
| 攻击军用供应还是压迫城市市场 | 军用断供较慢但平民代价低；城市压迫效果强、影响范围广，却提高合法性和报复风险；稳定供给消耗库存/现金但可能换来承认 | 已掌握的库存、路线、报价/成交报告、情报来源与时效 | 供应、价格、身体/劳力、组织合作、军事持续力逐层反馈 | 不可显示无来源的敌方库存全知；不得用单一“混乱值”替代因果 |
| 亲自处理还是委派代理 | 亲自处理可控制关键细节但占用时间/位置；委派可同时处理多线，但受权限、能力、预算和代理意图限制 | 代理职责、政策、预算、风险、当前通信状态 | 代理行动、部分成功、拒绝、延迟和信任变化可追溯 | 委派不是跳过模拟的自动成功按钮；玩家可推翻决定但承担关系代价 |
| 争取名分还是扩大个人控制 | 借朝廷/世族名分可得秩序和人才，但须让渡自主；壮大直属部曲可提高直接控制，却扩大军饷和继承风险 | 公开承认、关键组织支持、资源负担和竞争者态势 | 任命、征收、动员、代理覆盖和统治稳定变化 | 统治力按辖域和领域成立，不是可永久持有的万能属性 |

### 2.3 决策信息与反馈规则

- 玩家能看到**事实、推断和未知**的区别。情报卡显示来源、`known_time`、可信度和过期程度；推断不得伪装成确认事实。
- 命令至少反馈“待传递、已送达、已接收、执行中、拒绝、过期”及原因；“已下达”不能冒充“已执行”。
- 战斗反馈至少区分接触方向、是否命中/被阻、队伍阵型状态、士气区间、目标控制状态和关键指挥者状态。不同状态要有稳定的视觉/音频编码，不能只依赖颜色。
- 关键风险应在行动前后各给一次可辨认线索：例如冲锋路线危险、队伍无法接令、军旗受威胁、运输延误。允许失误，但不允许核心损失没有可学习的因果证据。
- 反馈强度服务可读性：关键接触优先于环境装饰；镜头震动、暂停帧和音效需可控，不能遮挡下一条威胁或命令结果。

### 2.4 玩家行为与操作关注

玩家不是切换职业，而是在同一身份下切换关注和介入强度。常见动作包括移动/观察、骑乘冲锋、选择目标、提交语义命令、检查传令状态、切换已训练预案、授权代理、查看情报、管理资源和关系、接受或拒绝关键请求。每个动作都必须说明改变的是“玩家位置/注意力、命令意图、组织授权还是领域事实”，避免 UI 点击越过世界规则。

### 2.5 数值设计框架

本案定义可调参数和状态边界，不在缺少原型数据时伪造最终平衡数值。每个可见数值都要回答它读取什么事实、由谁结算、在哪个节奏更新、玩家能通过什么行为改变。

| 参数组 | 当前策划框架 | 主要调节手段 | 定稿条件 |
|---|---|---|---|
| 士气 | 0–100 连续值映射 `steady / shaken / wavering / routing`；骑将切片参考阈值 75/45/20 | 伤亡、侧翼/后方威胁、旗帜、指挥官、疲劳、补给、训练 | 通过灰盒战斗记录校准状态停留时间和撤退可读性；阈值为切片候选，不是完整游戏最终数值 |
| 阵型 | 离散状态 `formed / compressed / disrupted / flanked / rear_threatened / routing` | 接触方向、单位间距、训练、士气和命令/预案 | 状态切换能被玩家看懂，且不会因单帧噪声反复跳变 |
| 命令 | 每条命令有 issuer、target、权限、有效期、路径、预案版本和 expected revision | 传令距离/中继、通信质量、预案、指挥官与队伍状态 | 命令失败可重复测试；延迟能改变决策而不沦为纯等待 |
| 补给与资源 | 以库存、预留、消耗速率、运输容量/时长/风险、有效供应量和需求表示 | 生产、征用、交易、路线保护/截断、配给、替代品 | 账面库存与有效可用量分开；玩家能从行动记录解释短缺 |
| 身体与劳力 | 需求压力、疲劳、疾病风险、有效能力和恢复时间分层 | 获得/消费、工作强度、季节、疾病、休整与照护 | 重大后果有足够持续时间和中间反馈；不以短期单点短缺直接判死 |
| 影响力/统治力 | 按对象群体、领域、辖域和时间分层，不合并成万能全局分 | 名分、信任、利益、能力声望、信息触达、执行网络 | 激活和失活使用不同门槛/持续时间，避免状态闪烁与一事全域生效 |

最终数值表、成长曲线、兵种伤害/防护和资源单位换算属于原型与战役阶段的平衡工作；要由自动化用例和可重复战斗记录共同确定。

### 2.6 核心指标定义

第一阶段不使用商业留存或付费指标评判核心玩法。以下为**建议验证阈值**，需在试玩中记录并调整：

| 指标 | 建议阈值/记录方式 | 判断目的 |
|---|---|---|
| 首次命令成功率 | 5 名首次试玩者中至少 4 人在 30 秒内发出任一命令，并能看到经过的传令节点 | 操作入口和命令链反馈是否清晰 |
| 战术因果理解 | 至少 4/5 人能指出一次阵型或士气变化的直接原因 | 反馈是否能解释命令和冲锋的后果 |
| 命令差异可辨 | 每位试玩者至少使用两条语义命令；自动化用例验证 `10/22/34` 指向正确分队 | 三条命令是否有可读且可验证的不同作用 |
| 关键目标理解 | 至少 4/5 人能在 5 分钟内说出当前关键目标及状态 | 目标优先级是否能被玩家感知 |
| 自治信任 | 玩家离开指挥范围后，试玩者能观察到部队按预案继续行动，并说出其依据 | “离场后世界继续”的反馈是否可信 |
| Demo 完成时间 | 记录从进入战场到结果收束的时间，参考区间 3–8 分钟 | 节奏是否符合一次短时验证切片 |
| 再玩意愿与问题 | 试玩后记录是否愿意再试一次、最困惑步骤和主观原因；不以单一评分替代访谈 | 判断是否存在有意义的第二种选择和清晰的改进点 |

样本规模很小，只用于早期发现问题，不代表市场验证或统计显著结论。失败率、命令选择分布、重试次数和测试环境均需与原始观察一并保存。

## 3. 设计支柱

1. **连续世界：** 战略、行军、战斗、经济和角色生活共享一条世界时钟与状态链。空间可以分层加载，时间和事实不能断裂。
2. **角色即代理人：** 玩家保留武力和人格连续性；统治、指挥、亲征、经营和流亡是同一角色在不同权限与关注焦点下的操作状态。
3. **权力可达而非全知：** 权限决定“能不能下令”，通信决定“命令能不能抵达”，影响力决定“对方愿不愿意执行”，领域 Owner 决定“结果能否成立”。
4. **军队自治：** 玩家离开后，部队按预案、继任链、训练、士气和补给继续行动；玩家只有在拥有权限且信息能抵达时才能重新介入。
5. **资源是战争：** 盐、粮、铁、马料、钱、工匠、运输能力和市场信誉共同决定军队能否行动，经济战通过供应链和人物选择产生军事与政治结果。
6. **世界事实与主观认知分离：** 世界真相账、角色记忆账和世界表现账互不冒充；司命可以制造压力和机会，不能替领域 Owner 宣布结果，也不能替角色决定信念。
7. **失败延续人生：** 失利、受伤、被俘、失势和死亡会改变控制角色和资源结构；只有没有可承接角色时才结束势力或本局。
8. **历史是压力点：** 默认历史事件有发生倾向，但玩家可以通过军令、情报、外交、经济战和亲战改变时间、参与者和结果。

### 3.1 题材、开局与玩家路线

- **题材基调：** 史实骨架、演义气质、原创细节；写实低魔，不复刻现有三国游戏的人物造型、UI 或数值表达。
- **火药分支：** 默认关闭，属于架空长线或特定后期剧本开关。
- **首个完整战役候选：** 196—198 年兖豫地区沙盒，控制在五座城池/坞堡左右，先验证小范围势力互动。
- **可选历史势力：** 曹操（屯田、强弩、朝廷名分）；吕布（突骑、陷阵、部曲不稳）；袁术（世族财力、杂兵基础、僭号风险）。派系差异来自制度、资源、人才和组织关系，不为每个派系复制一套兵种。
- **默认玩家角色：** 原创代理人，可依附、服务、受任、背叛或取代历史势力；史实君主直接开局属于后续模式。
- **晋升可能：** 校尉/都尉 → 郡守/中郎将 → 州牧/将军 → 诸侯/霸府。这是由任命、军功、承认、领地、组织和事实控制共同形成的政治过程，不是固定职业等级条。

### 3.2 季节与行动节奏

第 2 节的循环在连续世界中运行，不以固定回合为时间推进门槛。季节用于组织年度生产和征募节奏：春耕、夏征、秋战、冬训；玩家可以在任何季节发动行动，但要承担相应的粮秣、劳力、天气、道路和民心代价。

### 3.3 系统详细设计索引

| 玩法系统 | 规则与玩家动作 | 事实 Owner/边界 | 详细章节 |
|---|---|---|---|
| 身份、权限与通信 | 判断玩家能否发令、信息能否抵达、结果是否可追溯 | 组织/通信/领域 Owner；玩家身份不能越权写事实 | 第 5、7、18 节 |
| 战争与军队自治 | 目标开放、预案、阵型、士气、继任和关键目标 | UE/军事状态 Owner；角色只提交候选意图 | 第 7、8、20 节 |
| 资源网络与经济战 | 生产、库存、运输、市场、消费和政策取舍 | 资源/生产/市场/组织 Owner 组合结算 | 第 9–10、16–17 节 |
| 角色、政治与历史 | 记忆、关系、承认、继承和历史压力 | 角色智能体/司命/对应领域 Owner 分工 | 第 11–15、22–23 节 |
| 实现接合 | revision、幂等、receipt、回放、断线回退 | Paralls 既有底座和新增适配器 | 第 16、23 节 |

## 4. 世界与时间模型

### 4.1 连续时钟

战略代理、行军实体、战术战场、市场结算、角色需求和通信传递共享同一 `world_ts`。远处使用低细节代理，接近玩家时展开为中场行为种子或近场角色/战场实体；展开不重置时间，不复制身份，也不重新创造事实。

单人模式支持暂停、慢速和加速。暂停只冻结世界状态、命令传递、情报更新和已知信息；不会在暂停中刷新斥候报告、扩大视野或完成远处结算。多人或合作模式未来取消真正暂停，只保留慢速规则或房主控制的有限暂停。

### 4.2 三本账与三个时间

所有重要事实遵循 Paralls 三本账：

| 账本 | 记录 | 禁止冒充 |
|---|---|---|
| 世界真相账 | 领域 Owner 已承认的资源、伤势、库存、产权、组织、战斗和生命事实 | 角色猜测、脚本预演、表现刷新 |
| 角色记忆账 | 某角色亲眼所见、收到、推断、相信、计划和记住的内容 | 全局事实镜像 |
| 世界表现账 | 当前 UE 加载、显示和可交互的局部投影 | 权威结算 |

事件必须区分：

- `event_time`：事实发生时间；
- `known_time`：角色合法得知时间；
- `presented_time`：玩家或 UE 显示时间。

玩家离开区域后保留最后已知状态，显示时间戳、来源、可信度和过期程度；失联越久，状态越模糊。玩家不会因为打开地图而获得没有传到自己耳边的事实。

### 4.3 分层连续性

远处战斗仍运行同一套核心规则的低细节代理，至少推进：命令状态、军旗、阵型、士气、补给、撤退和指挥继任。玩家实际到达或随军同行并满足进入权限后，战斗才展开为可操控战场。玩家只能通过战报、斥候、传令和观察获得远处信息，不能远程跳转视角处理所有事务。

## 5. 玩家身份、模式和权限

### 5.1 身份是推导状态

玩家的当前身份由客观条件自动推导：官职、领地、组织归属、上级关系、部曲登记、声望、名分、所在位置、军队编制和授权记录共同决定。UI 的“统治模式”“行军模式”“指挥模式”“战斗模式”只是当前关注和可操作界面，不是互斥职业。

玩家是一方诸侯时仍可御驾亲征；玩家在别人的军队中任职时仍保留个人武力，但不能因此取得该军队指挥权。切换模式不扩大权限，原职责由授权手下、预案和继任链继续执行。

### 5.2 四类权限来源

1. **职务权限：** 官职、军职、领地和正式任命提供的范围。
2. **上级授权：** 可撤回、可过期、带辖域和目标限制的授权。
3. **权限所有者委托：** 当前军队、部曲或组织实际控制者主动交付的权限。
4. **部曲合法认可：** 指挥官失能、公开拥立或组织仪式形成的临时事实授权。

到达战场不等于获得指挥权。无权时玩家可以以个人身份作战、保护直属人员或向有权者提出建议；默认不能越权改阵、调队、夺取他人直属部曲或发布高级军令。只有明确的指挥官失能、上级临时任命或部曲公开拥立事件，才可形成越权后的合法授权。

### 5.3 直属部曲

登记为玩家直属亲卫或部曲的成员拥有稳定直接权限，除非忠诚崩溃或公开改投。部曲编入军阵后，战场任务服从所属编队指挥官；个人行动和预先登记的紧急召回仍听玩家。紧急召回只在玩家预先登记的条件满足时触发，条件不满足时只是普通请求，不能越过军阵指挥链。

### 5.4 指挥可达性

命令界面始终可查看，但每支部队显示：

- **可直达；**
- **可经中继；**
- **仅能依预案；**
- **失联。**

不可达命令显示原因，并允许玩家排队；排队不等于已经生效，命令可能在送达前过期、被截获、被替换或因权限变化而失败。

## 6. 影响力模型与统治力

### 6.1 影响力是普遍能力

所有人、家庭、部曲、军队、商贾、世族、官府和组织都拥有影响力，只是范围、稳定性和领域不同。影响力不是一个全局战斗力数值，而是以下维度的有向关系：

`Influence(subject, target_group, domain, jurisdiction, time)`

主要来源：名分、关系信任、利益交换、能力声望、信息触达、持续记忆、组织网络和强制威慑。影响力必须带对象群体、领域、辖域和时间，不能把“在军中有威望”自动转换成“能让商人降价”。

设计上将影响力记录为可解释的关系向量，而不是单一总分：名分与合法性、信任与互惠、利益依赖、能力声望、信息触达、组织覆盖、持续时间、强制能力。不同目标群体对各维度的响应不同；同一人可以受到军队信任、被世族排斥、被商贾忌惮。界面可提供领域摘要，但任何摘要都必须能展开到对象群体、依据和时效。

一次影响行为经过三道判断：权限决定行动是否合法且可下达；影响力关系决定目标人物或群体可能如何响应；对应领域 Owner 再根据事实、资源、版本和规则决定结果能否成立。高影响力不能替代权限，合法命令也不保证服从，角色的服从意图也不等于事实已经发生。

### 6.2 统治力是影响力的高阶变体

统治力不是第二套独立属性，也不是全局万能权力。它表示影响力已经在某一辖域和领域中组织化、稳定化，并有代理和执行网络。

建议激活条件：

`声望/承认达到门槛 × 势力与资源达到组织门槛 × 在辖域内持续稳定 × 存在合法名分或可接受的事实承认 × 有代理人、制度和执行链`

状态分为：未成形影响 → 影响力成势 → 统治力激活 → 争议统治 → 统治崩解。激活和失活采用滞回：短期失去一座仓库不会立即取消统治力，但长期失去税粮、军队、治安和承认会使其退化为名义统治或地方割据。

统治力按“辖域 × 领域”分别成立，不是角色的永久头衔。一个势力可以在军令与治安上有稳定统治力，在市场、司法或地方征收上仍处于争议状态。激活门槛由剧本和领域配置，至少检查持续控制、资源供给、代理人覆盖、执行链可达、关键群体承认和竞争者挑战；维持判断使用较低门槛，避免短期波动造成状态闪烁。失去条件时先降为争议统治，只有执行网络和持续控制进一步瓦解才判为崩解。

统治力主要决定：能否稳定征收、任命、调运、设定政策、要求组织协作和维持继任；影响力主要决定：具体人物和群体是否愿意配合、拖延、隐瞒、投机、抵抗或改投。权限、影响力和统治力必须分开显示。

### 6.3 经济战中的影响力

经济影响力按目标群体拆分：盐商、仓吏、运输户、军队、居民、工匠、世族和地方官各自独立。玩家可通过任命、授权、分封、联姻、拉拢、分权和制衡改变组织结构；个人意图不全知，需通过情报发现。组织汇总指标可见：部曲忠诚、世族支持、军队服从、地方秩序和市场信任。

## 7. 军队、预案和命令链

### 7.1 军队自治优先级

军队在每个决策窗口按以下优先级运行：

1. 已送达且有效的命令；
2. 战前训练过的预案；
3. 继任链与现场指挥官；
4. 训练度、士气、补给、疲劳、组织文化和个人性格。

玩家离开指挥范围后，军队继续行动。只有超出预案、发生关键突发、指挥官失能、目标状态改变或通信重新建立时，才生成玩家可处理的介入机会。玩家不能因为切换界面而暂停远处军队，也不能在无通信条件下强制改写其行为。

### 7.2 预案

预案是可训练、可版本化和可继承的组织能力，包含队形、目标优先级、士气反应、撤退路线、补给阈值、通信方法和继任顺序。玩家可在战前编辑，在战场中只可切换已训练预案；临时改案受军队素质、指挥官质量和通信质量约束。

### 7.3 命令包与验证

命令不是点击即执行，而是带目标编队、语义动作、执行条件、优先级、有效期、权限来源、预案版本和预期 revision 的命令包。状态为：已下达 → 传递中 → 已送达（验证结果）→ 已接收 → 执行中/失败/过期。

玩家制定口令、信物、双传令、多源复核和诱饵制度；具体封泥、签押、合符、应和和格式验证自动执行。异常时玩家选择暂缓、复核、接受风险或追溯。破译需要敌方投入资源，并通过封泥破损、格式异常、多源矛盾和无应和提供预警。

## 8. 战争与战斗

### 8.1 战争目标开放

玩家可自行选择夺旗、斩将、护送、抢粮、破坏器械、掩护撤退、抓捕、拖延或脱离接触。委派目标不是硬锁，玩家可以违背；系统分别结算目标损失、抗命记录、信任、军纪、声望、政治关系和后续授权。

完整战斗在双方脱离接触且一方无法或不愿继续争夺时自动收束。军旗是第一章 Demo 的主目标，也是完整游戏中最易读的战场锚点之一，不是所有战争的唯一胜利条件。

### 8.2 战斗遭遇与可读性

遭遇由“发现威胁 → 形成选择 → 承诺行动 → 接触结算 → 重组或撤退”构成。玩家应能从敌方朝向、距离、队形、旗鼓/动作提示和既有战报判断大致危险类型；提示允许不完整，但不能让决定性攻击在没有可学习信号时发生。

首章敌方单位以四种可辨认职能构成：主战队维持正面压力，军旗队守住士气锚点，冲车队保护攻城器械，指挥头目决定预案并可能失能。职能首先通过站位、动作、旗帜和状态反馈区分，灰盒阶段不依赖复杂模型或大量专属动画。

玩家亲战要在“个人局部影响”与“组织整体执行”之间留下真实张力：玩家靠近目标会增加局部接触机会，也可能远离传令节点；冲锋需要路线、速度和接触方向成立，撞入完整阵型应有受阻、失序或受伤风险。玩家不能仅通过重复冲锋成为无成本解法。

关键反馈以状态变化为主：命令链显示到达节点；近场接触反馈方向和结果；队伍面板显示士气区间、阵型状态、目标与当前预案；关键目标显示争夺/损坏/失守/夺回。任何数值伤害和动画表现最终仍由战场 Owner 结算。

### 8.3 指挥与亲战

玩家可在指挥关注和亲战关注之间切换，切换不暂停世界；单人模式的暂停/慢速只是辅助。亲战能改变局部接触、敌将状态、军旗压力和士气，但不能一人替代补给、通信、编队和远处战场。玩家离开后，预案和授权手下继续履职。

### 8.4 战斗层状态

军队和队伍至少有士气、疲劳、训练、补给、阵型、指挥状态、军旗状态和撤退意愿。士气不能直接由角色智能体写入；战场或军事状态 Owner 根据伤亡、侧翼、断粮、军旗、指挥官、疲劳和战果结算，角色只能形成 rally、withdraw、protect_standard 等候选意图。

### 8.5 兵种与装备结构

兵种定义为“装备组合 + 训练水平 + 组织来源 + 士气/忠诚 + 战术角色”，不是独立美术模型清单。派系通过兵种可用性、训练、维护成本、装备变体和组织关系形成差异。

完整目录目标约二十种；首章通过后的首轮兵种扩展候选约十种，不属于第一章制作清单：

| 类别 | 目录目标 | 主要战术职能 |
|---|---|---|
| 步兵（7） | 郡国矛兵、郡国刀盾兵、戟盾兵、长矛兵、募兵戟盾、部曲戟盾、陷阵先登 | 扛线、护卫、反骑、突破和据点争夺 |
| 远程（5） | 郡国弓手、募兵弓手、强弩兵、募兵强弩、弓骑 | 压制、远程杀伤、机动骚扰 |
| 骑兵（5） | 轻骑、突骑、重骑、外族突骑、亲卫骑 | 侦察、冲击、侧翼和护卫 |
| 特殊（3） | 义从、工程队、水军/舟师占位 | 护送、工程和后续水战扩展 |

首轮优先：戟盾兵、强弩兵、突骑、轻骑、弓手、亲卫骑、郡国矛兵、郡国刀盾兵、长矛兵、工程队。兵种数据允许内容迭代，但装备、训练、补给、忠诚和组织来源必须可独立结算。

装备资产采用模块组合：基础身体约三套、头型十至十二种、甲胄六套、马甲两套、头盔六种、盾六种、武器十八至二十件、马四种。兵种读取装备预设；派系皮肤通过材质、甲色、布衣色、盾徽、旗帜、盔缨和少量甲片体现，不制作二十套独立模型。

### 8.6 战场器械

器械必须有控制者、操作人员、补给、损坏状态和可观察的完整/损坏/残骸表现：

- **防御工事：** 拒马、鹿角、铁蒺藜、壕沟/土垒、栅栏/营寨、望楼、陷阱/绊马索；
- **攻城器械：** 云梯、冲车、盾车/洞屋、井阑、投石车、弩炮、地道/火攻，大型攻城塔后续考虑；
- **载具：** 辎重车/粮车、盾车、武刚车/偏厢车、工程车/推车、浮桥/舟桥，战船属于后续；
- **消耗品/信号：** 火油/火把、旗帜、鼓号、烟尘/信号、医药和担架。

战车不作为独立战车兵体系；武刚车/偏厢车先作为载具灰盒，验证车阵、运输和反骑用途。模型由木构件、铁件、绳索、轮子、布幔和旗帜模块拼装，近、中、远距离使用不同细节层。

### 8.7 科技与装备迭代

科技树是能力解锁与组织条件：

| 科技分支 | 主要解锁 | 本案阶段 |
|---|---|---|
| 兵器 | 矛、戟、刀、剑的材料和结构 | 核心 |
| 甲胄 | 皮甲、铁札、精铁、钢札；盾牌蒙皮与铁盾 | 核心 |
| 弓弩 | 单体弓、复合弓、强弩、有限连弩及弩机改进 | 核心 |
| 攻城 | 云梯、冲车、投石车、弩炮改进 | 后续战役 |
| 通信后勤 | 旌旗制度、鼓角训练、驿站、望楼和传令效率 | 后续战役 |
| 火药 | 火油、火箭、火门枪、突火枪、震天雷、早期臼炮 | 架空/后期开关 |

例：长杆/戟由木杆铁头到炒钢、百炼钢和精钢；环首刀由生铁到炒钢、百炼钢和精钢；札甲由皮甲到铁札、精铁和钢札；弓弩由单体木弓到复合弓、强弓/强弩和有限连弩。升级带来生产能力、成本、耐久、伤害/防护或训练门槛变化，不是无代价数值膨胀。

研发消耗铁、木、皮革、油、钱、工匠、方士/工程师、工坊和实战经验；火药分支才需要硝石。技术可通过工匠、俘虏、缴获、贸易、婚姻、学舍和投奔流动。换装时老兵可保留旧装，新兵读取当前预设，精锐可优先改装。

### 8.8 阵营与兵种维护

郡国兵、募兵、部曲、义从、外族骑和后期水军反映不同的招募权、训练成本、维护关系和政治风险。士兵不是可任意替换的同质数字：部曲更忠于直接主君但受欠饷和声望影响；郡国兵受官府与地方秩序影响；募兵受军饷、军功和战局影响；外族骑受盟约、互市和首领关系影响。

## 9. 复合战争与资源网络

### 9.1 四类核心资源

盐、粮、铁、马料首先使用同一资源网络的四个实例；以后可扩展皮革、木材、药材、油和钱。

`资源源头/生产 → 提纯/加工 → 储存与产权 → 运输路线与商道 → 城镇市场与公仓 → 家庭、军队、工坊、官府消费`

每个节点记录资源种类、质量、数量、预留、产权、事实控制、生产能力、成本、运输容量、时间、风险、市场可见度、价格、需求、现金流、替代品和情报可信度。

市场不是一张全域统一报价表。价格与成交由本地可交易库存、有效需求、替代品、运输时间与风险、信用、管控政策和参与者掌握的信息共同形成；被预留、藏匿、封锁或无法运达的库存不等于市场有效供应。玩家看到的是其渠道能够获得的报价、成交和报告，并带有时间戳与可信度。大规模投放可压价，但运输瓶颈、商人拒售、囤积、谣言和政策反应都可能改变实际成交量。

必须区分：

- **产权：** 谁在法律或契约上拥有资源；
- **保管：** 谁实际看守库存；
- **事实控制：** 谁能决定生产、发运和发放；
- **军事占领：** 谁控制节点周围的武力与道路；
- **市场影响力：** 谁能改变报价、信用、交易意愿和信息。

占领城池不自动获得商贾仓库、盐场和运输队；玩家需要授权、谈判、接管、查封、交换、保护或以合法程序改变控制关系。武力抄没失败时，物资可能被转移、藏匿或带出控制范围。

### 9.2 经济战操作

历史可行的市场操作包括：囤积、诱导囤积、反向放货、公仓平抑、限量配给、保护商路、截断运输、收购关键仓库、盐价管控、定向赈济、公开征用和秘密破坏。系统不引入现代期货、金融杠杆或抽象“做空”按钮；玩家可以通过现货库存、现金流和信息差实现类似的历史效果。

经济战分为：

1. **军用断供：** 优先减少敌军和军需节点的供给，尽量保留平民市场。
2. **城市压迫：** 同时影响居民、劳力和军队，效果更强，合法性、声望、叛乱和报复风险更高。
3. **市场夺权：** 夺取盐场、粮仓、商道、运输户和报价权，以利润和政治控制为目标。
4. **稳定战：** 通过公仓平抑、定向发放、保护商人和恢复运输，提高新占领地的事实统治。

玩家必须选择政策和目标范围，不能把“减少供给”直接等价为全城混乱。后果由供应、价格、身体、劳力、组织服从和角色行为逐层结算。

### 9.3 盐战因果链

`盐源/运输受控 → 可购买量下降、价格上涨、排队与配给 → 部分家庭和军队无法满足需求 → 身体压力、疲劳和劳动能力变化 → 家庭生产、运输、纳粮、募兵与修工事能力下降 → 角色感知不公、恐惧、投机、抗税、拒运、逃亡或继续服从 → 组织与军事 Owner 结算真实后果`

缺盐不会按一个“混乱度”直接扣分，也不会短期自动判定死亡。高温、重体力、疾病、年龄、饮食、作战和持续时长决定需求压力；长期严重缺口才会产生严重身体后果。Paralls 的 ResourceBodyRuntime、Status Tags、Effective Stats 和 Survival Authority/计划中的周期需求可作为基础；完整盐代谢、群体生存到军事反馈属于本案增量领域。

### 9.4 复合案例：新占领城的盐商博弈

玩家刚占领一座城市，商贾大族与旧势力结盟，并将大量盐带离城内。玩家公开抄没失败，因为仓库不在控制范围内，且公开干扰市场会伤害声望、市场信任和中立利益相关者。

玩家随后采取一组可被人物和市场误读的政策：

1. 点亮已满足条件的卤盐矿提纯技术，在附近建立秘密生产；
2. 保护产地和小规模运输，封锁消息，使商贾判断玩家储备不足；
3. 第一天投放 1000 斤，第二天 600 斤，第三天 200 斤，观察对方报价、收购和现金流；
4. 诱使对方继续高价囤盐，直到其现金流和仓储风险达到脆弱阈值；
5. 试探性放货确认对方仍在接盘后，通过公仓和市场按市价集中供给，令囤积盐贬值；
6. 结合细作、查路、护运和定向破坏，削弱对方库存和运输；
7. 对符合条件的军户、重体力家庭、贫困户和关键劳力定向免费发盐，恢复劳动和秩序；
8. 将战果转化为市场信任、居民服从、运输合作和事实统治，而不是只显示一笔金钱收益。

该案例的关键不是玩家拥有全知库存，而是玩家通过产量、报价、成交、传闻、商人情报和多日试探推断对手状态。错误判断会使玩家自己库存枯竭、失去信誉、刺激替代市场或被对手反制。范仲淹式“以收粮稳定市场、以高价吸收供给、以公仓调节价格”的历史逻辑可作为市场事件模板，但每次结果由库存、现金、运输和人物行为重新结算。

## 10. 生命、劳力、士气和社会反馈

### 10.1 需求与身体

资源短缺先进入需求与身体状态：可获得性、消费机会、身体压力、疲劳、疾病风险、有效属性和恢复速度。Survival 只提出满足需求的消费计划；Inventory、Economy、Ownership 和 Production 领域分别决定库存、付款、使用权和生产结果，不能由需求系统自行扣款或写入产权。

### 10.2 从身体到组织

身体状态通过组织和角色的可见证据产生后果：

- 居民：劳动能力、纳粮纳税、搬运、修工事和募兵意愿变化；
- 军队：疲劳、疾病、补给压力、士气和撤退意愿变化；
- 商人：现金流、信用、风险偏好、囤积和改投；
- 官府：配给、赈济、查禁、征用、腐败或妥协；
- 世族：支持、索取、联络旧主或重新下注。

### 10.3 不公与冲突

“高官府邸有盐、普通人无盐”必须经过观察、传闻、解释、角色候选行动和 Owner 结算：可能产生抗议、举报、拒运、哄抢、投靠、隐忍或借机敲诈。Laya/角色智能体可在关键人物、家庭和冲突窗口激活；司命可提供压力或机会，但不能直接写“居民忠诚下降 20”。

## 11. 细作、情报与信息战

细作是有身份、关系、暴露、任务、证据链和死亡风险的角色或组织行动，不是抽象百分比按钮。任务包括探查库存、观察现金流、伪造信物、散播传闻、接触商人、破坏运输、制造冲突、反间和确认敌方预案。

细作输出首先进入角色记忆和情报投影；只有被相应 Owner 接纳的破坏、交易、冲突或关系变化才进入世界真相账。司命可以制造机会、压力和揭示条件；细作角色必须经过 L1 感知、L2 理解、L3 规划、三重过滤器和 L4 执行意图。被捕、误报和假情报会产生可追溯的错误推断，而不是随机惩罚。

## 12. 政治、组织与统治

玩家可有限设计组织关系：任命、授权、分封、联姻、拉拢、分权、制衡、质子、征辟和保护。具体冲突由人物性格、利益、军功、恐惧、记忆、亲缘和组织状态演化。

平时只显示组织级指标：部曲忠诚、世族支持、军队服从、地方秩序、市场信任、军粮安全和合法性。个人意图通过情报、相处、异常行为、密谈和事件证据发现。任命一个忠诚的地方官不等于他会自动解决盐价；他仍受权限、库存、人员和自身利益约束。

新占领地经历“军事占领 → 名义统治 → 事实统治 → 稳定统治”过程。事实统治要求税粮、治安、司法、运输、市场和关键人物的持续配合；统治力的激活是这一过程的组织化表现。

### 12.1 内政与外交

领地经营覆盖郡县城池、坞堡、屯田、武库、市肆、学舍/察举、城墙和兵营。玩家可直接管理具体事项，也可设定预算、政策、责任人和检查条件，委派手下持续办理；委派不构成硬锁，玩家可推翻手下决定，但会改变信任、组织服从、损失和政治关系。

外交行动包括表奏朝廷、盟誓、质子、联姻、征辟、世族交涉、赎俘、交换和承认。每项关系都区分公开承诺、私下意图、履约能力和对方实际认知。汉室合法性、世族支持和部曲忠诚彼此牵制：借朝廷名分可得官职与秩序，但可能限制自主；依赖世族可获得钱粮人才，却要让渡地方权力；扩大直属部曲可提高个人控制，也增加军饷与继承风险。

### 12.2 经济层级与资源管理

经济由领地税赋/贸易/商路，与玩家个人战利品/任务报酬/竞技等两部分组成。钱、粮、盐、铁、马料、木、皮革、油和工匠共同进入库存、生产、市场、运输与组织预算。

默认管理界面只展示关键库存、现金流、军需天数、供给风险和异常市场信号；详细视图才显示完整账目、报价、仓库、运输批次、债务、合同、税费和生产队列。自动代理按玩家政策和权限行事，并受预算、组织承诺及事实约束；关键政策变化、越权请求、现金流危机和重大损失才要求玩家决策。

## 13. 科技、装备与技术流动

科技是能力解锁和组织条件，不是点数购买的魔法。兵器、甲胄、弓弩、攻城、通信后勤和架空火药六系科技共同影响装备组合、工事、训练、生产、验证和运输。

资源、工匠、地域、政治关系、实战经验、缴获逆向、俘虏、贸易、婚姻、学舍和投奔都会影响技术流动。玩家可以保护机密、垄断生产或主动传播；传播技术可能换来盟友，也可能帮助潜在敌人。

装备换装读取兵种预设和装备等级：老兵可保留旧装备，新兵使用新装备，亲卫和精锐可优先换装。技术提升必须能在战场、生产速度、维护成本、通信可靠度或市场竞争中被感知。

## 14. 角色、成长与继承

### 14.1 三条成长线

1. **个人能力：** 武艺、将略、统御、政略、交涉、工巧和身体状态。
2. **组织能力：** 任职经验、制度、授权网络、预案、市场和行政能力。
3. **军队训练：** 队形、通信、纪律、补给、器械和继任熟练度。

三者相互影响但不合并为一个等级。成长来自亲战、训练、治理、谈判、经营、长期任职和实际后果，而非单纯购买经验。

### 14.2 死亡与承接

重大失败可以导致受伤、被俘、失势、流亡或死亡。玩家认为复起无望时可选择自杀，也可能被杀。死亡后切换到最接近的可承接角色：配偶、子女、义子、部曲头目或亲信；无可承接角色才结束势力或本局。

继承人承接领地、组织名分、部分制度、公开资源和部分关系网络，但不完整承接原角色的个人威望、私人信任、军功、武艺、秘密、记忆和直属忠诚。继承人如刘禅继位，拥有结构性资源却必须重新建立个人影响力和事实统治。

### 14.3 战役目标和结束

沙盒不强制只有一个“统一天下”胜利条件。玩家可以设定个人/势力目标，例如保全家族、受封州牧、拥立天子、建立新朝、控制中原、复仇或维持独立；系统展示目标进展和代价，战争、政治和经济结算仍按世界事实发生。

建议战役持续到玩家主动结束、角色死亡后无可承接者，或当前剧本明确的时代终点。剧本时代终点触发后，玩家可选择结算成绩并结束，或继续进入架空后续。该规则是本案策划建议，需在剧本设计中确定具体年代和结算表现。

## 15. 历史分岔与司命边界

### 15.1 历史事件

历史事件是带条件的压力点：有默认发生倾向，但参与者、时间、地点、规模、结果和是否发生，都可被玩家的情报、军令、外交、经济战和亲战改变。若玩家长期没有产生足够影响，世界按照已登记的历史倾向推进。

### 15.2 司命不是 Owner

司命（Siming）是全局态势、高层催化、公平审计、候选、政策和可行性层。它可以推动历史趋向，输出 `impulse`、`opportunity`、`fact_reveal` 或压力变化，不能直接宣布城池易手、人物死亡、库存变化、战争胜负或角色已经决定行动。

历史结果由既有或新增的领域 Owner 独立结算。司命与 Owner 的关系是：司命提出压力/机会/候选，角色和群体模拟在授权范围内承接，领域 Owner 校验权限、版本、成本和因果后提交事实与 receipt。

### 15.3 角色与群体模拟

地方官、军队指挥官、军需官、部曲头目和关键商贾应激活为角色智能体，但日常行为以职责脚本、军制预案和规则程序为主。只有脚本未覆盖、利益冲突、谈判、继任、改投、抗命、重大危机和长期挂机决策才取得 activation lock，进入完整 CharacterAgent。

远场居民、运输户和普通士兵由 PopulationPlanner 使用 B0/B1 低成本推进，输出 `presentation_seed`、`activation_candidate` 或 `owner_bound_intent`。任何改变库存、价格、关系、组织或身体的结果都必须经过对应 Owner receipt；同一角色在一个窗口只能有一个推进者，不能群体模拟和 CharacterAgent 双写。

## 16. Paralls 底座接合与责任矩阵

| 游戏域 | 现有可复用边界 | 本案新增/组合责任 | 禁止 |
|---|---|---|---|
| 世界事实、回放、幂等 | GameplayEventStore、AtomicEventBatch、revision、outbox、receipt、replay | 为资源网络、军事组织和经济战注册新 Owner 或组合结算器 | 新建第二账本或直接写状态 |
| 身体与资源状态 | ResourceBodyRuntime、Status Tags、Effective Stats、Inventory、Ownership、Economy 原语 | 盐/粮/铁/马料需求、库存和身体反馈的跨域适配 | Survival 直接扣款或写产权 |
| 生存需求 | Survival profiles、need/consumption proposal、部分状态与义务 | 周期需求、群体消费、缺盐到劳动/军队反馈 | 把 NeedTension 当完整生存事实 |
| 市场与生产 | EconomyMarketPlatform 的报价、订单、撮合基础；Production/Construction 片段 | 资源网络、运输、仓储、现货政策、市场信息与经济战组合层 | 现代金融做空、无凭据库存全知 |
| 组织与社会 | Organization/Government/Social 平台片段、关系和隐私投影 | 商贾、官府、军队、居民的组织反应和政策后果 | 用单一混乱值代替社会因果 |
| 战斗与军事 | UE 战场事实、士气/阵型/军旗/继任边界；Paralls 语义意图 | 战略代理与战术战场的同钟投影、补给和命令链 | 未获领域写权的 Agent、规划器或脚本直接写位置、伤害或最终胜负；不按编程语言禁止合法 Owner |
| 角色智能体 | L1-L4、Laya、记忆、activation lock、execution contract | 关键角色的复杂决策、情报和政治承接 | 司命跳过角色直接命令 |
| 司命 | 全局态势、候选、政策、审计、高层事件 | 历史压力点、经济危机机会、叙事公平和可见性 | 司命充当历史 Owner |
| 群体模拟 | PopulationPlanner、B0-B3 交接、cadence、continuity | 远场市场/人口/运输推进和近场升级 | 群体输出直接成为世界真相 |

### 16.1 组合结算器

跨域行动可由二级组合结算器编排，但它不拥有第二份事实。它拆解玩家或角色意图，调用生产、库存、市场、运输、组织、身体和军事 Owner，收集各自 receipt，形成组合结果和补偿/重试状态。跨域失败采用部分结算加 receipt-driven recovery，不承诺全局回滚。

例如“秘密放盐并定向赈济”可拆为：生产完成 → 库存入库 → 运输通过 → 市场报价/公仓发放 → 家庭或军队消费 → 身体和组织投影更新。每一步由对应 Owner 决定，任何一步拒绝都必须留下可追溯原因。

完整游戏中的角色死亡后继任/继续游玩属于后续 Campaign 内容；当前守城县 Demo 中玩家死亡、投降或逃跑均为失败，不能由自动继任改为继续获胜。

## 17. 结算顺序与节奏

世界使用连续时钟，但不同事实使用不同 cadence：

| 节奏 | 典型内容 |
|---|---|
| 即时 | 战斗接触、命令送达、库存破坏、仓库起火、抓捕、军旗变化 |
| 短周期 | 报价、成交、运输队状态、排队、传闻、角色决策窗口 |
| 日级 | 家庭消费、盐粮需求、疲劳恢复、劳力、军队补给、市场库存 |
| 旬/季 | 税粮、征募、屯田、训练、技术生产、政治承认和统治力稳定 |

建议顺序为：已提交资源/环境事实 → 运输和库存可用量 → 市场价格与成交 → 消费计划 → 身体/需求状态 → 劳力和组织候选 → 角色 L1-L4 承接 → 军队士气/预案与政治结果。实际跨域提交仍以 Owner admission 和 revision 为准，顺序不能绕过权限和因果。

## 18. UI 与信息体验

### 18.1 四类界面

1. **世界/统治界面：** 领地、资源网络、组织权限、市场和历史压力点。
2. **行军/通信界面：** 行军实体、传令路径、命令状态、情报可信度和过期程度。
3. **战场指挥界面：** 阵型、士气、军旗、目标、预案、可达性和继任链。
4. **角色界面：** 当前身份、权限来源、个人能力、关系、记忆、伤势和候选行动。

默认面板只显示少数关键资源和异常；玩家想精细管理时可展开全部库存、现金、运输、报价、储备和组织账。系统不以文书操作量作为难度，验证自动完成，只有异常和关键选择才要求玩家介入。

### 18.2 远方事件通知

只通知玩家感知范围内已观察或已合法收到的事件。通知应说明“谁在何时、通过什么来源、以多大可信度告诉玩家什么”，而不是直接展示全球地图结果。玩家在领地可远程指挥，但必须接受传信延迟；玩家在战场听到领地消息后，可以回信或赶回，不能远程实时切换空间处理全部问题。

## 19. 模式与难度

- **标准模式：** 命令延迟短且可理解，视野较宽，验证以自动通过为主，破译提供明确预警。
- **硬核模式：** 完整模拟传令、信物、封泥、口令轮换、斥候可信度、视野更新、市场误判和细作风险；玩家可暂停，但暂停不刷新世界。
- **历史倾向开关：** 开启时历史压力更强；关闭时允许更开放的架空分岔，但仍遵守世界因果。
- **火药开关：** 默认关闭；开启后只进入标注为架空长线的科技分支，受成本、天气、炸膛、惊马和生产能力限制。

## 20. 骑将冲阵子切片参考与体验验证

本节只定义骑战/传令子切片的 3–8 分钟测试，不是整个县城 Demo 的时长或完成标准。当前 Demo 要守住召陵县、求援并等待约 30 个世界日或提前击退敌军；全部 23 Owner 基础设施按 08 完整建设。本节“暂缓”仅裁剪子切片内容，不能推迟领域合同、结算、恢复和测试。

本节所有断线自治测试均以本地已登记领域权威及有效意图/执行许可为前提；没有授权时保持 pending/安全中断。意图过期、revision 冲突、权限失败不能自动升格本地决策权或事实写权。

### 20.1 场景与单位

- 一张含平地、浅坡、道路/掩体、双方阵地、中央军旗和后撤线的灰盒战场；
- 玩家骑将、亲卫队、营指挥头目、营内三队；
- 敌方指挥头目、军旗队、主战队和冲车；
- 玩家可在第一/第三/俯视关注之间切换，骑马移动并发出 `10/22/34` 语义命令。

### 20.2 必须展示的闭环

1. 玩家接近战场目标并通过亲卫传令；
2. 命令显示传递状态和可达性；
3. 三队按照预案、训练、士气和权限执行或拒绝；
4. 冲锋造成阵型/士气变化；
5. 军旗、敌将或冲车至少一个目标状态改变；
6. 指挥官失能后按继任链继续行动；
7. 玩家离开指挥范围后军队继续自治；
8. Bridge 关闭时在有效许可内继续获准计划；意图过期须重校验或安全中断。

### 20.3 骑战子切片明确不展示

完整全国地图、完整朝廷系统、水战、多人、火药实装、完整经济战、复杂内鬼事件和全量 LLM 每兵决策均不属于骑战子切片验收。骑战子切片的数据接口必须为后续经济、政治和远场模拟保留语义 ID、权限、revision、事件和回放字段。

### 20.4 MVP 清单与范围门

| 模块 | 必须包含 | 暂缓/不做 | 验证目的 |
|---|---|---|---|
| 核心玩法 | 骑乘移动、三视角、`10/22/34`、玩家→亲卫→营指挥头目→目标队、三队自治、冲锋接触 | 完整骑马物理、高级连招、全国地图 | 验证具身冲锋与军令组织是否形成一个闭环 |
| 战场状态 | 至少一次可观察的阵型变化和士气变化；至少一个军旗/敌将/冲车目标可变更；一次指挥继任 | 复杂伤害模型、百种状态、全兵种目录 | 验证指挥、局部战斗和目标反馈能互相解释 |
| 内容 | 一张小型灰盒遭遇场景、一营三队和亲卫、简化敌军指挥头目/旗队/主战队/器械队 | 全国战役、完整围城、多人 | 以最少单位测试层级命令与战场识别 |
| 美术/音频 | 占位骑将、步兵、旗帜、冲车；可辨认的阵型/士气/命令提示 | 正式角色资产、大量专属动画、完整配乐 | 先验证信息层级和反馈可读性 |
| 技术边界 | UE 本地结算；可回放的命令/战场事实；Bridge 不可用时本地战术脑继续 | 多人网络、全量 LLM、规模性能终局优化 | 验证本地可玩性和未来 Paralls 接合边界 |

**切片时长与节奏建议：** 目标一次 3–8 分钟；30 秒内能发出第一条命令，2 分钟内看到阵型或士气变化，5 分钟内看到一次关键目标争夺或指挥继任。玩家可以选择多种目标，因此不要求每次同一路线或同一胜负结果。

**切片通过标准：** 自动化测试确认视角不复制玩家、三条命令路由正确、失效/过期/无权限命令被拒绝、继任幂等和 Bridge 关闭仍可玩；PIE 确认骑乘与三队行为可观察；首次试玩达到“核心指标定义”中的早期阈值，且能解释至少一次因果链。

**切片失败标准：** 只需反复冲锋即可稳定压过组织决策；玩家无法分辨三队命令差异或不知道命令到哪一步；部队离场后停止行动/直接完成脚本胜利；关键目标变化无法对应战场事实；Bridge 中断令 Demo 无法继续。任一项出现都应先修复核心闭环，不扩张内容。

### 20.5 核心假设与验证

| 假设 | 验证方式 | 建议通过信号 | 失败时的处理 |
|---|---|---|---|
| 玩家能理解“骑将不是全知 RTS 光标” | 首次试玩观察玩家在哪些位置发令、何时回到指挥范围，并做简短复述 | 多数试玩者能说出距离/中继影响命令抵达 | 强化可达性提示、传令路径和回归指挥的选择反馈 |
| 三条命令能形成互补任务 | 自动测试路由；试玩中记录三队执行状态和玩家选择 | 每个快捷码稳定指向其语义分队，玩家会结合目标使用至少两条 | 重做目标差异与反馈，不靠改数字制造差别 |
| 冲锋影响局部战局但不能替代组织 | 比较单骑冲锋、命令协同两种灰盒测试结果 | 单骑能改变局部状态；协同对关键目标/队伍状态有可辨优势 | 调整接触风险、目标压力或协同回报，检查是否存在支配打法 |
| 失去实时指挥后自治仍可读且可信 | 在玩家离开或 Bridge 断开时观察部队决策和日志 | 部队依预案继续行动，并能说明触发原因 | 降低 AI 复杂度，先把预案优先级和状态反馈做稳定 |
| 战斗状态反馈足以解释结果 | 玩家在战后按时间顺序还原一次士气/阵型/目标变化 | 能正确指出主要触发事实，而不是归因于隐藏随机数 | 补充命令状态、目标状态或因果战报 |

**最小测试样本：** 5 名首次试玩者即可做早期可用性检查；样本不足以代表市场。每轮记录问题、是否成功、耗时和版本，不将一次试玩结果包装成已验证的市场需求。

### 20.6 玩家旅程参考

| 时间窗 | 玩家看到/做什么 | 系统必须回应 | 不通过的表现 |
|---|---|---|---|
| 0–30 秒 | 骑将和战场目标可辨；移动、转向、视角可用；玩家发出第一条命令 | 亲卫收到请求并呈现下一传递节点 | 命令快捷码不可发现或传令结果无反馈 |
| 30–120 秒 | 玩家根据队伍任务选择冲锋、观察或继续发令 | 三队任务/阵型/士气至少一项出现可辨变化 | 玩家不清楚是命令还是随机脚本导致变化 |
| 2–5 分钟 | 玩家面对旗帜、敌将、冲车或撤退机会，选择风险与目标 | 目标、损失、授权或命令链变化产生回报/代价 | 无代价的唯一最佳解，或玩家操作不影响任何状态 |
| 5–8 分钟 | 玩家看到战斗收束或队伍继续自治 | 摘要按事实、来源和损失记录结果；Bridge 关闭仍可继续 | 结果只显示胜负，无法复盘关键因果 |

| 目标 | 军旗、敌将、冲车有明确轮廓、状态和归属反馈 | 先用低面数占位物；精细器械和破损表现延期 |
| 场景 | 平地、浅坡、道路/掩体、双方阵地、中央目标和后撤线支持读图 | 低 Poly/灰盒为主，避免高密度装饰遮挡冲锋路线 |
| UI 与反馈 | 命令传递状态、队伍任务、士气/阵型、目标状态和因果摘要 | 优先文字/图标/形状编码与基础音效；最终动效、配音和特效延期 |

外部资产必须按 `docs/art_resources/` 记录来源、许可证、预算、目标 Actor、导入状态、PIE 可见验证和替换记录；一次只改一类资源并保留可回退版本。

## 22. 全局完成标准

总策划完成不等于所有系统已实现。进入下一阶段前，设计必须能回答：

1. 玩家当前身份和默认优先级如何推导；
2. 玩家是否拥有某支军队或资源节点的权限；
3. 命令和情报是否能在当前通信条件下抵达；
4. 玩家离开后谁按什么预案继续行动；
5. 资源从源头到消费端经过哪些 Owner；
6. 缺盐如何先影响供应和身体，再影响劳力、组织和军队；
7. 角色为什么知道某事、为什么决定行动或拒绝行动；
8. 司命产生的是压力/机会还是正式世界事实；
9. 失败后谁承接身份、哪些东西丢失；
10. 历史事件通过哪些条件被改变或恢复历史倾向。

### 22.1 完整游戏的体验验收

- 玩家能在近场战斗、远场代理和统治界面之间切换关注，切换不暂停或改写世界状态；
- 玩家只收到由观察、传令和情报实际抵达的信息，且能辨认来源、时效和可信度；
- 玩家无权或无法联系的部队会按预案和继任链继续行动；
- 玩家能通过控制资源源头、运输、仓储、市场和消费端改变战争持续能力；
- 经济行动对身体、劳力、士气和组织的影响可由事件链解释，而非隐藏全局惩罚值；
- 角色智能体的复杂决策可追溯到其感知、记忆、意图与过滤过程；日常代理由脚本和预案运行；
- 每个世界事实变更均有领域 Owner 结果和 receipt；跨域流程支持失败、部分成功、恢复和 replay；
- 重大失败会改变玩家控制角色、授权、关系和积累，但不无条件删档。

## 23. 技术架构建议与 Paralls 设计参考

### 23.1 技术架构建议

UE 负责输入、具身执行与表现，并承载 Manifest 获准的领域 Owner；各域按 08 的全量节奏矩阵分别结算，不因宿主相同合并写权。Paralls 提供角色意图、司命候选、群体候选/投影及获准 Owner 与提交服务。Bridge 断开时仅在有效意图/执行许可和本地领域权威范围内继续获准计划；意图过期、revision 冲突或权限失败须拒绝/重校验，未授权范围保持 pending/安全中断，不自动接管决策或写权。

事实事件携带稳定 ID、`event_time`、因果/相关 ID、revision、幂等键和来源；认知投影另记 `known_time`/可见性元数据。命令请求记录下达与过期时间，不能提前标成已发生事实。远端角色、司命、群体规划器和意图调用方不能绕过权威接口直接写位置、骨骼、伤害、库存、城池控制、生命或最终战果；UE 战场 Owner 负责本地战斗事实，资源、产权等 Owner 无论部署在 UE 或 Paralls，均只在各自权限内可靠提交并生成 receipt。新增组合层只编排请求、收集 receipt 和处理部分失败，不建立第二世界真相或万能调度器。

## 24. 风险评估与取舍

| 风险 | 设计取舍 |
|---|---|
| 连续世界信息过载 | 默认分层显示，异常才展开细节；保留最后已知状态和可信度 |
| 通信延迟劝退 | 标准/硬核双模式，命令排队、预案和自动中继提供可理解的缓冲 |
| 经济战变成表格 | 玩家只在关键政策、授权、异常和风险窗口介入，日常由手下与 Owner 处理 |
| 经济战过度抽象 | 资源网络必须有源头、仓储、运输、市场和消费证据 |
| 缺盐直接秒杀全城 | 使用需求、身体、劳力和组织的连续因果，长期严重缺口才产生严重生命后果 |
| 司命越权成为上帝 | 司命只能催化，Owner 结算，角色先经过 L2/L3/L4 |
| 群体模拟双写角色 | activation lock、唯一推进者、receipt 和 revision 冲突时回排队 |
| 范围膨胀 | 当前只制作召陵县守城内容，骑战作为子切片；完整五阶段基础设施与 23 Owner 按 08 建成，后续扩展内容而不补占位基建 |
| 复合结算失败无法解释 | 每个 Owner 独立 receipt、部分结算、补偿/重试和 replay |

## 25. 最终设计口径

《烽火王座：汉末群雄》的核心不是让玩家管理更多按钮，而是让玩家在有限信息、有限权限和有限时间中建立可持续的个人影响力、组织能力和事实统治。玩家可以靠军旗赢下一场战斗，也可以靠盐、粮、铁、马料和人心让敌军在战斗前失去继续作战的能力；可以亲自冲阵，也可以把决策交给职责脚本、预案和角色智能体；可以顺着历史走，也可以通过一连串被世界承认的事实把历史推向另一条路。

所有宏大结果都必须落回三件事：谁看见了什么，谁有权做什么，哪个领域 Owner 最终承认了什么。

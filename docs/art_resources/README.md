# 美术资源管理

这里记录Guoshang项目的美术资源、版本和替换计划。资源管理服务于可玩的 Demo：从第一批可验证的写实风角色、坐骑、地形、建筑和器械开始，按镜头距离和性能预算逐步扩充，不以 Low Poly 作为第一阶段的目标风格。

## 目录约定

- `experience_index.md`：玩家体验、镜头、战场可读性和美术验收目标。
- `asset_registry.md`：资源来源、许可证、预算、导入状态和 UE 使用位置。
- `manifests/<asset_id>/<version>.yaml`：每个资产版本的事实清单，包含身份、依赖、校验和、UE 路径、状态、证据和回退关系。
- [召陵县场景需求](requirements/召陵县/场景素材需求.md)与[角色需求](requirements/召陵县/角色素材需求.md)：维护具体交付和逻辑锚点；[通用标准](standards/建筑模块化与流送标准.md)维护制作/流送规则；[场景布局](../PRD/04-内容与剧本/召陵县/场景布局与功能分区.md)维护空间用途。
- `source/<asset_id>/<version>/`：原始下载或创作源文件，只读保存，不覆盖。
- `staging/<asset_id>/<version>/`：处理、导入和验证中的副本。
- `approved/<asset_id>/<version>/`：已验证并允许用于正式 Demo 的版本，只读保存，不覆盖。
- `deprecated/<asset_id>/<version>/`：已替换或弃用但仍可回退的版本。
- `evidence/<asset_id>/<version>/`：导入日志、Editor/PIE 截图、性能报告和人工验收记录。

目录中的版本目录必须与 manifest 的 `version` 一致。文件移动或替换不能删除证据，也不能在原目录上覆盖已有版本；更新资产必须创建新版本，填写 `parent_version`、`replacement_for` 和 `rollback_target`。

## 资源状态

每个资源必须处于以下状态之一：`候选`、`制作中`、`待验证`、`已验证`、`已用于 Demo`、`已替换`、`弃用`。状态变化要记录原因、日期、操作者和验证证据。没有来源、许可证、依赖、SHA-256、UE 路径和证据的版本不得进入“已验证”或“已用于 Demo”。历史记录中的视口/关卡可见验证单独写入 manifest 的 `verification.historical`；它不代表通过当前资源治理准入。只有 `verification.governance.status=passed` 且证据齐全时，生命周期才能进入“已验证”或“已用于 Demo”。

manifest 是资产事实来源，登记表只做索引。`asset_id` 标识资产版本族，建筑资产另用稳定的 `building_id`，角色资产另用角色身份 ID；文件名和 UE 对象名都不能替代这些字段。依赖必须列出 `asset_id` 和版本范围，并能形成无断边的依赖图。候选和待验证版本的 `storage.approved_path` 必须为空；获准后才记录正式批准目录。

## 状态流转与文件交接

`候选 -> 制作中 -> 待验证 -> 已验证 -> 已用于 Demo` 是准入主路径；`已替换` 和 `弃用` 是保留历史版本的终态。状态变更必须同步更新 manifest、索引和对应目录，不通过改名或搬文件单独表示状态。批准目录在 manifest 治理验收通过后才创建；迁移时记录文件清单、SHA-256、执行日期和操作者，并复核依赖引用。目录缺失、文件校验失败或依赖断链时，状态退回“待验证”，不得让旧 UE 路径自动充当已批准版本。

## 资源预算原则

- 阶段一优先写实比例、真实构造、PBR 材质和可验证的 LOD；允许通过材质实例、HLOD、实例化和远端代理控制成本。
- 后续阶段逐个扩充角色、坐骑、地编、旗帜和攻城器械的变体与近景细节，不能用远端代理冒充近景成品。
- 近场玩家骑将允许更高预算；中远场部队必须使用低成本模型、LOD 或简化代理。
- 资源必须服务于战场识别：玩家、亲卫、守军各职能、敌军、指挥官、军旗和攻城器械要能快速区分。

## 最小交付检查

每个版本入库前检查：源文件和导出文件清单及 SHA-256、文件大小、几何/材质/纹理/LOD/碰撞预算、依赖图、UE `/Game/...` 路径、导入日志、编辑器/PIE 证据、批准人、当前状态、父版本和回退目标。建筑还要检查 `building_id` 与视觉体、逻辑体、Level Instance、Packed Level Actor、HLOD 的映射；角色还要检查角色身份 ID 与 Gameplay Component、骨骼、动画和装备接口的映射。

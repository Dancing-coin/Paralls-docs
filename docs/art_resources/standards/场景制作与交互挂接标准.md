## 权威边界与使用方式

本篇维护近中远景材质/可读性和视觉体到逻辑引用、锚点的交付合同。模块尺寸、实体盒、材质槽、L0–L4、流送/性能设计参数只引用[建筑模块化与流送标准](建筑模块化与流送标准.md)；召陵县的清单、路径与验收见[场景素材需求](../requirements/召陵县/场景素材需求.md)，空间分区见[场景布局与功能分区](../../PRD/04-内容与剧本/召陵县/场景布局与功能分区.md)。

系统技术权威只在 [UE 本地提交与 Paralls 同步](../../architecture/05-运行时接入/01-UE本地提交与Paralls同步.md#ue-paralls) 与 [architecture 技术参考入口](../../architecture/README.md#technical-reference)。下文列举的领域归属是对来源合同的引用，不新立事实写者；有冲突回 architecture 裁决。资产可见、历史视口通过均不等同玩法/运行能力验收。

汉末写实是长期成品方向；当前 Low Poly/灰盒样本可用于验证，只要登记用途、预算与验证状态。下文“不得提交玩具化Low Poly”的原句作用于正式近中景成品，不禁止当前原型。`county_id = RNSL`、S2和县署等出现在原字段样例中，属于召陵县示例绑定；跨场景复用须显式填写实际county_id，不把RNSL当全项目常量。

资源身份、授权、manifest、生命周期和准入规则仅在[资源治理](../README.md)维护；本篇按该规范交付和登记，不重复定义治理状态。

### 写实风执行基线

- 所有近景和中景建筑、地编、道具必须以写实比例、真实构造和可解释的材质反应制作；不得提交刻意棱角化、玩具化、纯色块化或无真实表面信息的 Low Poly 资产。
- 夯土、木材、砖、石、瓦、织物、皮革和金属需要分别建立粗糙度、法线、颜色变化和边缘磨损逻辑；材质实例可以复用，不能用统一纯色替代材质差异。
- 近景 L2 地标使用 Nanite 或等效高质量几何；是否启用 Nanite 以实测性能为准，不得为了面数指标牺牲门窗厚度、结构关系和轮廓可信度。
- 远景 HLOD、代理网格和批次投影只降低几何与 Actor 数量，不改变写实色彩、主要轮廓、屋顶类型、城墙收分和功能识别；远景代理不作为近景资产的替代品。
- 场景参考图、材质球、模型源文件和 UE 导入结果必须一并登记，确保写实目标可被复核，而不是只凭主观“像不像”。

### 识别规则

- 阵营蓝/红只用于旗帜、队标和必要 UI 投影；建筑不大面积染成阵营色。
- 县署、城门楼、市楼、粮仓、铁匠坊、医舍必须通过轮廓、屋顶、旗/牌、位置和道路关系区分。
- 主街、里巷、粮道、城墙巡道使用地面材质和宽度区分。
- 状态不能只用颜色表达；封锁、损坏、短缺、污染和可交互点需要形状、旗号、烟/火、声音或 UI 图标辅助。

## 逻辑体、锚点和数据契约

<a id="scene-249"></a>
<!-- 原始来源：docs/PRD/玩法系统/06-召陵县第一阶段Demo场景素材需求.md:249-276 -->
### 建筑逻辑体最小字段

每栋 L2 建筑和每个功能性 S2 节点都要有：

```text
building_id
county_id = RNSL
zone_id
asset_tier
visual_asset_ref
logic_volume_ref
entrance_points[]
door_points[]
interaction_anchors[]
nav_tags[]
storage_or_work_slots[]
owner_domain_tags[]
streaming_cell_ids[]
hlod_proxy_ref
damage_state_ref
facility_state_ref
presence_state_ref
policy_ref
territory_control_ref
```

上述玩法状态引用字段是带领域、稳定 ID 和 revision 的引用，不是建筑蓝图的另一份可写总状态。城门开闭、门闩和登记城防设施完整度归 Production / Facility；通行/占位归 Presence；封锁政策归 Government；控制权归 Territory；合法产权归 Ownership。`damage_state_ref` 指向适用的设施/装备完整度结果，Combat 提供伤害评估而不兼任设施写者。

### 锚点命名

统一使用 ASCII、稳定语义和可查询命名：

```text
S_Entrance_Main
S_Entrance_Service
S_Door_01
S_Interact_Command
S_Interact_Inventory
S_Interact_Production
S_Interact_Medical
S_Interact_Report
S_Load
S_Unload
S_Reserve
S_Output
S_Blocker
S_Escape
S_Ridge
S_Eave
S_Hip
```

锚点不能只存在于蓝图注释；必须作为可导出的结构化数据被 Presence、Inventory、Transport、Production、Government 或 Objective 查询。

### 8.1 整体风格

- 视觉风格：整体视觉风格为写实低魔的汉末战争表现；具体资产层级、灰盒验证方式与量产标准  。
- 色彩与氛围：敌我关系不能只依赖单一颜色；使用队旗、轮廓、形状、图标和状态组合表达归属、任务、士气和目标。
- 视角与镜头：第一人称、第三人称和俯视关注；镜头切换不复制玩家、不暂停或改写世界状态。
- 参考方向：参考历史战争、具身骑战和组织模拟的表达方法；不复制他人 IP、角色、剧情、UI 或美术资产。

### 8.2 美术需求清单
